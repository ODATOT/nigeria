Day 2 Task 03 의사결정 추적

Task 03. 의사결정 추적 (Decision Tracking)

비정형 구두 회의록이나 메신저 대화기록에서 의사결정 사항의 주체, 승인 배경, 미결 사항을 정형 아카이빙으로 추출하는 프로젝트 이력 보존 기술을 학습합니다.

Task 03 의사결정 히스토리 추출 실습 가이드

📥 실습 입력 (Input)

  • • messenger-chat.md (기획-개발 미팅 대화록)

📤 실습 출력 (Output)

  • • 의사결정 로그 (Decision Log) 표
  • • 보류 안건 (Pending Items) 표

🛠️ 실제 따라 하기 실습 가이드

  1. 대화록 생성: 아래 다운로드 버튼을 클릭하여 기획 미팅 대화 원본 파일 messenger-chat.md를 내려받습니다.
  2. 의사결정 추출 의뢰: Codex Client 입력창에 아래 Codex 요청 프롬프트를 전송하여 빌드합니다.
  3. 비즈니스 컨텍스트 확인: 추출된 의사결정 표에서 Apple 로그인 배제 근거(심사 지연 리스크), 카드 결제 단일 적용 사유 등이 정확히 요약 정리되었는지 분석합니다.

실습 자료 다운로드

Codex 요청 프롬프트

Task 03 Prompt프로젝트 폴더 내에 있는 'messenger-chat.md' 대화록을 읽고, 프로젝트 관리 및 추적을 위한 Decision Log와 Pending Items를 작성해줘.

아래 조건에 따라 분석을 수행해줘.
1. 결정 완료된 사안에 대해서는 '의사결정 로그(Decision Log)' 표를 작성해줘. 칼럼은 '결정 항목', '결정 내용', '의사결정 배경/근거', '결정일', '담당자/주체', '상태'를 포함해야 해.
2. 아직 결정되지 않고 후속 검토가 필요하거나 보류된 사안은 '미결 사항 (Pending Items)' 표로 정리해줘. 칼럼은 '미결 항목', '후속 조치 내용', '담당자', '예정 기한'을 포함해줘.
3. 대화록 텍스트에 근거하지 않은 가상의 날짜나 의사결정 주체를 마음대로 작성하지 말아줘.

💡 AI 활용 및 학습 포인트

프로젝트에서는 결정의 결과 정보보다 '배경/이유(Why)'를 정리해 두는 것이 리스크 관리 측면에서 10배 이상 중요합니다. AI를 활용해 메신저/대화 흐름 속 구체적인 정황과 승인 이력을 체계적으로 보존하는 방법을 익힙니다.

Flow 세 가지 Task의 연결 흐름 및 학습 마무리

요구사항 생애주기 관리 (Requirements Lifecycle Management) 시너지

실제 프로젝트 현업에서 기획, 디자인, 개발 산출물의 싱크를 맞추고 의사결정의 히스토리를 통제하기 위해 이 세 가지 Task를 유기적인 시퀀스로 연계 학습합니다.

  1. 1단계. 불일치 검출 (Task 01)

    회의록, 요구사항 정의서, 화면 정의서를 대조하여 문서 상호 간의 모순과 괴리를 조기 발견합니다. (무엇이 달라졌는가?)

  2. 2단계. 의사결정 추적 (Task 03)

    모순이 발생하게 된 회의 대화록과 메신저 기록을 파싱하여, '왜 그런 결정이 났는지'와 보류 안건 이력을 구조화해 쟁점을 해소합니다. (왜 달라졌는가?)

  3. 3단계. 변경사항 관리 (Task 02)

    요구사항 변경(v1.0 ➔ v2.0)에 따라 하위 화면 기획서 및 API 설계서가 영향을 받는 범위를 매핑하고 구체적 조치 이력을 작성합니다. (무엇을 수정해야 하는가?)

🎓 Day 2 실습의 최종 가치

학생들은 오늘 실습을 통해 AI를 단순한 코드 생성 도구로 가동하는 데 그치지 않고, 복잡한 비즈니스 설계 구조를 교정하고 엇갈림을 제어하는 '인공지능 기반 프로젝트 분석가(AI Business Analyst)'로 거듭나는 토대를 닦았습니다.
