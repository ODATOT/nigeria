ChatGPT와 Codex Client의 결정적 차이

일반적인 ChatGPT 웹 대화창과 다중 파일 프로젝트 단위의 Codex Client는 요구사항 설계 시 접근 방식부터 다릅니다.

비교 항목 일반 ChatGPT (웹 브라우저) Codex Client (Workspace 기반)
작업 인지 범위 현재 입력창에 입력한 단발성 텍스트만 인식 프로젝트 폴더(Workspace) 내의 모든 파일 인식
파일 제어 방식 화면에 출력된 결과 코드를 수동 복사·붙여넣기 AI가 지정된 마크다운 파일을 직접 생성 및 부분 수정
다중 파일 추론 이전 파일의 연계 수정을 위해 매번 수동 업로드 필요 하나의 기획 변경 시 연계된 다른 파일 내용 동시 추론

프로젝트 단위 개발 방식

우리는 바탕화면에 지정한 전용 폴더 automation을 AI 작업 영역(Workspace)으로 선포하고 실습합니다. 이렇게 지정된 폴더 구조 아래에서 AI는 0단계 요약 메모부터 5단계 이메일 보고서까지 각 명세 파일의 인풋-아웃풋 체인을 완벽하게 연결해 줍니다.

PBL 미션: 추가 요구사항 변경 대응 및 Gmail 플러그인 전송

PBL 실전 과제

대표의 신규 정책 추가 및 피드백 루프 작동

실제 개발 프로세스 중 대표가 회의록 끝부분에 새로운 요구사항을 덧붙였습니다.
"회원 탈퇴 기능도 추가합시다. 사용자가 회원 탈퇴를 하면 예약된 모든 상담 일정이 자동으로 취소되고 즉각 환불되어야 합니다."

미션 따라 하기 시퀀스

  • 1. 원본 파일 수정: 로컬의 meeting-notes-raw.md 문서 최하단에 대표의 가상 추가 대사(회원 탈퇴 및 자동 예약 취소)를 추가합니다.
  • 2. Codex Client 명세 갱신 지시: AI 프롬프트 창에 "meeting-notes-raw.md의 신규 대화를 반영하여 functional-requirements.md에 회원 탈퇴 기능(FR-005)과 그에 따른 예약 취소 예외 흐름을 업데이트해줘." 라고 지시합니다.
  • 3. 통합서 및 질문지 업데이트: 변경된 요구사항을 린트 검증하고, 연동해둔 **Gmail 플러그인** 발송 기능을 작동시켜 대표에게 회원 탈퇴와 관련된 미결정 사안 승인 메일을 즉시 전송합니다.
