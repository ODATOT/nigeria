1. 스토리 및 실습 배경

사용자가 앱에 접속하여 예약 결제에 골인하는 비율이 비정상적으로 떨어졌습니다. 조사를 해보니 상담을 위해 총 9번의 화면 이동과 클릭 약관 체크를 넘나드는 동안 피로감을 느껴 도중에 이탈한 것입니다.

개발팀은 DB의 Reservations 테이블에 is_approved 컬럼을 급히 추가하고 승인 대기 상태를 넣었으나, 이 중요한 구조 변경이 동의 및 결제서나 기획서에는 공유되지 않고 방치되었습니다. 이로 인해 QA 단계에서 API 파라미터 누락으로 인한 장애가 대량 발생했습니다.

이번 실습에서는 스키마의 수정이 발생했을 때, 이에 연쇄적으로 영향을 받는 API 엔드포인트와 화면 설계 수정 범위를 Codex를 활용해 전수 자동 분석하고 팀원들에게 공유할 리포트를 작성하는 워크플로우를 학습합니다.

2. 학습 목표

  • 데이터 구조의 변경(Schema Change) 사항이 시스템에 미치는 연쇄 여파를 추적할 수 있다.
  • 변경에 의해 즉각 개정이 필요한 동의 및 결제서 및 화면 목록을 식별 매핑할 수 있다.
  • 변경 사항 및 영향 범위를 요약하여 팀원들에게 공지할 공유 리포트를 자율 도출할 수 있다.

🛠️ 실제 따라 하기 실습 가이드

  1. 실습용 파일 생성: 아래 다운로드 버튼을 눌러 day5_signup_flow.md 파일을 automation/ 폴더 내에 저장합니다.
  2. Codex 분석 위임: Codex Client 프롬프트 입력창에 아래 **Codex 요청 프롬프트**를 전송하여 빌드합니다.
  3. 영향 보고서 점검: 생성된 보고서에서 DB 상태 세분화(Wait Approve), API Response 필드 조정, 화면 UI 버튼 및 상태창 조치 요구사항이 제대로 정리되었는지 확인합니다.
