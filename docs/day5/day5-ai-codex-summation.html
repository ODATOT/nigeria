사용성 설계의 한계 장벽

프로젝트 현장에서 기획, 디자인, 개발 간의 이해 오차는 데이터베이스의 누락과 정합성 붕괴로 직결됩니다. 설계 단계에서의 정합성 보장이 왜 중요한지 알아봅니다.

이해 오차

기능 중심 설계의 아집으로 인해, 처음 접속한 초보 사용자가 UI를 이해하지 못해 도중에 앱을 종료하는 이탈 현상이 발생합니다.

어휘 오차

화면마다 버튼 위치, 크기, 라벨(아이디 vs 고객 ID)이 다르게 구성되어 사용자의 학습 피로를 높입니다.

공유 오차

사용자가 목적(상담 예약)을 달성하는 데 지나치게 긴 9단계 화면 전환을 겪게 만들어 최종 결제 전환율을 떨어뜨립니다.

ChatGPT vs Codex Client (Workspace 기반)

단일 대화 컨텍스트에 국한된 ChatGPT와 달리, 폴더 구조 전체와 다중 파일 간 종속 관계를 인지하는 Codex Client의 특성을 비교합니다.

비교 항목 ChatGPT (일반 대화형 AI) Codex Client (Workspace 기반 AI)
컨텍스트 인지 다수의 화면 기획서 파일들과 사용자 유입 뎁스(Depth)의 이동 동선을 종합 비교 분석 로그인, 가입, 마이페이지 등 상호 대치된 UI 버튼 디자인, 크기, 정렬 오차와 상태 메시지 규격을 입체 추적
화면의 일관성 검토하기 텍스트 단일 화면의 편의성 피드백만 전달 프로젝트 표준 용어 사전을 기반으로 일관된 표준 네이밍 및 DB 컬럼명 자율 추천
영향 범위 분석 단편적인 스키마 오류나 가상의 테이블 수정안 제시 수준 스키마의 미세한 변경(예: 컬럼 추가)에 따른 API 규격과 화면 수정 부위 목록 역추론

Task 02. 화면의 일관성 검토하기

Task 03. 사용자 동선 개선하기

예약 승인제(WAIT_APPROVE) 추가에 따른 API 및 화면 수정 리스트 변경 영향도 분석서 (출력: change-impact-report.md)

Mission 01. 설계 기록

Task 01. 사용자 관점에서 화면 검토하기
📥 Input (기획 회의록)
• day5_meeting_notes.md (회의록) - 비정형 줄글 형태의 이용자 흐름 시나리오 및 예약 프로세스 내용
Codex Workspace ➔
💾 Output (ERD 명세)
Mermaid ERD 코드가 포함된 erd-schema.md - User, Expert, Reservation, Payment 엔티티의 Primary Key/Foreign Key 관계 시각화

STEP 1. Task 01 - 사용자 관점에서 화면 검토하기

회의 시나리오 줄글을 입력하여 정밀 정규화 관계(1:N, 1:1)와 Mermaid 코드를 도출합니다.

🔍 Codex 요청 프롬프트 (데이터 구조화)

제공된 예약 신청 상세 폼의 화면 명세를 기반으로, 서비스를 처음 접하는 초보 사용자의 입장에서 정보 구조가 명확한지 검토하고 사용성 저해 요소를 지목하여 개선 제안 보고서(UX Review Report)를 작성해 주세요.
  • User, Expert, Reservation, Payment 4대 엔티티의 PK, FK 설정이 시나리오 논리에 어긋나지 않는지 점검합니다.
  • Mermaid 다이어그램 렌더링(`erDiagram`) 시 카디널리티 표기가 올바른지 확인합니다.

STEP 2. Task 02 - 화면의 일관성 검토하기

Figma 기획서 용어와 DB 개발 명세의 격차를 비교 분석해 도메인 용어 마스터 사전을 빌드합니다.

🔍 Codex 요청 프롬프트 (용어 사전 생성)

제공된 day5_signup_flow.md의 각 화면 설계 내역들을 서로 대조하여, 버튼의 배치 규칙, 사용 용어, 피드백 메시지의 일관성이 결여된 요소를 분석해 화면 비교 보고서를 작성해 주세요.
  • 비즈니스 도메인에 부합하는 영문 표준 네이밍 및 컬럼 타입 정보가 올바르게 제시되었는지 확인합니다.

STEP 3. Task 03 - 사용자 동선 개선하기

예약 절차에 '승인' 단계가 추가되는 릴리즈 계획 변경 시의 API 및 테이블 영향 범위를 파악합니다.

🔍 Codex 요청 프롬프트 (영향 범위 파악)

제공된 day5_signup_flow.md의 예약 상세 시나리오 동선을 분석하여, 사용자가 상담 예약을 완료하기까지의 클릭 단계와 화면 이동을 최소화할 수 있는 사용자 동선 개선 보고서(User Journey Report)를 작성해 주세요.
  • Reservations 테이블의 status 변경 사항과 신규 API 스펙, 기획 화면의 버튼 상태 전이 연쇄 영향이 검출되었는지 확인합니다.

STEP 4. Mission 01 - 처음 사용하는 사용자 되어보기 (Design Decision Log)

정규화 결정, 예약 이력의 물리 분리 결정 등에 관한 기각 사유와 합의를 로그화합니다.

🔍 Codex 요청 프롬프트 (의사결정 기록)

당신은 디지털 스마트폰 앱 사용이 다소 서툰 50대 자영업자입니다. 제공된 day5_signup_flow.md 명세서에 작성된 회원가입 및 첫 화면 UI 명세를 보면서, 당신의 입장에서 가입 시 무엇이 가장 헷갈리고 어려운지 감정적인 반응과 개선 요구사항을 적어주세요.
  • 이력 테이블 분리(DEC-003) 결정 배경과 대안(테이블 단일화 시 성능 저하)이 명확히 로깅되는지 점검합니다.

STEP 5. Mission 02 - AI와 함께 서비스 품질 평가하기 (Edge Case)

참조 무결성 위배(탈퇴) 및 트랜잭션 붕괴를 예방하기 위한 시스템 취약점 오디팅을 진행합니다.

🔍 Codex 요청 프롬프트 (Edge Case 도출)

제공된 day5_signup_flow.md 스펙을 기반으로, 1) 정보 가독성, 2) 조작 접근성, 3) 에러 회복성, 4) 동선 효율성 등의 항목에 대해 각각 5점 만점의 점수를 매기고, 종합 평가 점수와 함께 장점 및 뼈아픈 개선점을 지목하는 서비스 품질 평가서(Usability Evaluation)를 빌드해 주세요.
  • Soft Delete(논리 삭제) 도입을 통한 참조 정합성 유지 방안 및 분산 트랜잭션 롤백 대응을 확인합니다.

작동 원리 및 핵심 메커니즘

스키마 맥락 인지 추론

단순 텍스트 매칭을 넘어 엔티티의 참조 무결성(FK) 관계 및 트랜잭션 수명 주기를 파악하여, 자연어 기획안을 DDL DDL(Data Definition Language) 쿼리 및 상태 기계 규칙으로 자동 역추론해냅니다.

메타 용어 클러스터링

서로 다르게 표기된 용어(고객명 vs Nickname)를 의미론적으로 의미 군집화(Clustering)하여 전사 용어 마스터 사전을 도출하고, 이를 바탕으로 데이터 사전의 정합성을 동기화합니다.

다섯 가지 Task/Mission의 기술설계 시너지

각 단계별로 도출된 데이터와 분석 정보가 기술설계 루프를 돌며 어떻게 품질을 극대화하는지 확인합니다.

💡 교육 설계 스펙

  • 난이도: ★★★★☆ (상급 - 데이터베이스 설계 정규화 및 분산 트랜잭션 개념 포함)
  • 예상 실습 시간: 1시간 30분 ~ 2시간 (종합 설계 실습)
  • 실무 활용도: ★★★★★

학습자 질문/토의 주제

교육 과정 중 토의하거나 면접 질문으로 활용하기 좋은 주제 리스트입니다.

Q1. 회원 탈퇴 전략

"회원가입 오류 시 입력한 데이터 전체가 날아가는 것은 보안을 위한 정보 삭제(Security) 관점과 사용자 경험(UX) 관점에서 어떻게 균형을 잡아야 할까요?"

Q2. 용어 부채 (Terminology Debt)

"화면의 일관성 검토하기 사전을 작성하지 않고 프로젝트를 중반까지 진행했을 때, 개발팀 내부에서 발생하는 '용어 부채' 비용은 실제 일정에 어떤 여파를 주나요?"
