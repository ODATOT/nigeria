Day 3 · 데이터 정규화, ERD & 무결성 관리

비즈니스 언어에서
신뢰받는 데이터
구조로.

오늘 우리는 미팅에서 나온 비즈니스 개념을 엔티티와 관계 모델로 변환하고, 파편화된 용어를 표준화하며, 스키마 변경 파급 효과와 데이터 무결성 예외를 추적했습니다.

3Day 3의 전환점

좋은 데이터 설계는 단순히 표를 그리는 것이 아니라, 현실 세계의 규칙, 용어, 예외를 일관된 구조로 번역하는 것입니다.

오늘 우리는 무엇을 했나요?

우리는 Codex를 데이터 모델러, 용어 관리자, 변경 영향 분석가, 디자인 감사관으로 활용했습니다.

비즈니스 개념 추출 ➔ ERD 구축 ➔ 용어 표준화 ➔ 변경 추적 ➔ 의사결정 기록 ➔ 예외 방어 설계

회의록에서 User, Expert, Reservation, Payment 등 핵심 엔티티와 PK, FK, 카디널리티를 도출했습니다. 프로젝트 내 혼용되던 용어를 표준 용어 사전으로 통일하고, 승인 대기 결제 정책 변경이 DB, API, 화면에 미치는 영향을 역추적했습니다. 마지막으로 정규화 선택 배경과 대안을 기록하고, 동시성 오류 및 참조 무결성 붕괴 시나리오를 발굴했습니다.

6가지 핵심 개념

수업 목표와 Codex 실습을 통해 직접 다룬 데이터 설계 핵심 개념입니다.

Entity & Attribute (엔티티 & 속성)

관리 대상 비즈니스 객체를 엔티티로, 그 세부 특성을 속성으로 정의합니다.

PK & FK (주키 & 외래키)

PK는 고유 행을 식별하며, FK는 테이블 간의 관계와 참조 무결성을 형성합니다.

Cardinality (관계 수량성)

1:1, 1:N, N:M 관계를 통해 실제 비즈니스 규칙을 데이터 모델에 연결합니다.

Normalization (정규화)

데이터 중복과 이상 현상을 방지하도록 데이터를 논리적으로 분리하고 정렬합니다.

Standard Glossary (표준 용어 사전)

기획 용어, API 필드명, DB 컬럼명을 하나의 표준 단어로 매핑합니다.

Data Integrity (데이터 무결성)

중복 결제, 탈퇴 사용자 참조, 동시성 오류 등의 시스템 장애를 견뎌내는 데이터 가드입니다.

변경은 얼마나 멀리 파급되는가?

예약 승인 프로세스 하나를 변경하는 것은 컬럼 하나 수정으로 끝나지 않습니다.

① 비즈니스 규칙

제공된 회의록을 데이터 구조 관점에서 분석하여 핵심 엔티티와 관계를 도출하고, 데이터 구조 정의서 및 Mermaid ERD 코드를 작성해 줘.
