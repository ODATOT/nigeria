Superpowers —
초보자를 위한 입문 가이드

AI에게 체계적인 소프트웨어 개발 방식을 가르쳐주는 14가지 스킬 패키지 오픈소스입니다: 선 설계, 계획 수립, 단계별 구축, 근본 원인 디버깅, 객관적 검증 후 완료. Codex 앱에서 클릭 한 번으로 설치할 수 있으며, 데모데이 이후 나만의 프로젝트에 활용해보세요.

0Superpowers란 무엇인가

독립된 앱이나 플러그인이 아닙니다. AI의 일하는 방식을 체계적으로 변화시키는 마크다운 프롬프트 지침서입니다.

각 "스킬"은 브레인스토밍, 계획 수립, 디버깅 등 특정 작업 시 AI가 따라야 할 역할을 정의한 마크다운 문서입니다. 스킬을 호출하면 AI는 임의로 코드를 작성하는 대신 엄격한 방법론을 따릅니다. 이 스킬 팩 전체는 하나의 단단한 철학을 담고 있습니다:

시작할 때 속도를 줄이세요. 코드 전에 설계를, 개발 전에 계획을, 수정 전에 근본 원인을 파악하고 — 객관적 검증 없이 절대 "완료"라 말하지 마세요.

이는 대부분의 사람들이 AI를 사용하는 방식(바라는 바를 입력하고 나오는 결과를 그대로 받기)과 반대되는 접근이며, 바로 이 때문에 강력하게 동작합니다.

⌁ github.com/obra/superpowers공식 리포지토리 — 모든 스킬이 마크다운 파일로 공개되어 있습니다. MIT 라이선스.
설치 시기 안내

데모데이가 끝난 후 설치하는 것을 권장합니다. 스프린트 기간 동안은 gstack을 단일 스킬 팩으로 유지하여 $ 명령어 목록이 혼동되는 것을 방지합니다. Superpowers는 본 과정 마친 후 개인 프로젝트 개발 시 활용하세요.

1설치 방법 — 터미널 없이 3번의 클릭

gstack과 달리, Superpowers는 Codex 앱의 공식 플러그인 디렉토리에 등록되어 있어 명령어가 필요 없습니다.

  1. Codex 데스크톱 앱 실행 → 사이드바 Plugins 메뉴 선택
  2. 검색창에 “superpowers” 입력 → Public 탭에서 Superpowers — “A dev methodology for agents” 찾기 → Install 클릭
  3. Codex 앱을 완전 종료 후 재시작
# 설치 확인 — 채팅창에 아래 명령어를 입력해보세요: $brain Brainstorming 구현 전에 의도, 요구사항 및 설계를 구체화합니다 ← 성공 표시
단일 복사본 유지

Public 탭에서 1회만 설치하세요. 명령어 목록에 동일한 스킬이 중복 표시되면 두 곳에서 설치된 것이므로 Plugins 메뉴에서 하나를 제거하세요.

2스킬 호출 방법

gstack과 동일한 방식: $ 기호를 입력하고 목록에서 선택합니다.

  • 채팅창에 $ 입력 → 스킬 목록이 나타납니다. 몇 글자($brain, $debug, $test)를 입력하여 검색 후 선택하세요. 이름을 외울 필요가 없습니다.
  • 선택 후 동일한 메시지에 요청할 작업을 자연어로 작성하세요.
  • 스킬은 자동 감지(Implicit)로도 작동합니다 — 버그 상황을 설명하면 AI가 스스로 Systematic Debugging 스킬을 불러옵니다. Explicit 호출은 확실성을 높여줍니다.
사용자 ▸ $brainstorming 기숙사 학생들을 위한 룸메이트 매칭 사이트를 만들고 싶어. AI ▸ 본격적으로 개발하기 전에 — 이번 프로젝트의 주요 목표가 무엇인가요? 스타트업 창업, 수업 과제, 해커톤 시연, 또는 웹 개발 학습인가요? ← 사용자에게 질문부터 던집니다

3개발 루프 — 14개 스킬의 유기적 연결

6단계 프로세스입니다. 개발 중 이전 단계로 되돌아가는 것은 정상적인 과정입니다.

4실제로 가장 많이 쓰이는 핵심 6가지 스킬

총 14개 스킬 중 아래 6가지 핵심 스킬부터 시작하세요.

① Brainstorming

언제 쓰나요: 새로운 기능, 앱, 행동 변경 등 새로운 것을 만들기 전에 사용합니다.

역할: 즉시 코드를 쓰지 않고 거부합니다. 한 번에 하나씩 질문을 던지며 사용자가 승인할 때까지 설계 문서(Design Document)를 작성합니다.

사용자 ▸ $brainstorming 스터디 그룹원들에게 마감일을 알림으로 전송하는 툴을 만들고 싶어.
② Writing Plans

언제 쓰나요: 승인된 설계서가 있고 작업 단계가 여러 개인 경우 사용합니다.

역할: 설계를 검증 가능한 번호 순서의 구현 계획으로 변환하여, 장시간 개발 시 방향을 잃지 않도록 돕습니다.

사용자 ▸ $writing-plans 방금 합의한 설계를 바탕으로 구현 계획을 작성해줘.
③ Executing Plans

언제 쓰나요: 계획서 작성이 완료되어 본격적으로 개발을 시작할 때 사용합니다.

역할: 체크포인트 승인 단계를 거치며 계획을 단계별로 진행합니다. 무작정 끝까지 달리지 않고 각 단계마다 사용자 확인을 받습니다.

사용자 ▸ $executing-plans 계획을 실행해줘. 각 단계가 끝날 때마다 멈추고 확인을 받아줘.
④ Systematic Debugging

언제 쓰나요: 에러 발생, 테스트 실패, 예상과 다른 동작 등 문제가 생겼을 때 사용합니다.

역할: 임의의 짐작으로 코드 수정을 금지합니다. 버그 재현 ➔ 원인 격리 ➔ 근본 원인(Root Cause) 명시 후 해결책을 제안합니다.

사용자 ▸ $systematic-debugging 로그인 페이지에서 제출 버튼 클릭 시 오류가 발생해. 에러 로그: …
⑤ Test-Driven Development

언제 쓰나요: 나중에 코드 수정을 거쳤을 때 깨지기 쉬운 핵심 기능을 개발할 때 사용합니다.

역할: 테스트 코드를 먼저 작성하고, 실패를 확인한 후, 이를 통과시키는 기능 코드를 작성합니다.

사용자 ▸ $test-driven-development 더치페이 계산 기능을 추가해줘. 테스트 코드부터 먼저 만들어줘.
⑥ Verification Before Completion

언제 쓰나요: AI나 사용자가 "완료되었다", "수정되었다"라고 말하려 할 때 사용합니다.

역할: 완료를 선언하기 전에 실제 명령어 실행 및 출력 결과 등 객관적 증거를 요구합니다.

사용자 ▸ $verification-before-completion 완료 처리하기 전에 실제로 잘 동작하는지 증명해줘.

6첫 20분 실습 가이드

간단하지만 실제로 구현하고 싶은 소형 아이디어로 시작하세요.

  1. 0~8분 · 브레인스토밍. $brainstorming + 아이디어 한 문장 전달. 질문에 솔직히 답변하세요. 설계안을 제시하고 승인을 요청할 때 멈춥니다. 승인 전 설계안을 꼼꼼히 읽으세요.
  2. 8~12분 · 계획 작성. $writing-plans. 단계를 읽어보세요. 이해되지 않는 큰 단계는 더 작게 쪼갭니다.
  3. 12~18분 · 구현. $executing-plans. 각 체크포인트에서 승인 또는 피드백을 전달합니다. 문제 발생 시 $systematic-debugging 활용.
  4. 18~20분 · 검증. $verification-before-completion. 객관적 작동 증명이 없으면 완료가 아닙니다.
관전 포인트

AI가 여러분에게 더 많은 질문을 던지고, 코드 작성을 평소보다 늦게 시작한다는 점을 느낄 수 있습니다. 이 지연시간이 바로 방법론의 핵심입니다. 시작 10분의 질문 과정이 나중에 발생할 2시간의 재작업을 방지해줍니다.

7Superpowers vs gstack — 라이벌이 아닌 보완 관계

두 스킬 팩은 서로 다른 목적을 가지고 있습니다.

구분gstack (수업에서 활용)Superpowers (본 가이드)
핵심 질문“이 아이디어가 실제로 존재할 가치가 있는가?”“어떻게 하면 완성도 높게 잘 만들 것인가?”
역할 톤앤매너냉철한 투자 분석가 / CEO체크리스트를 준수하는 수석 엔지니어
유용한 시기아이디어만 있고 시장 증거가 없을 때검증된 아이디어를 코드로 구현할 때
대표 스킬office-hours, plan-ceo-reviewbrainstorming, systematic-debugging, TDD
설치 방식프롬프트 복사 또는 스크립트 설치Plugins 메뉴에서 1-클릭 설치

실제 프로젝트 추천 워크플로우: gstack을 먼저 사용하여 아이디어가 주말을 투자할 가치가 있는지 판단 ➔ 이후 Superpowers를 사용하여 코드 구조를 깔끔하게 구축하세요.

8트러블슈팅 및 자주 묻는 질문

증상원인해결 방법
$brain 입력 시 아무것도 안 뜸설치 후 앱 재시작 안 함Codex 앱 완전 종료 후 다시 실행
모든 스킬이 2개씩 중복 노출됨두 곳에서 중복 설치됨Plugins 메뉴에서 하나 삭제 (Public 버전 유지)
$ 목록이 너무 길어짐gstack과 Superpowers 동시 활성화Plugins에서 사용하지 않는 팩 일시 비활성화
코드는 안 짜고 계속 질문만 함Brainstorming 스킬의 정상 동작임답변을 진행하거나, 간단한 작업 시 스킬 제외
삭제하고 싶을 때—Plugins → Superpowers → Uninstall 클릭
