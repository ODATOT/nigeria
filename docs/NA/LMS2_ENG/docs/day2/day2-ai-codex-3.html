Codex request prompt

Task 03 PromptRead the 'messenger-chat.md' transcript in the project folder and write a Decision Log and Pending Items for project management and tracking.

Analyze it under these conditions.
1. For settled matters, write a 'Decision Log' table. Columns must include 'Decision item', 'Decision', 'Reason/background', 'Decision date', 'Owner' and 'Status'.
2. Put matters not yet decided, needing follow-up or on hold into a 'Pending Items' table. Columns: 'Pending item', 'Follow-up action', 'Owner' and 'Due date'.
3. Don't make up dates or decision owners not based on the transcript text.

💡 AI use and learning points

In projects, recording the 'background/reason (Why)' of a decision is over 10 times more important for risk management than the result itself. Learn to use AI to systematically keep the specific context and approval history inside messenger/chat flows.

Flow How the three Tasks connect, and wrap-up

Synergy in Requirements Lifecycle Management

In real projects, we learn these three Tasks as a linked sequence to keep planning, design and dev outputs in sync and control decision history.

  1. Step 1. Find mismatches (Task 01)

    Compare meeting notes, requirements doc and screen spec to find contradictions and gaps between docs early. (What is different?)

  2. Step 2. Track decisions (Task 03)

    Parse the meeting transcripts and messenger records behind the contradictions, structure 'why that decision was made' and pending item history, and resolve the issues. (Why is it different?)

  3. Step 3. Manage changes (Task 02)

    Map how requirement changes (v1.0 ➔ v2.0) affect downstream screen plans and API designs, and write specific action history. (What must we fix?)
