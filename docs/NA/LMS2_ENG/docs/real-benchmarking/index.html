MISSION 01 · DISCOVER

Observe a Real Service's Growth Structure

Find the features on public screens that drive users' next action, and explain the growth loop with observable evidence.

25POINTS
Input public screens·official sourcesOutput OBS 10+ · EXP 5+Done signal evidence linked to every claim
01

Fix what you'll observe

Pick only one service, one main user and one main task. Internal algorithms or revenue are hypotheses, not facts, unless there's an official source.

JumiaDiscover products → browse details → check trust → purchase intentYouTubeDiscover content → watch → next video → returnJijiChoose area → find listings → check trust → intent to contact seller
02

Do 3 observation sessions

  1. First visit · 30 minWhile logged out, record the value, choices, CTAs and your 5-second impression.
  2. Main task · 45 minRecord clicks, scrolls and inputs, expected vs actual results, and trust/drop-off factors.
  3. Return features · 30 minFind where saving, subscribing, notifications, reviews and sharing lead to the next visit or value for others.
03

Link evidence with IDs

OBSERVATION TEMPLATE
## OBS-001 — [observation title]\n- Date / URL / environment:\n- User goal:\n- Fact observed:\n- My interpretation:\n- Effect on the next action:\n- AARRR stage:\n- Evidence file:\n- Uncertainty:

Observation: "Product cards show ratings and review counts." / Interpretation: "This seems to reduce uncertainty before opening details." Don't mix the two.

04

Turn AARRR into a repeating growth loop

User action→Service value grows→Other users respond→Acquisition·return

Write the 3 strongest OBS, the hidden links, the conditions where the loop stops, the principles to borrow and the things you must not copy.

MISSION 02 · DEFINE

Reverse-Engineer Your Observations into 3 Docs

Turn Mission 1's evidence into actionable contracts: a product opportunity, a business model and a base engineering design.

25POINTS
Input OBS · GROWTH LOOPOutput 3 core MDsDone signal OBS→PRD→BM→ADR
01

Start with an evidence trace table

Trace in one line where each decision started. This is the central tool that stops the docs from describing different products.

OBS-001→PRD-001→BM-001→ADR-001
02

Write the 3 docs in order

PRODUCTOPPORTUNITY.mdProblem·journey·PRD·MVP scope·success metricsDownload example →BUSINESSBUSINESS_MODEL.mdValue exchange·AARRR·Canvas·BM hypotheses·risksDownload example →ENGINEERINGBASE_ARCHITECTURE.mdFlow·data·events·quality·tests·ADRDownload example →
03

Cut the MVP to 1 flow and 1–3 screens

  • Can a user experience it in one visit?
  • Does it show the top growth hypothesis?
  • Can it be built and tested in 6–10 hours?
  • Can it be demoed without real personal data, payments or outside services?

Login, payment, live chat and recommendation algorithms can be replaced with mock data.

04

Give AI contradiction checks, not generation

CROSS-DOC REVIEW PROMPT
The three docs below define the product, business and tech of the same service.\nDon't create new features or facts; find only these:\n1. PRD/BM/ADR items with no OBS evidence\n2. Places using the same term differently\n3. Conflicts between product scope and dev scope\n4. Success criteria that can't be measured\n5. Personal data, copyright and security risks

MISSION 03 · BUILD

Build the Site with AI Based on Your Docs

Use the 3 docs as a build contract to make a main user flow with start, key action, done and failure states.

30POINTS
Input PRD · BM · ADROutput WEB · TEST · AI LOGDone signal LINT·BUILD pass
01

Check the environment and build baseline first

node --version
npm --version
git --version

npx create-next-app@latest development/apps/web

After installing, record the build target, linked IDs, how to confirm done and out-of-scope items in `development/README.md`. If the official Next.js requirements differ from this guide, follow the official docs and note why in an ADR.

02

Finish in 3 vertical cycles

  1. Understanding the valueMake it possible to understand the audience and value and find the CTA within 5 seconds.
  2. Key actionState changes through browsing or input, handling loading, empty results and wrong input.
  3. Done and next actionLink done feedback to the growth hypothesis's next action, like saving, sharing or browsing more.
03

Lock the scope and done criteria for every AI request

AI BUILD PROMPT
Role: Next.js development partner\nGoal: [user result for this cycle]\nDocs you must follow: PRD-___ / BM-___ / ADR-___\nPaths you may change: [files or folders]\nDone criteria: screen conditions / failure states / mobile·accessibility / tests\nDon'ts: new features, copying original assets, secrets, unverified packages\nFirst suggest a work plan and the files to change.

After each task, record the request, changed files, checks, AI errors and human change/reject decisions in `AI-###`.

MISSION 04 · LEARN

Prove the Differences Between the Original and Your Build

Use the same task and conditions on both sites to prove where growth principles were kept, improved, lost or changed.

20POINTS
Input original·build·TESTOutput CMP 10+ · EXP 3Done signal evidence for every conclusion
01

Fix the same comparison baseline

First record the original and build versions, measurement time, device, browser, screen size, login state and the shared task. Compare "how each reaches the same goal," not "are they similar."

Same start→Same task→Same end→Same conditions
02

Repeat 3 times, switching the order

Alternate between the original and your build, recording completion, time, clicks and inputs, blockers and errors. Also write the limit that testing alone doesn't represent all users.

Understanding the value5-second record
Task efficiencyTime·steps·errors
Growth structureNext action·return
TrustEvidence of less worry
BM linkValue exchange
Tech qualityAccessibility·performance
OriginalityAdapting the principle
03

Make CMP records your basis for judgment

COMPARISON TEMPLATE
## CMP-001 — [comparison title]\n- Area / linked evidence:\n- What you saw in the original:\n- What you saw in your build:\n- Category: kept/improved/lost/intentional change\n- Evidence file or measurement:\n- Why the difference happened:\n- Effect on users:
04

Close the project with 3 next experiments

Each `EXP-NEXT-###` must have the CMP that revealed it, the one thing to change, primary and side-effect metrics, success/failure criteria, the smallest build scope and why it's prioritized.

"Improve the design" isn't an experiment. Make one change and one main metric at a time.

Safety and ethics rules you must follow
  • Use only public screens and official public material; no bypassing auth, private APIs or mass scraping.
  • Don't copy original logos, images, videos, text or source code; use a new name and legal assets.
  • Don't store or submit real personal data, locations, payment info or secrets.
  • People check AI-made claims and code, and keep usage records including rejected suggestions.
