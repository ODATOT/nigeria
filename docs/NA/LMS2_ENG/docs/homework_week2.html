HW-D08-02. Preventing OAuth2 Token Theft and a Session Security Audit

🚨 Real business situation (Production Context)

After VidAce introduced Google and Facebook social login, an outside security audit reported these critical session weaknesses:

[CRITICAL 1] JWT Refresh Token stored in LocalStorage: one line of XSS attack script can leak a user's long-lived token to a hacker's C2 server.
[CRITICAL 2] No Refresh Token reuse detection: even if a hacker uses a leaked token to get a new Access Token, the real user never learns the session was hijacked.
[HIGH 3] Weak OAuth2 CSRF defense: missing state parameter checks when exchanging the Auth Code allow account linking to be hijacked.

Fix required: use HttpOnly, Secure, SameSite=Strict cookies, discard the old token each time a Refresh Token is renewed, and if an already-used token is submitted again, treat it as a breach and force-expire all sessions for that account (Family Invalidation) — an RTR (Refresh Token Rotation) architecture.

💡 Self-Reflection Questions
  • When the SPA and back-end API server are on different domains (api.vidace.com vs www.vidace.com), how must SameSite cookies and CORS be set so cookies aren't lost?
  • How do you handle a grace period (10 seconds) so a normal client that accidentally sends the previous token twice due to mobile network delay during rotation doesn't get its session cut by a false positive?
  • When storing a session revocation list in Redis, what technique matches the token's remaining expiry (TTL) to reduce wasted memory?
🤖 Example AI question (reference prompt)
⚠️ This is a reference example: don't copy and submit the prompt below. Build your own prompt that covers token family management and anomaly detection in detail. 
Build security-hardened JWT Refresh Token Rotation (RTR) service code.
1) Issue tokens with HttpOnly/Secure cookies
2) On renewal, invalidate the old Refresh Token and issue a new token family (Family ID)
3) Include logic that detects a breach when an already-used, discarded token is resent, and immediately invalidates all of that user's active sessions.
