Barriers in usability design

In real projects, misunderstandings between planning, design and development lead directly to missing database items and broken consistency. Let's see why guaranteeing consistency at the design stage matters.

Understanding gap

Stubborn feature-centered design means first-time beginners don't understand the UI and quit the app midway.

Vocabulary gap

Button positions, sizes and labels (Username vs Customer ID) differ on each screen, making users tired of relearning.

Sharing gap

Users go through an overly long 9-step screen journey to reach their goal (booking a session), lowering final payment conversion.

STEP 1. Task 01 - Review screens from the user's view

Enter the meeting scenario prose and derive precise normalized relationships (1:N, 1:1) and Mermaid code.

🔍 Codex request prompt (data structuring)

Based on the screen spec of the provided booking request form, review whether the information structure is clear from the view of a beginner who's new to the service, point out what hurts usability, and write an improvement report (UX Review Report).
  • Check that the PK and FK settings for the 4 entities User, Expert, Reservation and Payment don't conflict with the scenario logic.
  • Check that cardinality notation is correct when the Mermaid diagram (`erDiagram`) renders.

STEP 2. Task 02 - Screen consistency review

Compare the gap between Figma plan terms and DB dev specs and build a domain term master dictionary.

🔍 Codex request prompt (term dictionary)

Compare the screen designs in the provided day5_signup_flow.md with each other, analyze elements that lack consistency in button placement rules, terms used and feedback messages, and write a screen comparison report.
  • Check that standard English names and column types that fit the business domain are given correctly.

STEP 3. Task 03 - User journey improvement

Find the API and table impact when the release plan changes to add an 'approval' step to booking.

🔍 Codex request prompt (find impact)

Analyze the detailed booking scenario path in the provided day5_signup_flow.md and write a User Journey Report that minimizes the click steps and screen changes a user needs to complete a session booking.
  • Check that it detected the chain impact of the Reservations table status change, new API specs and button state transitions on the planned screens.

STEP 4. Mission 01 - Be a first-time user

Log the rejection reasons and agreements for normalization decisions, splitting booking history physically, and so on.

🔍 Codex request prompt (decision record)

You are a self-employed person in your 50s who is a bit clumsy with smartphone apps. Looking at the sign-up and first screen UI spec in the provided day5_signup_flow.md, write from your own point of view what is most confusing and hard when signing up, with your emotional reactions and requests for improvement.
  • Check that the reason for splitting the history table (DEC-003) and the alternative (slower performance with one table) are clearly logged.

STEP 5. Mission 02 - Evaluate service quality with AI

Audit system weak points to prevent referential integrity violations (account deletion) and broken transactions.

🔍 Codex request prompt (derive Edge Cases)

Based on the provided day5_signup_flow.md spec, score each of 1) information readability, 2) control accessibility, 3) error recovery and 4) flow efficiency out of 5, and build a service quality evaluation (Usability Evaluation) with an overall score, strengths and painful areas to improve.
  • Check the plan to keep referential consistency with Soft Delete (logical delete) and the response to distributed transaction rollback.

How It Works & Key Mechanisms

Schema-aware reasoning

Going beyond simple text matching, it understands entity referential integrity (FK) and transaction lifecycles, and works backward from a natural-language plan to DDL (Data Definition Language) queries and state machine rules automatically.

Meta term clustering

It groups differently written terms (customer name vs Nickname) by meaning (Clustering) to produce a company-wide term master dictionary, and syncs the data dictionary's consistency based on it.
