The key difference between ChatGPT and Codex Client

A regular ChatGPT web chat and the project-based, multi-file Codex Client take different approaches to designing requirements.

Compared Regular ChatGPT (web browser) Codex Client (Workspace-based)
What it sees Only the one-off text typed in the input box Every file in the project folder (Workspace)
How files are handled Copy and paste result code from the screen by hand AI creates and partly edits the chosen markdown files directly
Multi-file reasoning You must upload earlier files by hand every time to update linked content When one plan changes, it reasons about linked files at the same time

Project-based development

PBL Mission: Handle a New Requirement and Send with the Gmail Plugin

PBL real-world task

The CEO adds a new policy and the feedback loop kicks in

During development, the CEO added a new requirement at the end of the meeting notes.
"Let's add account deletion too. When a user deletes their account, all booked counseling sessions must be cancelled automatically and refunded right away."

Mission steps

  • 1. Edit the source file: add the CEO's made-up extra lines (account deletion and automatic booking cancellation) to the bottom of your local meeting-notes-raw.md.
  • 2. Tell Codex Client to update the spec: in the AI prompt box, type "Using the new conversation in meeting-notes-raw.md, update functional-requirements.md with the account deletion feature (FR-005) and the booking cancellation exception flow that follows."
  • 3. Update the combined doc and questions: lint-check the changed requirements, then use the connected **Gmail plugin** to send the CEO an approval email about open issues related to account deletion right away.
