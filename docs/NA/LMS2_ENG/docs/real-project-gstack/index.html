SLIDE 02 01 / ORIENTATION
02 / 16

Today you'll learn a way of working more than commands.

If you just tell AI "build it," you pile up code that looks right but isn't verified. gstack controls the project with 3 principles.

01

Don't build right away

Before writing code, check the user's problem and project scope first, and bring hidden assumptions to the surface before building.

Key question: "Whose pain, and what pain, are we solving?"
02

Split roles

Don't mix product (CEO), design (Design), tech (ENG), code review (Review) and quality checks (QA) at once; run each as a separate skill.

Code changes are strictly forbidden in the planning stage.
03

Verify results

AI output isn't an answer key. A person checks it directly with the real files, git status, git diff and browser run results.

A pass without evidence (files·reproduction steps) doesn't count.

Windows native track ① for first-time installers

Windows learners first follow PATH A (Windows native), installing right from PowerShell without another OS.

Terminal

A window where you give the computer commands as text.

PowerShell

The terminal built into Windows.

Commands

Copy, paste and press Enter.

WSL

Optional Ubuntu Linux feature inside Windows.

Step 1~3. Install PowerShell · Git · Node.js · Bun

Windows key → run PowerShell, then run the commands below in order.

winget install --id Git.Git -e winget install OpenJS.NodeJS.LTS
powershell -c "irm bun.sh/install.ps1|iex"
After installing, close and reopen PowerShell and check that bun --version shows a number.

Step 4~6. Install Codex · Claude Code and check versions

powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex" winget install Anthropic.ClaudeCode
git --version node --version bun --version codex --version claude --version
If each line shows a version number, your basic tools are ready.

SLIDE 07 METHOD B · PROMPT-DRIVEN SETUP
07 / 16

Instead of typing commands, ask Codex to install it

After installing and logging in to Codex CLI, install safely in 2 steps: Prompt 1 environment check (read-only) → Prompt 2 install (approval-based).

PROMPT 01 · Read-only check

Step 1: check the environment only, don't install

I'm getting ready to install gstack. First check the current operating system and shell, and check the Git, Bun and Codex versions and whether gstack is already installed. Don't install anything or change files yet; just show me the facts you found, what's missing, the install path to use and the plan of commands to run.
First check the OS, missing tools and install path plan with your own eyes.
PROMPT 02 · Install with approvals

Step 2: run a safe, conditional install

Based on the check you just did, install gstack for the Codex host. Conditions: 1. Use only the official repository https://github.com/garrytan/gstack. 2. On Windows native, use $HOME\gstack and setup.ps1; on macOS·Linux·WSL, use ~/gstack and ./setup. 3. If a gstack folder already exists, don't overwrite or delete it; stop and tell me. 4. Don't run destructive commands. 5. If you need network access or to write to the home folder, ask for approval first. 6. After installing, run the --host codex registration and the --status check. 7. At the end, summarize the commands you ran, the install path and the status result.
PROMPT 03 · First run in a new session

Step 3: check skill recognition & first analysis

First check whether you can use the gstack-office-hours skill. If you can, read this project and summarize: 1. Target users 2. The problem users face 3. The smallest core feature 4. Unverified assumptions Don't change any files yet.
Approval window check: ① Is it git clone/setup? ② Is it garrytan/gstack? ③ Is it my home folder? ④ No delete commands?
