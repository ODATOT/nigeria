Go through the steps below one by one from the top. Don't type text like PS C:\Users\... before a command; type only what's inside the gray command box.

PATH A Windows native install - default beginner track

  1. Open PowerShell

    Press the Windows key, search for PowerShell and run it. If you see PS C:\Users\username> in the window, you're good.

  2. Install Git and Node.js

    Paste the commands below one line at a time and press Enter.

    winget install --id Git.Git -e winget install OpenJS.NodeJS.LTS

    Expected result · After the install-complete message, close and reopen PowerShell.

  3. Install Bun

    powershell -c "irm bun.sh/install.ps1|iex"

    Open a new PowerShell and type bun --version; if a number appears, it worked.

  4. Install and log in to Codex

    powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"
    codex --version codex

    On first run, follow the on-screen steps to log in with one of the offered options, like a ChatGPT account.

  5. Install and log in to Claude Code

    winget install Anthropic.ClaudeCode
    claude --version claude doctor claude

    You need an account that can use Claude Code. If you only use one tool, you can skip this step.

  6. Check all install results at once

    git --version node --version npm --version bun --version codex --version claude --version

    If each line shows a version number, go to the next step.

  7. Download gstack

    git clone --single-branch --depth 1 https://github.com/garrytan/gstack.git "$HOME\gstack" cd "$HOME\gstack"

  8. Register gstack in Codex·Claude Code

    .\setup.ps1 --host codex .\setup.ps1 --host claude .\setup.ps1 --status

    If you only use one tool, run only that host's command. If codex or claude appears in the status table, it worked.

  9. Open PowerShell in the ZIP lab folder

    Right-click the ZIP and choose Extract All. Open the extracted project folder, type powershell in File Explorer's address bar and press Enter.

    git init git add . git commit -m "Lab start state" git status

  10. Start the first lab

    # If you chose Codex codex # If you chose Claude Code claude

    Always check git status and git diff before and after AI work.

PATH B WSL2 Ubuntu install - optional track

What is WSL?

WSL stands for Windows Subsystem for Linux. It lets you run an Ubuntu terminal and Linux dev tools inside Windows. It isn't required to use gstack.

  1. Install WSL from an admin PowerShell

    wsl --install

    When the install finishes, restart your computer.

  2. First Ubuntu run

    Run Ubuntu from the Start menu and create a Linux username and password. It's normal that no characters show while you type the password.

  3. Install required tools in Ubuntu

    sudo apt update sudo apt install -y git curl unzip curl -fsSL https://bun.com/install | bash source ~/.bashrc

  4. Install Codex and Claude Code inside Ubuntu

    curl -fsSL https://chatgpt.com/codex/install.sh | sh curl -fsSL https://claude.ai/install.sh | bash

  5. Install gstack inside Ubuntu too

    git clone --single-branch --depth 1 https://github.com/garrytan/gstack.git ~/gstack cd ~/gstack ./setup --host codex ./setup --host claude ./setup --status
Don't mix environments

If you install only Codex on Windows and gstack in WSL, they use different home folders. Install everything on Windows or everything in WSL2 Ubuntu.

Check these first when stuck

Command not found

Close PowerShell completely, open a new one and try again.

setup.ps1 is blocked

Run it like powershell -ExecutionPolicy Bypass -File .\setup.ps1 --host codex.

Git commit name error

Set git config user.name "student" and a local email.

gstack skills don't show up

Quit Codex·Claude, open a new session and check .\setup.ps1 --status.

Bun isn't recognized

Open a new PowerShell and check bun --version again.

Windows security blocks it

Don't turn off security settings; tell the instructor and switch to the WSL2 track.

METHOD B · PROMPT-DRIVEN SETUP

Instead of typing commands yourself,
ask Codex to install it

Codex can check your current environment and suggest·run the needed commands. If it needs to write files or access the network, it asks you for permission based on the approval policy.

What you need first

Codex can't install itself. Finish installing and logging in to Codex CLI with the official install command above before starting this.

  1. Start Codex in your lab folder

    Open a terminal in an empty folder or the extracted lab folder and run Codex.

    # Windows PowerShell mkdir "$HOME\gstack-class" -ErrorAction SilentlyContinue cd "$HOME\gstack-class" codex # macOS · Linux · WSL mkdir -p ~/gstack-class cd ~/gstack-class codex

  2. Prompt 1 — check the environment only, don't install

    First, read-only, check the OS, shell, required tools and any existing install.

    PROMPT 01Environment check
    I'm getting ready to install gstack.
First check the current operating system and shell,
and check the Git, Bun and Codex versions and whether gstack is already installed.

Don't install anything or change files yet;
just show me the facts you found, what's missing, the install path to use
and the plan of commands to run.

  3. Check the results

    Check that the OS and install path Codex shows match your real environment. Don't put passwords, API keys or auth codes in prompts.

    CODEX · Sample check result

    Environment Windows 11 / PowerShell 7

    Found Git 2.x, Bun 1.x, Codex CLI logged in

    Missing gstack not installed

    Plan Clone the official repository to C:\Users\student\gstack, then register the Codex host and check status

  4. Prompt 2 — run the install while approving

    If the check looks right, send the next prompt. When a network access or home folder write approval appears, read the command and path before allowing it.

    PROMPT 02Install gstack
    Based on the check you just did, install gstack for the Codex host.

Conditions:
1. Use only the official repository https://github.com/garrytan/gstack.
2. On Windows native, use $HOME\gstack and setup.ps1;
   on macOS·Linux·WSL, use ~/gstack and ./setup.
3. If a gstack folder already exists, don't overwrite or delete it; stop and tell me.
4. Don't run destructive commands.
5. If you need network access or to write to the home folder, ask for approval first.
6. After installing, run the --host codex registration and the --status check.
7. At the end, summarize the commands you ran, the install path and the status result.

  5. What to check in the approval window

    CommandIs it git clone or setup?SourceIs it the official garrytan/gstack address?PathIs it the gstack folder in my home?ScopeNo deletes or forced resets?

    If you see a command you don't know, don't approve it; ask "Explain what this command changes."

  6. Check the install result

    CODEX · Sample done result

    Install path C:\Users\student\gstack

    Registered host codex

    Status installed / skills linked

    Next step Quit Codex and run a gstack skill in a new session

    # After leaving Codex, in a new terminal cd "$HOME\gstack-class" codex

  7. First gstack prompt

    PROMPT 03Check install and first run
    First check whether you can use the gstack-office-hours skill.
If you can, read this project and summarize:

1. Target users
2. The problem users face
3. The smallest core feature
4. Unverified assumptions

Don't change any files yet.

    Expected result · office-hours questions start, or users·problem·assumptions are summarized. If it says it can't find the skill, fully quit Codex and run it again in a new session.

Why split it into two prompts?

Separating the environment check from the actual install lets you catch wrong OS commands, overwriting existing folders and unexpected install paths before they run.

05Review·debug

REVIEW & DEBUG

Find change risks and fix causes, not symptoms

review finds bugs·gaps·structural risks in the diff, and investigate narrows down causes in the order reproduce → evidence → hypothesis → fix. When you only want a report, say "Don't fix anything."

Review
Use the gstack-review skill to review the current diff.
Report only severity, file evidence and how to reproduce; don't fix anything.

Claude: /review
Root cause investigation
Use the gstack-investigate skill to find the cause of duplicate items.
Show the reproduction and evidence first, and don't fix anything before approval.

Claude: /investigate
OutputReview by severity · Reproduction steps · Root causePass conditionEvery point has file/behavior evidence, and guesses are separated from facts.
EXAMPLE OUTPUT 05Sample review·investigate result
P1 · User input can run as HTML

app.js inserts the title with innerHTML. It can be reproduced with malicious HTML input; a text node or textContent is needed.

Root cause

The duplicate check runs after rendering, so a fast second click reads the same array state. The cause is the check order, not button disabling.

Human check → Are severity, file location, reproduction conditions and user impact tied to one piece of evidence?
