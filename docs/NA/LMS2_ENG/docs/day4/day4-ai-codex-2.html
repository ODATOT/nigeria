1. Story and lab background

Late in the project, a strange conversation happens in a bug review meeting. The planner says "The rating doesn't show on the expert list screen," the API developer says "The star_rating field for the expert list card isn't in the API Response spec," and the front-end developer says "The expert's approve button calls an API that doesn't exist."

When the plan, screen design, API spec and DB tables don't line up like this, communication costs between developers grow and it breeds code rework.

In this lab, you'll learn to use Codex to survey scattered terms across all project docs and build a standard term dictionary (Glossary) that runs from planning all the way to DB variable names.

2. Learning goals

  • Identify how domain terms are scattered across docs and design specs.
  • Define the detection areas and English abbreviations (domain standard names) for the project.
  • Define a standard term dictionary that planners, developers and designers all follow.
  • Use AI to map legacy words to variable names and data types.

🛠️ Follow-along lab guide

  1. Create lab files: press the download buttons below to download the planning docs and API spec draft, and save them in the automation/ folder.
  2. Hand standardization to Codex: send the **Codex request prompt** below in the Codex Client prompt box and build.
  3. Review the report: check that mismatched items are correctly mapped to a detection area, English standard name and recommended action.
