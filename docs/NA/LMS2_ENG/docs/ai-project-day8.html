Build contract for one REQ 

Use only the approved docs (screen specs · DATA/API · LAYER_MAP · BACKEND_RULES) as your basis.
This time the scope is just [REQ-___].
Before writing code, first report 1) related doc paths 2) files to change 3) anything unclear.
Build after approval, and at the end summarize the changed files · how to run ·
results for each acceptance criterion (only what you actually ran).
Don't touch other REQs or do refactoring I didn't ask for.

QA after integration (gstack) 

/qa-only
Test the core user flow from start to finish.
- Normal input / empty input / wrong input / repeated clicks / refresh / mobile width
- Write it as a table (test item / expected result / actual result / verdict / steps to reproduce)
- Draft FAIL items as DEF-### and suggest a severity
Don't change any code.
