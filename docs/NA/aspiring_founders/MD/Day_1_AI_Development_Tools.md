# Day 1. AI 개발 도구와 작업 방식 익히기

## 1. 교육 개요

- **교육 시간:** 6시간
- **대상:** 개발 경험이 없거나 적은 예비창업자
- **핵심 도구:** Codex, Antigravity, 웹 브라우저, 코드 편집기
- **핵심 목표:** Codex로 요구사항 MD를 작성하고, Antigravity로 서비스를 구현한 뒤, Codex로 테스트·검증하는 기본 작업 사이클을 익힌다.
- **최종 산출물:** 개인 프로젝트 폴더, `README.md`, 실행 가능한 단일 웹페이지, 프롬프트 기록

## 2. 학습 목표

교육 종료 후 수강생은 다음을 수행할 수 있어야 한다.

1. 프로젝트 폴더와 파일의 관계를 설명할 수 있다.
2. Codex와 Antigravity에서 같은 프로젝트 폴더를 열 수 있다.
3. Codex에서 목표·조건·완료 기준이 포함된 요구사항 MD를 작성할 수 있다.
4. Antigravity에서 MD를 기준으로 웹페이지를 구현할 수 있다.
5. Codex에서 문서 대비 구현 결과를 검증하고 테스트 항목을 만들 수 있다.
6. 검증 결과를 MD에 반영한 뒤 Antigravity에서 수정할 수 있다.

### 교육 운영자

- 계정·API 키·비밀번호를 프롬프트에 입력하지 않는다는 보안 원칙 안내

### 수강생

- 개인 노트북과 관리자 권한

- Chrome 또는 Chromium 기반 브라우저
- 프로젝트를 저장할 로컬 폴더

### 5.1 AI 개발의 기본 사이클 — 10분

```text
Codex로 MD 작성 → Antigravity로 구현 → Codex로 테스트·검증
→ Codex로 MD 보완 → Antigravity로 수정
```

AI가 생성한 결과는 완성품이 아니라 검토 대상이다. 한 번에 전체 서비스를
요청하기보다 한 번에 확인할 수 있는 작은 작업으로 나눈다.

#### 전달할 내용

- Codex는 생각을 요구사항 MD로 구조화한다.
- Antigravity는 MD를 기준으로 서비스 파일과 화면을 구현한다.
- Codex는 구현 결과가 MD와 일치하는지 테스트하고 검증한다.
- 변경이 필요하면 코드를 바로 고치기 전에 MD를 먼저 수정한다.
- 각 단계에는 파일 형태의 산출물이 남아야 다음 도구가 같은 기준을 사용한다.

#### 강사 질문

- 화면의 버튼 문구를 바꾸고 싶다면 가장 먼저 어떤 파일을 수정해야 하는가?
- Antigravity가 요구하지 않은 기능을 만들었다면 어느 단계에서 발견해야 하는가?
- “완성됐다”는 AI의 답변과 실제 브라우저 화면 중 무엇을 기준으로 판단해야 하는가?

### 5.2 폴더·파일·경로 이해 — 10분

#### 전달할 내용

- **프로젝트 폴더:** 문서, 코드, 이미지가 함께 저장되는 공통 작업 공간
- **파일:** 역할과 확장자를 가진 작업 단위 (`.md`, `.html`, `.css`, `.js`)
- **절대 경로:** 컴퓨터 안에서 프로젝트 위치를 정확히 나타내는 주소
- 두 도구에서 같은 절대 경로를 열어야 MD 수정과 구현 결과가 공유된다.

```text
my-startup-mvp/
├── README.md
├── PAGE_REQUIREMENTS.md
├── VALIDATION.md
├── index.html
├── styles.css
└── script.js
```

#### 2분 확인 활동

학생에게 파일 트리를 보여주고 다음 질문에 손으로 가리키게 한다.

- 서비스 개발 기준 문서는 무엇인가?
- 브라우저가 처음 여는 화면 파일은 무엇인가?
- 검증 결과는 어디에 기록하는가?
- 두 AI 도구가 반드시 동일하게 열어야 할 범위는 어디까지인가?

### 5.3 도구 역할과 좋은 프롬프트 — 10분

#### 도구 역할

- **Codex:** 기획과 요구사항을 MD로 작성·수정하고, 테스트·자동화·문서 대비 구현 검증을 수행한다.
- **Antigravity:** 작성된 MD를 읽고 프로젝트 생성, 서비스 기능 구현, UI/UX 개선과 구현 오류 수정을 수행한다.
- **브라우저:** AI의 설명이 아니라 실제 사용자 화면과 핵심 흐름을 검증한다.

기능 변경이 필요하면 먼저 Codex에서 MD를 수정하고, 변경된 문서를
Antigravity에 전달한 뒤 구현 결과를 다시 Codex에서 검증한다.

#### 좋은 프롬프트의 기본 구조

```text
[목표] 무엇을 만들 것인가?
[현재 상태] 어떤 파일과 화면이 있는가?
[요구사항] 반드시 포함할 내용은 무엇인가?
[제약사항] 변경하면 안 되는 것은 무엇인가?
[완료 기준] 무엇을 확인하면 끝난 것인가?
```

예시:

```text
Antigravity가 웹페이지 개발의 기준으로 사용할 PAGE_REQUIREMENTS.md를 만들어 주세요.
서비스 이름, 한 문장 소개, 시작하기 버튼을 필수 화면 요소로 정의해 주세요.
외부 라이브러리를 사용하지 않고 모바일에서도 읽기 쉬워야 한다는 제약과
브라우저에서 확인할 수 있는 완료 기준을 포함해 주세요.
결정되지 않은 내용은 임의로 정하지 말고 Open Questions로 분리해 주세요.
```

#### 나쁜 프롬프트와 개선 프롬프트 비교

```text
[모호한 요청]
멋진 스타트업 홈페이지를 만들어 줘.

[개선된 요청]
PAGE_REQUIREMENTS.md를 읽고 단일 소개 페이지를 구현해 주세요.
서비스 이름, 한 문장 소개, 장점 카드 3개, 시작하기 버튼을 포함합니다.
외부 라이브러리는 사용하지 않고 index.html, styles.css, script.js로 나눕니다.
버튼 클릭 시 안내 문구가 표시되고 모바일 375px에서도 가로 스크롤이
없어야 합니다. 완료 후 변경 파일과 실행 방법을 보고해 주세요.
```

### 5.4 안전한 작업과 복구 — 10분

- 비밀번호, 인증 토큰, API 키를 프롬프트나 저장소에 넣지 않는다.
- 파일 삭제나 대규모 변경 전에는 대상과 변경 범위를 확인한다.
- AI가 수정한 파일 목록과 변경 내용을 확인한 뒤 실행한다.
- 오류 메시지는 요약하지 말고 가능한 한 원문 그대로 전달한다.
- 정상 동작 시점을 기록하고 큰 변경 전에는 복사본이나 버전을 남긴다.

#### 오류 전달 템플릿

```text
[수행한 행동]
시작하기 버튼을 클릭했습니다.

[실제 결과]
아무 변화가 없고 콘솔에 다음 오류가 표시됩니다: ...

[기대 결과]
버튼 아래에 “준비 중입니다” 안내가 표시되어야 합니다.

[재현 단계]
1. index.html 열기
2. 시작하기 버튼 클릭
```

#### 복구 원칙

```text
정상 상태 확인 → 변경 범위 기록 → 한 단계 수정 → 실행 확인
→ 실패하면 오류 기록 → 마지막 정상 상태로 복구
```

### 5.5 전체 작업 사이클 시연 — 30분

#### 시연 목표

강사가 하나의 빈 폴더에서 시작해 Codex로 요구사항 MD를 만들고,
Antigravity로 웹페이지를 구현한 뒤, Codex로 문서 대비 결과를 검증하는
전체 흐름을 실제 화면으로 보여준다.

| 소요 시간 | 시연 구간 | 강사가 보여줄 행동 | 시연 산출물 |
|---|---|---|---|
| 5분 | 공통 폴더 열기 | 두 도구에서 같은 절대 경로를 확인한다. | 프로젝트 폴더 |
| 7분 | Codex 문서 작성 | `PAGE_REQUIREMENTS.md` 생성과 변경 내용 확인 | 요구사항 MD |
| 8분 | Antigravity 구현 | MD를 읽히고 첫 웹페이지를 생성·실행한다. | 웹페이지 |
| 5분 | Codex 검증 | 요구사항별 구현 여부를 표로 만든다. | 검증 결과 |
| 5분 | 수정 사이클 | MD 수정→Antigravity 반영→Codex 재검증 | 개선 화면 |

#### 시연 중 강조할 행동

1. AI에게 작업시키기 전 현재 폴더와 대상 파일을 말한다.

### 실습 2. Codex로 화면 요구사항 MD 만들기

4. 문서에 임의로 추가된 요구사항이 없는지 검토한다.
5. `README.md`에 프로젝트 목적과 이후 작업 흐름을 기록한다.

**완료 기준**

- `PAGE_REQUIREMENTS.md`에 목표, 화면 요소, 동작, 완료 조건이 있다.
- 모호하거나 결정되지 않은 내용은 질문으로 분리되어 있다.
- README만 읽고도 Antigravity에서 다음 작업을 시작할 수 있다.

### 실습 3. Antigravity로 MD를 구현하고 개선하기

2. 핵심 장점 카드 3개를 추가한다.
3. 모바일 화면에 맞춘 레이아웃을 적용한다.
4. 버튼 클릭 시 안내 문구가 표시되도록 구현한다.
5. 브라우저에서 핵심 동작을 실행한다.

**완료 기준**

- 요청 전후의 변경 사항을 설명할 수 있다.
- 버튼 동작을 직접 확인했다.
- 한 번 이상의 수정 또는 복구 경험을 기록했다.

### 검증 실습. Codex로 테스트·검증하기

- Codex에서 `PAGE_REQUIREMENTS.md`와 구현 파일을 함께 분석한다.
- 요구사항별 구현 여부를 체크리스트로 만든다.
- 반복 가능한 테스트 또는 검증 명령을 작성·실행한다.
- 누락, 오류, 문서와 다른 구현을 `VALIDATION.md`에 기록한다.
- 변경이 필요하면 요구사항 MD를 먼저 수정하고 Antigravity에서 반영한다.

#### Codex 따라 하기 프롬프트

```text
PAGE_REQUIREMENTS.md와 현재 구현 파일을 비교해 주세요.
아직 코드를 수정하지 말고 각 Acceptance Criteria를 다음 상태로 분류합니다.
- Pass: 코드와 실행 결과로 충족 확인
- Fail: 문서와 다르게 구현됨
- Manual Check: 브라우저에서 사람이 확인해야 함
- Not Implemented: 구현되지 않음

근거 파일과 확인 방법을 포함한 표를 VALIDATION.md에 작성해 주세요.
안전하게 실행 가능한 자동 검증이 있다면 먼저 명령과 목적을 설명하고 실행해 주세요.
```

#### 예시 검증 화면

```text
┌─ VALIDATION.md ───────────────────────────────────────────────┐
│ 완료 기준                         상태          근거/확인 방법 │
│ 서비스 이름 표시                  Pass          index.html     │
│ 장점 카드 3개                     Pass          index.html     │
│ 버튼 클릭 시 안내 표시            Pass          script.js      │
│ 모바일 375px 가로 스크롤 없음     Manual Check  브라우저 확인  │
│ 외부 라이브러리 미사용            Pass          파일 검사      │
│                                                              │
│ 수정 필요: 모바일에서 카드 간격이 너무 좁음                  │
└──────────────────────────────────────────────────────────────┘
```

#### 수정 사이클

```text
1. Codex 검증에서 Fail 또는 개선 항목 확인
2. Codex로 PAGE_REQUIREMENTS.md의 완료 기준 수정
3. Antigravity에 변경된 MD 기준 수정 요청
4. 브라우저 실행
5. Codex로 다시 검증
```

#### 실습 포인트

- Codex가 코드를 읽었다는 사실과 브라우저 동작 확인을 구분한다.
- 확인하지 못한 항목을 억지로 Pass 처리하지 않고 Manual Check로 남긴다.
- 자동 검증과 사람의 시각 검증을 함께 사용한다.
- 코드 문제를 바로 수정하기 전에 요구사항 변경인지 구현 오류인지 판단한다.

**완료 체크**

- [ ] 모든 완료 기준에 상태와 근거가 있다.
- [ ] 자동 검증과 수동 확인 항목이 구분돼 있다.
- [ ] `VALIDATION.md`가 저장됐다.
- [ ] 한 번 이상 MD 수정→Antigravity 반영→Codex 재검증을 수행했다.

- **목적:** 수강생 개인의 경력, 핵심 역량, 주요 프로젝트 이력 및 연동 링크를 담은 1페이지 포트폴리오 웹 서비스 구축
- **작성할 명세 파일:** `PORTFOLIO_REQUIREMENTS.md`

  3. 문의 및 링크: 이메일 문의하기 및 외부 링크(LinkedIn, GitHub 등)
- **완료 기준:** 브라우저에서 스킬 카드가 반응형으로 배치되고 문의 버튼 클릭 시 이메일 링크 동작 확인
