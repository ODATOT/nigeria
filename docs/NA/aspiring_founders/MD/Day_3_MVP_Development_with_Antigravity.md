# Day 3. PROJECT.md에서 동작하는 MVP 만들기

## 1. 교육 개요

- **교육 시간:** 6시간
- **선행 조건:** `PROJECT.md`와 `HANDOFF_PROMPT.md` 완성
- **핵심 도구:** Antigravity, Codex, 웹 브라우저
- **핵심 목표:** Day 2의 기획 문서를 Antigravity에서 실행 가능한 Web App으로 구현하고 Codex로 문서 대비 결과를 검증한다.
- **최종 산출물:** 프로젝트 기본 구조, 핵심 화면, 첫 번째 완전한 사용자 흐름, `VALIDATION_DAY3.md`, MVP v0.1

## 2. 학습 목표

교육 종료 후 수강생은 다음을 수행할 수 있어야 한다.

1. `PROJECT.md`를 기준으로 Antigravity에 단계적 구현을 지시할 수 있다.
2. 한 번에 검증 가능한 크기로 구현 작업을 나눌 수 있다.
3. 로컬에서 프로젝트를 실행하고 브라우저로 핵심 흐름을 확인할 수 있다.
4. 로딩·빈 값·오류 상태를 정상 화면과 구분할 수 있다.
5. Codex로 완료 조건별 Pass/Fail/Manual Check 검증표를 만들 수 있다.
6. 검증 결과를 MD에 반영한 뒤 Antigravity에서 수정할 수 있다.

## 3. 오늘의 핵심 원칙

```text
Antigravity에서 작게 구현 → 브라우저에서 바로 확인
→ Codex에서 문서 대비 검증 → MD 수정 → Antigravity에서 반영
```

Day 3의 목표는 화면을 많이 만드는 것이 아니라 핵심 사용자 흐름의 시작과
끝이 실제로 연결되는 MVP v0.1을 만드는 것이다.

### 5.0 강의 운영 구성

| 소요 시간 | 강의 구간 | 핵심 질문 |

| 10분 | 프로젝트 구조 | 화면, 스타일, 동작과 데이터는 어디에 위치하는가? |

### 5.1 문서를 구현 기준으로 사용하기 — 10분

Antigravity에 전체 서비스를 한 번에 요청하지 않는다. `PROJECT.md`에서
이번 작업에 필요한 화면, Must 기능, 데이터, 완료 조건과 제외 범위만
확인하고 구현 순서를 나눈다.

```text
PROJECT.md
├── Core User Flow       → 구현 순서
├── Features             → 작업 단위
├── Screen List          → 화면 파일과 이동
├── Data Model           → 입력과 결과 구조
├── Acceptance Criteria  → 구현 완료 판단
└── Out of Scope         → 만들지 않을 기능
```

**사용 이미지**

- `../LECTURE/assets/day3/01_project_md_to_build_plan.png`
- 구성: `PROJECT.md`의 섹션이 구현 순서·화면·기능·검증 항목으로 변환되는 흐름
- 강조 문구: `문서의 각 항목은 구현 또는 검증과 연결돼야 한다`
- 대체 텍스트: 프로젝트 문서를 구현 계획으로 변환하는 구조

### 5.2 프로젝트 구조와 실행 흐름 — 10분

기술 스택은 운영자가 제공한 스타터 템플릿을 사용한다. 학생은 프레임워크
선택보다 파일의 역할과 실행 흐름을 이해하는 데 집중한다.

```text
사용자 입력 → 화면 이벤트 → 데이터 처리 → 결과 상태 변경 → 화면 갱신
```

예시 구조:

```text
my-startup-mvp/
├── PROJECT.md
├── HANDOFF_PROMPT.md
├── src/
│   ├── screens/ 또는 pages/
│   ├── components/
│   ├── data/
│   └── styles/
└── VALIDATION_DAY3.md
```

**사용 이미지**

- `../LECTURE/assets/day3/02_project_structure.png`
- 구성: 문서, 화면, 공통 컴포넌트, 데이터와 검증 문서를 색상별 파일 트리로 표현
- 강조 문구: `파일 이름보다 역할과 연결 관계를 이해한다`
- 대체 텍스트: MVP 프로젝트의 기본 파일 구조

### 5.3 한 번에 검증 가능한 구현 단위 — 10분

```text
[큰 요청]
PROJECT.md를 보고 서비스를 전부 완성해 주세요.

[작은 요청]
프로젝트 기본 구조와 홈 화면만 구현해 주세요.
홈에서 조건 입력 화면으로 이동하는 버튼까지 연결하고,
로컬 실행 방법과 변경 파일을 보고해 주세요.
```

좋은 구현 단위는 작업 후 브라우저에서 한 가지 결과를 바로 확인할 수 있다.

**사용 이미지**

- `../LECTURE/assets/day3/03_incremental_build.png`
- 구성: 전체 MVP를 홈→입력→결과의 세 구현 블록으로 나눈 계단
- 강조 문구: `한 단계 구현하고 한 단계 확인한다`
- 대체 텍스트: 큰 MVP 작업을 검증 가능한 작은 구현 단위로 나눈 그림

### 5.4 정상·로딩·빈 값·오류 상태 — 10분

각 핵심 화면은 최소한 다음 상태를 고려한다.

| 상태 | 사용자에게 보여줄 내용 | 확인 질문 |
|---|---|---|
| 기본 | 입력 또는 시작 안내 | 다음 행동이 분명한가? |
| 로딩 | 처리 중 표시 | 중복 클릭을 방지하는가? |
| 빈 값 | 필요한 입력 안내 | 무엇을 입력해야 하는가? |
| 성공 | 핵심 결과와 다음 행동 | 목표를 완료했는가? |
| 오류 | 원인과 다시 시도 방법 | 사용자가 복구할 수 있는가? |

**사용 이미지**

- `../LECTURE/assets/day3/04_ui_states.png`
- 구성: 동일 화면의 기본·로딩·빈 값·성공·오류 상태 5개 비교
- 강조 문구: `정상 화면 하나만으로는 사용자 흐름이 완성되지 않는다`
- 대체 텍스트: 웹 화면에서 필요한 다섯 가지 상태 비교

## 6. 학생용 따라하기 실습 워크북

### 6.0 공통 진행 방식

```text
강사 시연 → 학생 따라 하기 → 브라우저 확인 → 체크박스 표시 → 다음 구간
```

검증 구간에서는 왼쪽 도구만 Codex로 전환한다.

### 6.1 실습 1 — 프로젝트 구조와 첫 화면 만들기

| 구간 | 시간 | 학생 작업 | 확인 결과 |
|---|---:|---|---|
| 1-A | 8분 | 문서와 미결정 사항을 Antigravity에 요약시킨다. | 구현 전 질문 |
| 1-B | 10분 | 스타터 템플릿과 실행 명령을 확인한다. | 실행환경 확인 |
| 1-C | 18분 | 기본 프로젝트와 홈 화면을 생성한다. | 첫 화면 |

구현 프롬프트:

```text
PROJECT.md를 기준으로 공통 스타터 템플릿에 프로젝트 기본 구조와 홈 화면을

```

예시 화면:

```text
┌──────────────────── 서비스 이름 ────────────────────┐

│                                                     │
│                  [ 시작하기 ]                       │
└─────────────────────────────────────────────────────┘
```

**실습 포인트**

- 구현 전 요약과 질문을 먼저 받는다.
- 첫 요청에서 모든 화면을 만들지 않는다.
- 실행 명령을 `README.md`에 기록한다.

**완료 체크**

- [ ] 프로젝트가 로컬에서 실행된다.
- [ ] 홈 화면이 `PROJECT.md`와 일치한다.
- [ ] 변경 파일과 실행 방법이 기록됐다.

### 6.6 Day 3 자율형 실습 주제 (Autonomous Practice Topics)

기본 따라하기 실습(PROJECT.md 기반 MVP v0.1) 외에, 수강생이 자신의 역량과 학습 진도에 맞춰 도전할 수 있는 **자율형 실습 주제 2종**을 제공합니다.

#### [자율 주제 A] 단순 CRUD 노트 앱 MVP v0.1 구현 (Simple CRUD Notes MVP)

- **목표:** 브라우저 localStorage를 활용한 데이터 저장·조회·삭제 MVP 개발
- **Must 기능:**
  1. 텍스트 노트 작성 및 저장 버튼 (localStorage 연동)
  2. 저장된 노트 목록 조회
  3. 개별 노트 삭제 버튼
- **상태 처리:** 빈 입력 시 안내 메시지, 저장된 노트 없을 때 빈 화면 안내
- **완료 기준:** 노트 생성 → 조회 → 삭제 흐름이 브라우저 새로고침 후에도 유지될 것.

#### [자율 주제 B] 인터랙티브 계산기 또는 단위 변환기 도구 (Interactive Calculator/Converter)

- **목표:** 사용자 입력을 받아 실시간으로 계산 결과를 반환하는 유틸리티 웹 서비스 구현 (예: BMI 계산기)
- **Must 기능:**
  1. 키(cm)와 몸무게(kg) 입력 폼
  2. BMI 수치 계산 및 결과/판정(저체중/정상/과체중/비만) 표시
  3. 초기화(재입력) 버튼
- **완료 기준:** 유효한 숫자 입력 시 정확한 계산 결과와 판정 문구가 화면에 표시될 것.
