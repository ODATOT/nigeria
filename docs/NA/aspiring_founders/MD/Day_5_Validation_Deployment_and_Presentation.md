# Day 5. 최종 검증·배포·발표와 개선

## 1. 교육 개요

- **교육 시간:** 6시간
- **선행 조건:** MVP v1.0, `VALIDATION_DAY4.md`, 발표 시나리오
- **핵심 도구:** Codex, Antigravity, 브라우저, 공통 배포 도구
- **핵심 목표:** Codex로 최종 자동화·검증을 수행하고 외부 데모 URL을 만든 뒤 실제 사용자 피드백을 반영해 프로젝트를 발표한다.
- **최종 산출물:** 최종 MVP, 데모 URL, `FINAL_VALIDATION.md`, 발표 자료, 동료 피드백, 개선 로드맵

## 2. 학습 목표

1. 배포 전 비밀정보와 데모 데이터를 안전하게 점검할 수 있다.
2. Codex로 최종 테스트·빌드·검증 과정을 반복 실행할 수 있다.
3. 외부 데모 URL에서 핵심 흐름을 재현할 수 있다.
4. 문제→해결책→데모→학습 구조로 5분 발표를 구성할 수 있다.
5. 동료 피드백을 관찰 사실과 개선 제안으로 기록할 수 있다.
6. Codex에서 개선 요구를 MD로 정리하고 Antigravity에서 마지막 수정을 할 수 있다.

## 3. 오늘의 핵심 원칙

### 5.1 최종 검증 피라미드 — 10분

```text
자동 검사: 빌드, 테스트, 정적 검사, 민감정보 패턴 확인
수동 검사: 핵심 흐름, 모바일, 오류 상태, 배포 URL
사용자 검사: 설명 없이 첫 행동과 핵심 결과를 완료하는지 관찰
```

**사용 이미지**

- `../LECTURE/assets/day5/01_final_validation_pyramid.png`
- 구성: 자동 검사→수동 검사→사용자 검사의 3단 피라미드
- 강조 문구: `자동화만으로 사용자 경험을 검증할 수 없다`
- 대체 텍스트: 최종 검증의 자동·수동·사용자 검사 구조

### 5.2 안전한 배포 — 10분

배포 전에 다음을 확인한다.

- 비밀번호, API 키, 토큰이 코드나 MD에 포함되지 않았는가?
- `.env` 같은 비밀정보 파일이 공개 대상에서 제외됐는가?
- 실제 개인정보 대신 데모 데이터를 사용하는가?
- 실제 결제가 아닌 Mock Payment임을 화면에 표시했는가?
- 외부 API 실패 시 데모가 완전히 중단되지 않는가?

**사용 이미지**

- `../LECTURE/assets/day5/02_deployment_safety_gate.png`
- 구성: 코드가 배포 문을 통과하기 전 비밀키·개인정보·실결제·오류 대응 체크
- 강조 문구: `공개 URL은 로컬보다 더 엄격하게 확인한다`
- 대체 텍스트: 웹 배포 전 안전 점검 게이트

### 5.3 배포 후 검증 — 10분

```text
새 브라우저 → 데모 URL 접속 → 정상 시나리오 → 빈 값 → 실패 상태
→ 모바일 화면 → 새로고침 → 공유 링크 재접속
```

로컬 캐시나 로그인 상태에 의존하지 않도록 시크릿 창 또는 다른 기기에서
확인한다.

**사용 이미지**

- `../LECTURE/assets/day5/03_local_vs_deployed.png`

- 대체 텍스트: 로컬 환경과 배포 환경에서 확인해야 할 차이

### 6.2 실습 2 — 배포와 외부 URL 검증

운영자가 지정한 공통 배포 방식과 스타터 템플릿의 배포 안내를 사용한다.
플랫폼별 계정 생성이나 결제 설정은 교육 전에 완료한다.

| 구간 | 시간 | 학생 작업 | 결과 |
|---|---:|---|---|
| 2-A | 6분 | 배포 대상·제외 파일·환경변수를 확인한다. | 배포 체크 |
| 2-B | 10분 | 공통 방식으로 첫 배포를 실행한다. | 배포 결과 |
| 2-C | 8분 | 데모 URL을 새 브라우저에서 연다. | 외부 접속 |
| 2-D | 10분 | 정상·빈 값·실패·모바일을 확인한다. | 배포 검증 |
| 2-E | 6분 | URL과 제한사항을 README에 기록한다. | 배포 문서 |

예시 배포 완료 화면:

```text
Demo URL: https://example-demo.invalid
Deployment Status: Ready
Verified:
[x] 새 브라우저 접속
[x] 핵심 사용자 흐름
[x] 모바일 375px
[x] Mock 기능 표시
Known Limitations: 외부 API 장애 시 Mock 결과 사용
```

**실습 포인트**

- 배포 로그에 비밀값을 복사하지 않는다.
- URL만 열리는 것이 아니라 핵심 흐름을 끝까지 실행한다.
- 다른 학생의 기기에서도 접속을 확인한다.

| 데모 완성도 | 외부 URL에서 핵심 흐름이 동작하는가? |

| 검증 과정 | 테스트·오류·제한사항을 솔직하게 설명하는가? |
| 향후 계획 | 다음 검증 또는 개선이 구체적인가? |
