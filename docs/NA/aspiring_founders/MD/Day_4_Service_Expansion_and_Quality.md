### 5.1 변경 요구사항과 영향 범위 — 20분

변경은 코드를 바로 수정하는 작업이 아니라 기준 문서를 갱신하는 일부터
시작한다.

```text
[변경 목적]
[추가할 기능]
[변경할 화면·데이터]
[반드시 유지할 기존 기능]
[신규 완료 조건]
[오류·예외 상태]
[Out of Scope]
[회귀 테스트 항목]
```

예시:

```text
변경 목적: 생성된 결과를 나중에 다시 확인한다.
추가 기능: 결과 저장과 저장 목록 조회
보존 조건: 기존 입력→결과 생성 흐름은 변경하지 않는다.
예외: 저장할 결과 없음, 중복 저장, 저장 실패
Out of Scope: 회원가입, 클라우드 동기화
```

**사용 이미지**

- `../LECTURE/assets/day4/01_change_impact_map.png`
- 구성: 새 기능이 화면, 데이터, 사용자 흐름과 테스트에 미치는 영향 지도
- 강조 문구: `추가 기능 하나는 여러 기존 요소에 영향을 준다`
- 대체 텍스트: 기능 변경의 영향 범위를 보여주는 지도

- `../LECTURE/assets/day4/02_change_request_anatomy.png`
- 구성: 변경 목적, 범위, 보존 조건, 완료 기준, 회귀 테스트의 다섯 블록
- 강조 문구: `추가할 것과 깨지면 안 되는 것을 함께 쓴다`
- 대체 텍스트: 안전한 변경 요구사항의 구성 요소

### 5.2 오류·예외·복구 경험 — 10분

| 상황 | 잘못된 처리 | 개선된 처리 |
|---|---|---|
| 빈 값 | 아무 반응 없음 | 필요한 입력과 위치 안내 |
| 중복 | 동일 항목 반복 생성 | 중복 안내와 기존 항목 보기 |
| 처리 실패 | 기술 오류 노출 | 쉬운 설명과 다시 시도 버튼 |
| 권한 없음 | 빈 화면 | 접근 조건과 돌아가기 제공 |
| 데이터 없음 | 오류처럼 표시 | 첫 데이터 생성 행동 안내 |

**사용 이미지**

- 대체 텍스트: 사용자가 오류에서 복구할 수 있는 화면 구성

#### [자율 주제 A] 기존 목록 화면에 실시간 검색 및 필터·정렬 기능 추가

- **목표:** 기존 데이터 목록(노트, 상품, 게시물 등)에 사용자 편의 기능 추가 및 회귀 검증
- **추가 기능:**
  1. 키워드 실시간 검색 (제목/내용 기준)
  2. 정렬 및 필터링 (최신순, 상태별 등)
- **보존 조건:** 기존 항목 생성, 조회, 상세 보기, 삭제 흐름은 파괴되지 않아야 함
- **산출물:** `CHANGE_REQUEST_SEARCH.md` 및 검색 기능이 추가된 MVP

#### [자율 주제 B] 에러 상태 및 빈 값 UX 전면 개선 (Robust Error & Empty States)

- **목표:** 모든 입력 폼과 비동기 처리에서 발생 가능한 예외 상황 대응 강화
- **추가 기능:**
  1. 빈 값/유효하지 않은 입력 시 필드별 즉각적인 인라인 에러 안내
  2. 처리 실패 시 원인 설명 + 입력 데이터 보존 + 재시도(Retry) 버튼 제공
  3. 데이터 0건 시 첫 시작을 돕는 Empty State 액션 버튼 제공
- **보존 조건:** 정상 성공 시나리오는 동일하게 유지될 것
- **산출물:** 예외 처리가 강화된 견고한 MVP v1.0
