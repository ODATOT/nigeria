# AI 기반 Web App MVP 개발 기본 교육 커리큘럼

## 1. 교육 개요

-   **교육 기간:** 5일
-   **교육 시간:** 1일 6시간 / 총 30시간
-   **교육 방식:** 교육 → 실습 → 공유
-   **주요 도구:** Codex, Antigravity
-   **교육 목표:** 자신의 서비스 아이디어를 AI가 이해할 수 있는 기획
    문서(MD)로 구조화하고, Codex와 Antigravity를 활용하여 실제 동작하며
    핵심 사용자 흐름을 시연할 수 있는 Web App MVP와 데모 URL까지 완성한다.
-   **기본 도구 흐름:** Codex에서 기획·요구사항 MD를 작성하고,
    Antigravity에서 MD를 기준으로 서비스를 개발한 뒤, Codex에서 테스트,
    자동화, 문서 대비 구현 검증과 개선 목록 작성을 수행한다.
-   **권장 공통 기술 스택:** 교육 시작 전 운영자가 하나의 웹 프레임워크와
    실행·배포 방식을 정하고 스타터 템플릿으로 제공한다. 수강생별 기술
    스택 분산을 피하고, 과정의 초점을 설치가 아닌 기획과 구현에 둔다.

### 전체 교육 흐름

**Day 1 도구 익히기 → Day 2 AI와 기획하기 → Day 3 MVP 만들기 → Day 4
서비스 완성하기 → Day 5 발표하고 개선하기**

# Day 4. 상세 기능을 추가하여 서비스 완성하기

> 상세 강의안: [`Day_4_Service_Expansion_and_Quality.md`](./Day_4_Service_Expansion_and_Quality.md)

## 교육 목표

> **기본 MVP에 실제 서비스에 필요한 기능을 추가한다.**

모든 프로젝트에 Membership과 Billing을 일괄 적용하지 않는다. 프로젝트
유형에 맞는 확장 기능을 선택하고, **기획 문서를 변경한 뒤 AI가 기존
시스템을 확장하도록 지시하는 과정**을 경험한다.

### 프로젝트 유형별 선택 트랙

| 프로젝트 유형 | 권장 확장 기능 |
|---|---|
| 커머스형 | Membership, 상품·주문, Mock Payment, Point |
| 플랫폼형 | Membership, 게시물, 검색, 상태 변경 |
| 업무도구형 | 데이터 입력·조회·수정, 필터, 내보내기 |
| AI 서비스형 | 프롬프트 입력, AI 응답, 결과 저장, 재실행 |

Day 2에 하나의 트랙을 선택하고 `PROJECT.md`에 반영한다. 핵심 가설 검증과
관련 없는 회원가입·결제 기능은 구현하지 않아도 된다.

# 4. Codex와 Antigravity 역할 정의

| 단계 | 주 도구 | 교육에서의 역할 | 주요 산출물 |
|---|---|---|---|
| ① 기획·문서화 | **Codex** | 생각과 요구사항 구조화, 질문과 미결정 사항 정리, MD 작성·수정 | `PROJECT.md`, 기능 명세, 완료 기준 |
| ② 서비스 개발 | **Antigravity** | MD 분석, 프로젝트 생성, 기능 구현, UI/UX 구체화, 구현 오류 수정 | 실행 가능한 Web App MVP |
| ③ 자동화·검증 | **Codex** | 문서 대비 구현 점검, 테스트 작성·실행, 반복 작업 자동화, 오류·누락·개선 목록 정리 | 테스트, 자동화 스크립트, 검증 보고서 |
| ④ 피드백 반영 | **Codex → Antigravity** | 검증 결과를 MD에 반영한 뒤 변경된 문서를 기준으로 서비스 수정 | 갱신된 MD와 개선된 MVP |

### 표준 작업 사이클

```text
Codex: 아이디어·요구사항을 MD로 작성
  → Antigravity: MD를 읽고 서비스 개발
  → Codex: 테스트·자동화·문서 대비 검증
  → Codex: 검증 결과와 변경 요구를 MD에 반영
  → Antigravity: 변경된 MD를 기준으로 서비스 개선
```

두 도구가 임의로 같은 작업을 중복하지 않도록 각 단계의 주 도구를
명확히 한다. 다만 Codex의 검증에서 발견된 코드 문제는 수정 요구사항으로
정리한 뒤 Antigravity에서 구현하는 것을 기본 원칙으로 한다.

# 5. 교육 운영 원칙

## ① 하나의 프로젝트를 5일 동안 발전시킨다

매일 새로운 예제를 만드는 방식이 아니라 Day 1부터 Day 5까지 **동일한
프로젝트를 지속적으로 발전**시킨다.

## ② 문서를 먼저 수정하고 개발한다

기능을 바로 추가하기 전에 요구사항을 먼저 MD에 반영한다.

**생각 → Codex로 MD 작성·수정 → Antigravity로 개발 → Codex로 테스트·검증
→ 검증 결과를 MD에 반영 → Antigravity로 다시 수정**

이 과정을 반복한다.

## ③ Codex와 Antigravity가 같은 폴더를 사용한다

학생들이 두 AI 도구를 별개의 실습 도구로 이해하지 않고, **Codex의 MD를
Antigravity가 구현하고 Codex가 다시 검증하는 하나의 작업 파이프라인**으로
이해하도록 한다.

## ④ 결과보다 과정을 공유한다

공유 시간에는 완성된 화면만 발표하는 것이 아니라 다음 내용을 함께
공유한다.

-   어떤 프롬프트를 사용했는가?
-   AI가 어떤 결과를 만들었는가?
-   어떤 문제가 발생했는가?
-   어떻게 수정했는가?
-   다음에는 어떻게 지시하면 더 좋은 결과가 나올 것인가?

## ⑤ 공통 기술 스택과 스타터 템플릿을 사용한다

교육 운영자는 과정 시작 전에 하나의 기술 스택, 실행 명령, 폴더 구조,
배포 방법을 결정한다. 설치 실패에 대비한 완성된 스타터 템플릿도 함께
제공한다. 기술 선택 자체가 학습 목표인 경우를 제외하고 수강생이 서로
다른 프레임워크를 선택하지 않도록 한다.

## ⑥ 초보자를 위한 안전장치를 제공한다

-   API 키·비밀번호·개인정보를 프롬프트나 저장소에 입력하지 않는다.
-   AI가 변경한 파일 목록과 변경 내용을 실행 전에 확인한다.
-   오류 메시지, 재현 단계, 기대 결과를 함께 기록한다.
-   정상 동작 시점을 버전 또는 복사본으로 남겨 복구 가능하게 한다.
-   설치 실패자를 위한 예제 프로젝트와 공통 문제 해결표를 준비한다.

## ⑦ 로컬 실행에서 배포까지 완료한다

Day 5에는 운영자가 정한 공통 배포 방식을 사용해 외부에서 접속 가능한
데모 URL을 만든다. 실제 비밀키와 실결제 대신 데모 데이터와 Mock 기능을
사용한다.

# 7. 교육의 핵심 메시지

> **AI에게 코딩을 시키는 교육이 아니라, 내 아이디어를 AI가 이해할 수
> 있는 문서로 만들고 그 문서를 실제 서비스로 발전시키는 교육**

학생들은 5일 동안 다음 과정을 직접 경험한다.

**아이디어 → 구조화 → 문서화 → AI 개발 → 테스트 → 개선 → MVP → 발표**
