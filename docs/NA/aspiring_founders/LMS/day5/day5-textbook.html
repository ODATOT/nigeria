최종 검증·배포·발표와 개선

1. 교육 개요 및 핵심 원칙

💡 Day 5 핵심 원칙:
로컬에서 동작함 ≠ 배포 환경에서 동작함
AI가 완료했다고 말함 ≠ 사용자가 핵심 흐름을 완료함
발표가 끝남 ≠ 검증이 끝남

2. 최종 검증 3단계 피라미드

자동 검사: 빌드, 테스트, 정적 검사, 민감정보 패턴 확인 수동 검사: 핵심 흐름, 모바일, 오류 상태, 배포 URL 사용자 검사: 설명 없이 첫 행동과 핵심 결과를 완료하는지 관찰

3. 안전한 배포 체크리스트

  • ☐ 비밀번호, API 키, 토큰이 코드나 MD에 포함되지 않았는가?
  • ☐ .env 같은 비밀정보 파일이 공개 대상에서 제외됐는가?
  • ☐ 실제 개인정보 대신 데모 데이터를 사용하는가?
  • ☐ 실제 결제가 아닌 Mock Payment임을 화면에 표시했는가?
  • ☐ 외부 API 실패 시 데모가 완전히 중단되지 않는가?

4. 5분 발표 이야기 구조

시간발표 내용보여줄 자료
40초사용자와 문제문제 한 문장
40초현재 대안과 핵심 가치Before/After
2분핵심 사용자 흐름실제 데모 URL
50초구현·검증 과정Codex→Antigravity→Codex 흐름
30초배운 점과 다음 단계개선 로드맵
20초여유 시간데모 지연 대비

5. 실습별 프롬프트 가이드

실습 1. 최종 자동화·검증 (Codex)

📌 Codex: PROJECT.md, VALIDATION_DAY4.md와 현재 구현을 기준으로 최종 검증 계획을 세워 주세요. 안전하게 실행 가능한 테스트·빌드·정적 검사와 민감정보 패턴 점검을 수행하고, 브라우저에서 확인할 항목은 Manual Check로 남깁니다. 결과를 FINAL_VALIDATION.md에 근거와 함께 기록해 주세요. 검증 전에 코드를 수정하지 마세요.

실습 2. 배포 후 제한사항 기록 (Codex)

📌 Codex: 배포 URL에서 확인한 결과를 README.md에 추가해 줘. 포함할 항목: - Demo URL - 확인된 기능 목록 (체크박스 형태) - Known Limitations (알려진 제한사항) - 데모 데이터 초기화 방법 코드는 수정하지 말고 문서만 업데이트해 줘.

실습 3. 5분 발표안 생성 (Codex)

📌 Codex: PROJECT.md와 FINAL_VALIDATION.md를 기반으로 5분 발표안을 작성해 줘. 구조: 문제 → 핵심 가치 → 데모 시나리오 → 개발 과정 → 배운 점 → 다음 단계 데모 시나리오는 5단계 이내로 제한하고, 실패 시 보여줄 스크린샷과 대체 설명도 포함해 줘.

최종 개선 (Codex + Antigravity)

📌 Codex: 동료 피드백 내용을 기반으로 최종 변경 요구사항을 MD로 정리해 줘. 피드백: [받은 피드백 내용 붙여넣기] '발표 전 필수'와 '발표 후 개선'으로 분류하고, 대규모 구조 변경이나 새 기능은 '발표 후 로드맵'으로 이동해 줘.

6. 상호 리뷰 피드백 양식

[관찰] 사용자가 실제로 한 행동 [문제] 목표 달성을 막거나 혼란을 준 지점 [근거] 화면, 메시지 또는 재현 단계 [제안] 바꾸면 좋을 한 가지 [우선순위] 발표 전 필수 / 발표 후 개선

7. 발표 후 회고 질문 (NEXT_STEPS.md)

  1. 5일 동안 검증한 가장 중요한 가설은 무엇인가?
  2. 사용자 반응으로 새롭게 알게 된 사실은 무엇인가?
  3. 제거하거나 미룰 기능은 무엇인가?
  4. 다음에 인터뷰하거나 테스트할 사용자는 누구인가?
  5. 2주 안에 개선할 기능·문서·검증 항목은 무엇인가?
⚠️ 발표 직전 금지 사항:
대규모 구조 변경, 새 기능 추가, 미검증 코드 배포는 하지 않습니다.
정상 데모를 깨뜨릴 가능성이 있는 변경은 발표 후 로드맵으로 이동합니다.
