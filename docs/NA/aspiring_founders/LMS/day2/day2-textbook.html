AI와 개발 가능한 프로젝트 기획하기

1. 교육 개요 및 핵심 원칙

💡 Day 2 핵심 원칙: 많은 기능보다 하나의 완전한 사용자 흐름을 먼저 만든다.

Day 2에서는 서비스 코드를 구현하지 않습니다. Codex로 기획과 요구사항을 충분히 문서화하며, 완성된 PROJECT.md는 Day 3에 Antigravity가 읽고 서비스를 개발하는 단일 기준 문서로 사용됩니다.

2. 아이디어 vs 문제 정의

기술이나 기능부터 정하면 실제 사용자 문제와 관계없는 제품이 만들어집니다. 문제 문장에는 최소한 사용자, 상황, 어려움, 원하는 변화가 들어가야 합니다.

아이디어 중심 (❌)문제 중심 (✅)
"AI 기반 여행 플래너 앱""혼자 해외여행 가는 사람이 동선 계획에 2시간 이상을 쓴다"
"식당 추천 앱""퇴근 후 혼자 저녁 장소를 10분 안에 결정하고 싶은 직장인"

3. 핵심 사용자 흐름 설계

입력→처리→결과 한 줄 흐름으로 핵심 사용자 행동을 정의합니다.

입력: 선호 장소와 여행 가능 시간 입력 처리: 조건에 맞는 방문 순서와 이동 동선 생성 결과: 사용자가 일정표를 확인하고 저장 핵심 흐름 화면: 홈 → 조건 입력 → 일정 생성 → 결과 확인 → 일정 저장

## 1. Project Overview ## 2. Problem ## 3. Target User ## 4. Current Alternatives ## 5. Core Value and Hypothesis ## 6. Core User Flow ## 7. Features and Acceptance Criteria ## 8. Screen List ## 9. Data Model ## 10. Technical Requirements ## 11. MVP Scope ## 12. Out of Scope ## 13. Risks and Open Questions ## 14. Demo Scenario

5. 실습별 프롬프트 가이드

실습 1. 한 장 서비스 정의서

📌 Codex: 내가 만들 서비스를 한 장 정의서로 작성해 줘. 아이디어: [내 아이디어] 1. 목표 사용자 (상황과 행동으로 구체적으로) 2. 사용자 문제 (상황, 불편, 현재 대안 포함) 3. 핵심 가치 제안 4. 한 줄 서비스 문장 임의로 사실을 추가하지 말고, 불확실한 부분은 질문으로 남겨줘.

실습 2. 핵심 흐름·화면·데이터 구조화

📌 Codex: 서비스 정의서 기반으로 핵심 흐름, 화면 목록(3~5개), 데이터 모델을 구조화해 줘. 핵심 흐름은 입력→처리→결과 형태로 한 줄 작성해 줘. 문서에 없는 내용은 임의로 추가하지 말고 질문으로 남겨줘.

실습 3. PROJECT.md 작성

📌 Codex: PROJECT.md 파일을 14섹션으로 생성해 줘. 조건: - 제공하지 않은 사실은 임의로 확정하지 말고 Open Questions로 분리 - Must 기능은 3~5개로 제한 - 각 기능에 확인 가능한 완료 조건 포함 - 구현하지 않을 항목을 Out of Scope에 명시

실습 4. MVP 범위 결정

📌 Codex: PROJECT.md의 MVP 범위를 검토해 줘. 각 기능을 Must/Should/Could/Out of Scope로 분류하고 근거를 설명해 줘. Must는 3~5개로 제한하고, 최종 결정 전에는 문서를 직접 수정하지 마세요.

실습 5. 사용자 시나리오 검증

📌 Codex: PROJECT.md 기준으로 정상, 빈 값, 실패 사용자 시나리오를 만들어 줘. 각 단계에서 필요한 화면, 기능, 데이터와 기대 결과를 표로 정리해 줘. 문서에 정의되지 않은 동작이나 모순되는 요구사항은 별도 표시해 줘.

실습 6. HANDOFF_PROMPT.md 개발 지시문 생성

📌 Codex: HANDOFF_PROMPT.md 파일을 생성해 줘. [기준 문서] PROJECT.md를 먼저 읽고 구현 기준으로 사용해 주세요. [이번 작업 범위] MVP 기본 구조와 첫 번째 핵심 사용자 흐름을 구현해 주세요. [우선순위] Must 기능부터 구현, Should/Could/Out of Scope 제외 [제약사항] 문서에 없는 요구사항 임의 추가 금지 [완료 기준] 로컬 실행 가능 + 핵심 흐름 시작 화면 확인 가능 [작업 보고] 파일목록·실행방법·구현항목·미구현항목 정리

6. AI 문서 검토 체크리스트

⚠️ PROJECT.md 검토 포인트
- AI가 사용자 문제를 임의로 바꾸지 않았는가?
- 존재하지 않는 사용자 요구를 추가하지 않았는가?
- Must 기능이 핵심 사용자 흐름과 연결되는가?
- 2일 안에 구현하기 어려운 기능이 Must에 포함되지 않았는가?
- 개인정보, 결제, 외부 API 위험 요소가 표시되어 있는가?
