Day 3 Detailed Curriculum

Data Normalization & ERD Design with Codex AI

Day 3 learning includes structuring the necessary data based on screen design and user flow, defining key entities and relationships to complete the normalized data structure and ERD, and verifying and supplementing the design with Codex AI. It's a module.

Study Overview

Day 3 is the step of connecting the previous screen design and data flow design to the actual database structure. Participants will extract the necessary data from screens and user flows and organize it into entities and properties.

Afterwards, relationships between entities are defined, and a normalization process from 1NF to 3NF is applied to design a data structure that reduces duplication and increases integrity. Ultimately, an ERD that can be used for service implementation Complete.

In this process, Codex AI is used as a project architect and auditor to sort data between planning and development (Task 01), build a dictionary of terminology standards across the project (Task 02), Automate analysis of chain impacts from schema modifications (Task 03), create DDL to record technical architecture decisions (Mission 01), and exception cases such as concurrency/integrity errors Carry out excavation (Mission 02).

Main session structure

Session 1 · 2 hours
Understanding ERD design and aligning data structures (Task 01)

Determine what data is needed based on screens and user flows, and organize it into structurable data items. Using Codex AI to identify key entities and relationships in planning meeting minutes Extract precisely and generate Mermaid ERD scripts.

  • Screen and user flow-based data extraction
  • Defining and grouping data fields (ERD concepts)
  • Resolving gaps in data structure understanding using Codex AI (Task 01)
Session 2 · 3 hours
Terminology standardization (Task 02) and change impact analysis (Task 03)

Convert the extracted data into entities, apply a normalization process, and build a standard dictionary for mixed vocabulary (Member/Customer/User/Member) within the project. Additionally, when changing DB schema, API and We thoroughly analyze the scope of screen influence.

  • Apply 1NF → 2NF → 3NF normalization
  • Building a Codex AI-based term fragmentation standard dictionary (Task 02)
  • Automatically generate API/UI chain impact analysis report when modifying DB schema (Task 03)
Session 3 · 1 hour
Record architectural decisions (Mission 01) and discover exception cases (Mission 02)

The normalization and DB structure decision-making background is permanently preserved as a log (DDL), and fatal edge cases such as concurrency errors and foreign key integrity collapse are discovered and countermeasures are established.

  • Codex AI-based Design Decision Log (Why) Creation (Mission 01)
  • Physical schema-based concurrency/referential integrity edge case detection and response (Mission 02)
  • Final ERD and deliverable comprehensive review feedback
