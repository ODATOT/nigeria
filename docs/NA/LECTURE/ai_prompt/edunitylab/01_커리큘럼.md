# ODA Boost AI - ACE AI Startup Bootcamp 실습교육 커리큘럼 (Days 1–10)

## 1. 과정 개요

- **과정명**: [ACE Startup SW/AI 파일럿 과정] Antigravity 기반 AI 워크플로우 설계와 에이전트 구축
- **교육 형태**: PBL(프로젝트 기반 학습) 및 실습 중심 교육
- **교육 대상**: SW 비전공/전공 혼합 예비 창업가 및 기획자
- **필요 도구**: 1인 1PC, 인터넷 연결, Codex Client 활용 환경
- **본 문서 범위**: 1일차부터 10일차까지의 전체 교육 과정 설계 (Days 1–10)

---

## 2. 일자별 세부 커리큘럼 요약 (Days 1–10)

### Day 1. Codex Client 기반 요구사항 정의
- **1차시**: 프로젝트 콘텍스트 설정, 회의록 핵심 요약 전처리 (0단계) 및 사용자 역할 분류 (1단계).
- **2차시**: 기능 요구사항 정의 명세 표 빌드 (2단계) 및 결제/예약 등의 예외 흐름 보완 (3단계).
- **3차시**: 미결정 질문지 분리 (4단계), AI Linter 6대 검증 규칙 자가 린팅 (5단계) 및 Gmail API 발송.

### Day 2. 일관성 검증, 변경 관리 및 의사결정 추적
- **4차시**: 3대 명세(회의록, 요구사항, 화면설계) 간의 기획 삼각 모순 오디팅 및 결함 검출.
- **5차시**: 기획 개정에 따른 변경 전/후 의미적 디프 분석 및 화면, API, DB 연쇄 영향 범위(Impact Map) 도출.
- **6차시**: 미팅 대화록 기반 의사결정 로그(Decision Log) 및 미결 사항 분리, 우선순위 이슈 리포트 자동화.

### Day 3. 기술설계 (데이터 정규화)
- **7차시**: 자연어 시나리오에서 핵심 엔티티(User, Expert 등) 및 카디널리티(1:N, 1:1) 도출 및 Mermaid ERD 빌드.
- **8차시**: 파편화 혼용 어휘 전수 분석을 통한 프로젝트 표준 용어 사전(Glossary) 구축 및 스키마 변경 영향 공유.
- **9차시**: 아키텍처 정규화 설계 의결 보존(Design Decision Log) 및 동시성/Soft Delete 참조 붕괴 예외 안전 설계.

### Day 4. 기술설계 (API 설계 및 인터페이스 정의)
- **10차시**: 화면 UI 정보를 역추론한 RESTful 기반 표준 API 계약서(API Contract) Req/Res JSON 모델 구축.
- **11차시**: 기획서-API 간 필드/엔드포인트 누락 불일치 교차 오디팅 및 RFC 7807 표준 에러 아키텍처 리뷰.
- **12차시**: 정상 흐름(Happy Path) 및 이상 입력, 한도 초과, 인증 만료를 검증하는 API 테스트 시나리오 기획.

### Day 5. 서비스 설계 (UI / UX 리뷰 및 최적화)
- **13차시**: 초보 유저 관점 인지 부하 요건(별점 가려짐 등) 검토 및 액션 버튼/라벨의 UI 일관성 정렬.
- **14차시**: 예약 캘린더 통합 및 간편 동의를 적용해 9단계 동선을 4단계로 단축하는 User Journey 최적화.
- **15차시**: 50대 자영업자 페르소나 리서치 곤경 로그 채집 및 4대 품질 지표 수치 평점 Usability Score 평가.

### Day 6. 개발 (AI와 함께 화면 만들기)
- **16차시**: 정형 기획에서 반응형 대시보드 및 카드 컴포넌트 HTML 마크업과 CSS 그리드 뼈대 코드 생성.
- **17차시**: 비동기 데이터 렌더링 404 TypeError 예외 디버깅 및 가독성 향상 중복 코드 리팩토링.
- **18차시**: 런타임 JSON 파싱 오류 보고서(`day6_error_report.md`) 및 AI 코드 리뷰 피드백 리포트 작성.

### Day 7. 개발 (AI와 함께 기능 완성하기)
- **19차시**: 정적 로그인 폼 및 예약 카드에 이벤트(Submit, Click)를 적용해 로컬 스토리지에 데이터를 적재하는 연동.
- **20차시**: 뒤로 가기 시 데이터 리셋 방지 Session 캐싱 검증 및 중복 예약 연타 방지 disabled 락 장치 설계.
- **21차시**: 가용성 품질 진단 보고서(`day7_service_audit.md`) 및 가상 실버 사용자 동선 E2E 시나리오 최종 검증.

### Day 8. 회원 서비스 만들기 (User Management)
- **22차시**: 일반 이메일 가입/로그인(필수) 및 SNS 간편가입(선택) 기능 정의 구현 체크리스트 작성.
- **23차시**: 마케팅 정보 등 복잡한 인풋 폼의 가입 장벽(Friction Block)을 해소하는 UX 동선 개선안 기획.
- **24차시**: 이메일 중복 가입 가드 조건식 보강, 보안 로그인 실패 안내 문구 통일 및 60대 온보딩 FGI 분석.

### Day 9. 결제 서비스 설계하기 (Payment Service)
- **25차시**: 상품 선택부터 최종 완료까지 이메일 가입자의 결제 동선을 단 3단계 이하로 축약하는 결제 흐름 최적화.
- **26차시**: 한도 초과, 통신 지연 등 원시 에러 로그(ERR_CARD_LIMIT)를 사용자 행동 지침 한글 안내문으로 변환.
- **27차시**: 부가세 표기, 256비트 암호화 및 7일 환불 링크를 가미한 안심 영수증 UI 보강 및 이중결제 방어 락 설계.

### Day 10. 서비스 런칭하기 (Service Launch)
- **28차시**: 핵심 가치 요약 5초 소개서 작성, 뉴스레터 및 홈페이지 오픈 공지 배너 문구 수립.
- **29차시**: 쉬운 이용약관/개인정보방침 초안 가이드 및 회원/이용/결제/오류 5대 영역 고객 지원 FAQ 20선 구축.
- **30차시**: 프로젝트 Keep/Problem/Try 3대 회고 결과보고서 및 MoSCoW 로드맵 수립 후 최종 성과 공유.
