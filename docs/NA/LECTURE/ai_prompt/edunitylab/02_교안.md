# ODA Boost AI - ACE AI Startup Bootcamp 강사용 교안 (Days 1–10)

## 1. 강의 운영 원칙

- **강의 톤**: 개념은 이론 최소화로 컴팩트하게 전달하고, 실습(손 코딩 대신 프롬프트 가이드)과 공유를 극대화한다.
- **핵심 메시지**: 기획자는 단순히 줄글 기획서를 쓰는 사람이 아니라, AI와의 협업(Codex Client)을 통해 동작 가능한 명세 데이터 파이프라인을 설계하고 프로젝트 리스크를 방어하는 시스템 엔지니어이다.
- **진행 방식**: 설명 20%, 실습 60%, 피드백 및 공유 20% 비율을 준수한다.
- **시간 배분 (총 10일 / 일자별 9시간)**:
  - **Day 1**: 1~3차시 (요구사항 정의 명세화 파이프라인)
  - **Day 2**: 4~6차시 (일관성 검증, 변경 관리 및 의사결정 추적)
  - **Day 3**: 7~9차시 (기술설계 - 데이터 정규화 및 ERD 모델링)
  - **Day 4**: 10~12차시 (기술설계 - API 설계 및 인터페이스 정의)
  - **Day 5**: 13~15차시 (서비스 설계 - UI / UX 리뷰 및 최적화)
  - **Day 6**: 16~18차시 (개발 - AI와 함께 화면 만들기)
  - **Day 7**: 19~21차시 (개발 - AI와 함께 기능 완성하기)
  - **Day 8**: 22~24차시 (회원 서비스 - 온보딩 및 보안 가드)
  - **Day 9**: 25~27차시 (결제 서비스 - 이탈 차단 및 실패 예외 처리)
  - **Day 10**: 28~30차시 (서비스 런칭 - 패키징, FAQ 및 최종 로드맵 발표)

---

## 2. 강의 준비물

### 강사용
- **Codex Client 시연 환경**: 빔 프로젝트 화면 공유를 위한 사전 연결 테스트
- **예시 파일 세트**: 각 차시별 실습 입력 리소스셋 (HTML, JS, JSON 데이터 등)
- **Gmail 인증 계정**: Gmail API 플러그인 전송 테스트 완료 계정
- **타이머**: 실습 시간 통제용

### 학습자용
- **PC 및 개발 도구**: 인터넷 및 웹 브라우저, 에디터 및 Codex Client 설치 환경
- **API Key**: Google AI Studio에서 생성한 Gemini API 인증 키
- **연동 메일 주소**: 메일 전송 실습을 수신할 대표(의사결정권자)의 테스트용 이메일 주소

## 3. 차시별 강사 상세 가이드 & 지도 요령

### [Day 1] 요구사항 정의 및 명세화 파이프라인
* **1차시: 전처리 및 객체 분류**
  - **지도 요령**: Workspace 개념을 숙지하고 15줄 핵심 요약(`meeting-notes.md`) 및 역할군(Customer, Expert, Admin) 분류.
* **2차시: 기능 요구사항 설계 및 정상/예외 흐름 보완**
  - **지도 요령**: 요구사항 ID 기반 정형 명세 표 작성 및 예외 흐름(Fail-safe) 보완.
* **3차시: 질문지 분리, 린팅 검수 및 Gmail 전송**
  - **지도 요령**: 미결 정책 `open-questions.md` 작성 및 AI Linter 6대 검사 후 Gmail API 전송.

### [Day 2] 일관성 검증, 변경 관리 및 프로젝트 추적
* **4차시: 다중 문서 불일치 검출 (Consistency Check)**
  - **지도 요령**: 회의록, 요구사항서, 화면설계서 정책 모순을 AI 기획 검토 비서(Reviewer)로 감사.
* **5차시: 요구사항 변경 및 영향도 분석 (Impact Analysis)**
  - **지도 요령**: 기획 개정에 따른 변경 전/후 의미적 디프 분석 및 화면, API, DB 컬럼 영향 범위 도출.
* **6차시: 의사결정 추적 & 주간 이슈 리포트**
  - **지도 요령**: 미팅 대화록 기반 의사결정 로그(Decision Log) 및 미결 사항 분리, 이슈 리포트 자동화.

### [Day 3] 기술설계 (데이터 정규화)
* **7차시: 데이터 구조 이해 차이 해결 및 ERD 모델링**
  - **지도 요령**: 자연어 시나리오에서 핵심 엔티티를 도출하고 관계를 정의해 Mermaid ERD 코드 생성.
* **8차시: 용어 표준화 및 스키마 변경 영향 공유**
  - **지도 요령**: 혼용 어휘 수집해 표준 용어 사전(Glossary) 빌드 및 스키마 변경 영향 공유.
* **9차시: 설계 의사결정 기록 & Edge Case 예외 방어**
  - **지도 요령**: 정규화 설계 의결 로깅 및 동시성/Soft Delete 참조 붕괴 예외 안전 설계 가이드라인 작성.

### [Day 4] 기술설계 (API 설계 및 인터페이스 정의)
* **10차시: API 계약서 작성 및 불일치 오디팅**
  - **지도 요령**: 화면 UI 구성 필드를 기반으로 RESTful 기반 표준 API 계약서 Req/Res JSON 모델 구축.
* **11차시: API 변경 영향 추적 및 글로벌 아키텍처 리뷰**
  - **지도 요령**: 변경에 따른 영향 분석서와 RESTful 규칙 위배(동사 엔드포인트) 및 RFC 7807 에러 스키마 리뷰.
* **12차시: API 테스트 시나리오 설계**
  - **지도 요령**: Happy/Sad Path 경계값 테스트 케이스 목록 검증 체크리스트를 완성.

### [Day 5] 서비스 설계 (UI / UX 리뷰 및 최적화)
* **13차시: 초보 사용자 UX 리뷰 및 UI 일관성 검토**
  - **지도 요령**: 가독성 취약점과 인지 부하 요건을 색출하고 명칭/액션 컬러 UI 일관성 가이드 제안.
* **14차시: 사용자 동선 최적화 (User Journey Optimization)**
  - **지도 요령**: 9단계 동선을 아코디언 및 간편 동의를 적용해 4단계로 단축하는 화면 통합 설계.
* **15차시: 페르소나 리서치 및 종합 사용성 편의성 평가**
  - **지도 요령**: 50대 자영업자 페르소나 곤경 로그를 채집하고 4대 사용성 품질 지표 수치 평점 보고서 작성.

### [Day 6] 개발 (AI와 함께 화면 만들기)
* **16차시: 화면 초안 빠르게 만들기 (Boilerplate & Layout)**
  - **지도 요령**: 바탕화면 에디터의 막막함을 깨는 단계입니다. Codex에게 레이아웃 명세를 던져 반응형 HTML/CSS 뼈대를 자동으로 만들게 하십시오.
* **17차시: 비동기 데이터 통신 런타임 오류 디버깅**
  - **지도 요령**: `TypeError: Cannot read properties of undefined` 등 비동기 지연 오류의 원인을 파악하고 옵셔널 체이닝(`?.`)이나 방어 조건식을 가르칩니다.
* **18차시: 코드 리팩토링 및 리뷰 리포트 작성**
  - **지도 요령**: 동작하는 스파게티 소스에서 중복 헬퍼 함수를 분리하고 변수를 정명하며, 오류 보고서(`day6_error_report.md`)와 코드 리뷰 리포트를 아카이빙합니다.

### [Day 7] 개발 (AI와 함께 기능 완성하기)
* **19차시: 이벤트 바인딩 및 데이터 적재**
  - **지도 요령**: 정적 가입/예약 화면에 이벤트 리스너(Submit, Click)를 달고 브라우저 `localStorage`에 정보를 저장하는 동선을 연결시킵니다.
* **20차시: 시나리오 정보 유지 및 입력 락 설계**
  - **지도 요령**: 뒤로 가기 시 입력 데이터가 다 날아가는 곤경을 `sessionStorage` 캐싱으로 복원하고, 예약 확정 버튼 연타 에러를 `disabled = true` 락으로 차단합니다.
* **21차시: 서비스 완성도 오디팅 및 E2E 최종 검증**
  - **지도 요령**: 50대 가상 실버 사용자 역할을 임베딩해 전체 여정(E2E) E2E 검증서(`day7_e2e_validation.md`)를 도출해 냅니다.

### [Day 8] 회원 서비스 만들기 (User Management)
* **22차시: 온보딩 기능 정의 및 가입 장벽 해소**
  - **지도 요령**: 이메일 가입/로그인의 구현 체크리스트를 정비하고, 복잡한 인풋 폼의 가입 장벽(Friction Block)을 걷어내는 분할 동선을 기획하게 합니다.
* **23차시: 중복 가입 가드 보강 및 로그인 실패 예외 처리**
  - **지도 요령**: 이메일 중복 체크 logic 및 비밀번호 분실 임시 링크 세션을 검토하고, 로그인 실패 시 해커의 무작위 대입을 차단하는 통합 에러 안내 문구로 통일합니다.
* **24차시: 60대 가상 유저 온보딩 FGI 분석**
  - **지도 요령**: 디지털 소외 계층의 시선에서 가입 폼의 실시간 유효성 인디케이터 필요성을 발견하고 사용성 보고서를 완성하게 유도합니다.

### [Day 9] 결제 서비스 설계하기 (Payment Service)
* **25차시: 결제 동선 최소화 및 주문 요약 시트 기획**
  - **지도 요령**: 주문, 약관, 결제 수단을 모달 오버레이로 통합해 최종 완료까지의 결제 동선을 단 3단계 이하로 축약하는 흐름을 설계합니다.
* **26차시: PG 원시 오류 로그의 행동 지침 변환**
  - **지도 요령**: `ERR_CARD_LIMIT_EXCEEDED` 같은 날것의 에러 로그를 사용자가 즉시 대처할 수 있는 친절한 안심 한글 안내 문구로 바꿉니다.
* **27차시: 영수증 영수증식 가격 세분화 및 이중 승인 방제**
  - **지도 요령**: 상세 혜택 할인 표시와 256비트 보안 배지를 배치하고, 30분 유효 UUID 고유키(Idempotency Key)로 이중 전송을 차단하는 Mitigation Playbook을 작성합니다.

### [Day 10] 서비스 런칭하기 (Service Launch)
* **28차시: 서비스 오픈 패키징 및 홍보 배너 작성**
  - **지도 요령**: 핵심 가치가 응축된 5초 소개서와 뉴스레터, 홈페이지 배너용 공지 문구를 채널별 톤에 맞춰 수립합니다.
* **29차시: 쉬운 약관 초안 및 고객 지원 FAQ 20선 구축**
  - **지도 요령**: 가입, 이용, 결제, 오류 등 5대 도메인을 커버하는 고객 응대 시나리오 스크립트와 FAQ 자료집을 기획합니다.
* **30차시: 프로젝트 회고 결과보고서 및 MoSCoW 로드맵 성과 발표**
  - **지도 요령**: Keep/Problem/Try 회고를 거쳐 Version 2.0 3개월 개발 로드맵 MoSCoW 우선순위를 정리하고 최종 프로젝트 성과를 상호 공유 및 회고합니다.
