# Day 2. Codex Client 기반 불일치 검출, 변경 관리 및 의사결정 추적 교육 요약서

본 요약서는 실제 프로젝트 관리(PM) 핵심 업무인 **불일치 검출 (Task 01)**, **변경사항 관리 (Task 02)**, **의사결정 추적 (Task 03)**을 Codex Client의 프로젝트 Workspace 맥락 추론 기능과 접목하여 학습하는 교육 과정 요약서입니다.

---

## 📌 Part 1. 왜 이 세 가지 업무에 Codex Client인가?

### 1. ChatGPT와 Codex Client의 차이점 (다중 문서 & 이력 추적)
* **일반 ChatGPT (단일 대화)**: 한 번에 한 문서의 파편적 정보만 비교하거나 기억합니다. 여러 개의 파일이 변경되어 관계가 얽힐 때, 이전의 맥락을 잃어버리고 파일마다 모순되거나 누락된 상태로 방치하기 쉽습니다.
* **Codex Client (Workspace 기반)**: 프로젝트 폴더 자체를 인지하므로, 변경 전/후 문서(`requirements-before.md`, `requirements-after.md`), 설계서(`screen-specification.md`), API 규격(`api-specification.md`) 등 여러 파일 간의 정합성을 한 번에 비교합니다. 또한 비정형 대화록에서 완료된 의사결정과 미결 사항을 논리 구조적으로 파싱해 줍니다.

### 2. AI를 검토자(Reviewer)로 활용할 때의 생산성
* **소프트웨어 공학적 예방**: 설계 단계의 오류 수정 비용은 개발 및 테스트가 완료된 상태에서 수정하는 것에 비해 **최대 100배** 저렴합니다.
* **Reviewer로서의 가치**: AI는 사람이 놓치기 쉬운 세부 정책 누락, 엇갈린 변수 매핑(예: 평가 주체 뒤바뀜), 비활성화 규칙 미반영 등을 몇 초 만에 전수 검사하여 커뮤니케이션 오차를 줄이고 재작업을 원천 방지합니다.

## 📌 Part 2. 실습 목표

### 1. 오늘 만들 최종 결과물
* **Task 01**: 3대 기획 문서 간의 모순을 비교한 **불일치 요약 리포트 표**
* **Task 02**: 변경 요건에 따른 화면/API 영향도 및 조치 사항을 정리한 **변경 영향도 분석 표**
* **Task 03**: 미팅 대화록에서 추출한 **의사결정 로그(Decision Log) 표** 및 **미결 사항(Pending Items) 표**

### 2. Input / Output 데이터 파이프라인

```text
===========================================================================================
[Task 01. 불일치 검출]
 - 회의록 (meeting-notes.md)
 - 요구사항 (requirements.md)          ──► (Codex Client) ──►  [💾 Output: 불일치 요약 리포트 표]
 - 화면 정의 (screen-specification.md)
-------------------------------------------------------------------------------------------
[Task 02. 변경사항 관리]
 - 변경 전 요구사항 (before.md)
 - 변경 후 요구사항 (after.md)          ──► (Codex Client) ──►  [💾 Output: 변경 영향도 분석 표]
 - v1.0 화면정의서 & API 명세서
-------------------------------------------------------------------------------------------
[Task 03. 의사결정 추적]
 - 미팅 및 메신저 대화록               ──► (Codex Client) ──►  [💾 Output: 의사결정 로그 & 미결 표]
===========================================================================================
```

## 📌 Part 3. 따라하기 (Codex Client 실제 UI 가이드)

### STEP 1. Task 01 - 불일치 검출
* **행동**: `automation` 프로젝트 폴더 내에 `meeting-notes.md`, `requirements.md`, `screen-specification.md` 파일을 생성한 후 프롬프트 창에 아래 명령을 날려 빌드합니다.
  > "세 문서를 비교하여 서로 다른 내용과 누락된 항목을 표 형태로 정리하고, 개발에 영향을 줄 수 있는 부분을 우선순위별로 표시해줘."
* **확인**: 생성된 결과 표에서 회원 탈퇴 정책 및 별점 평가 주체 오류가 검출되었는지 확인합니다.

### STEP 2. Task 02 - 변경사항 관리
* **행동**: 폴더 내에 `requirements-before.md`, `requirements-after.md`, `screen-specification-v2.md`, `api-specification.md` 파일을 작성한 후 프롬프트 창에 아래 명령을 빌드합니다.
  > "requirements-before.md와 requirements-after.md의 변경점을 분석하고, v1.0 화면 및 API 명세서 파일에서 수정되어야 할 부분을 영향 범위 표 형태로 작성해줘."
* **확인**: Google 소셜 로그인, SMS 인증, Admin 권한 추가가 화면 기획과 API 규격서에 각각 매핑되어 조치 사항이 도출되었는지 확인합니다.

### STEP 3. Task 03 - 의사결정 추적
* **행동**: 폴더 내에 `messenger-chat.md` 파일을 준비한 후 프롬프트 창에 아래 명령을 빌드합니다.
  > "회의록을 분석하여 결정사항, 결정 이유, 미결 사항(Action Item)을 구분하여 Decision Log와 Pending Items 표로 작성해줘."
* **확인**: Apple 로그인 보류 사유와 신용카드 우선 도입 근거가 정확히 기록되었는지 점검합니다.

### Mission 1. 회원가입 변경 영향도 분석 (Task 06)
* **행동**: 휴대폰 인증 추가 변경 요청에 따라 아래 명령을 빌드합니다.
  > "회원가입에 휴대폰 인증 기능이 추가될 경우 영향을 받는 화면, API, DB, 문서를 모두 찾아 영향도 분석 보고서를 작성해 주세요."
* **확인**: 가입 화면 수정(높음), 로그인 API 수정(중간), DB 컬럼 추가(높음), 관리자 화면 조회 항목 추가(낮음) 조치 매핑이 올바르게 요약 보고서로 도출되었는지 확인합니다.

### Mission 2. 프로젝트 이슈 리포트 작성 (Task 07)
* **행동**: 회의록, 변경이력, 이슈 목록 등을 준비한 후 아래 명령을 빌드합니다.
  > "현재 프로젝트의 주요 이슈를 요약하고, 긴급도와 우선순위를 포함한 프로젝트 이슈 리포트를 작성해 주세요."
* **확인**: 로그인(완료), 회원가입(진행/중간), 결제 API 지연(이슈/높음/PM 담당), 요구사항 변경 예정(위험/높음/기획팀), 관리자 권한 정책 확정 필요(미결/중/기획팀)가 긴급도 및 담당자별로 요약되었는지 점검합니다.

## 📌 Part 4. 작동 원리 및 의의

### 1. 의미론적 디프 (Semantic Diff)
* 단순 코드나 텍스트의 라인 비교가 아닌, 기획 요건의 비즈니스 논리(예: 이메일 로그인 ➔ Google 소셜 연동) 변화를 해석하여 하위 시스템에 매핑하는 원리입니다.

### 2. 비정형 대화 내 컨텍스트 캡슐화
* 대화체 흐름 속에서 "촉박한 개발 일정 때문에 보류하자"는 구어체 논쟁에서 '결정 근거(Reasoning Context)'와 '상태(보류/완료)', '담당자' 등의 메타데이터를 정밀 구조화해냅니다.

### 3. 다섯 가지 Task/Mission의 연결 흐름 시너지
```text
[무엇이 달라졌는가?] (Task 01. 불일치 발견)
       │
       ▼
[왜 달라졌고 배경은?] (Task 03. 의사결정 추적)
       │
       ▼
[실제 무엇을 수정해야 하는가?] (Task 02. 변경사항 관리)
       │
       ▼
[아키텍처에 미치는 영향 범위는?] (Mission 1. 영향도 분석)
       │
       ▼
[현재 진행 및 잔존 리스크는?] (Mission 2. 이슈 리포트)
```
이 피드백 루프는 실제 IT 프로젝트 관리에서 산출물 정합성 유지와 리워크(재작업) 방지를 책임지는 핵심 설계 통제 아키텍처가 됩니다.
