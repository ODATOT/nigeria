# Day 05. 서비스 설계 (UI / UX 리뷰)

서비스를 만드는 것은 단순히 예쁜 디자인이나 동작하는 코드를 짜는 것이 아니라 **사용자가 쉽고 편하게 제품을 사용할 수 있도록 논리적으로 설계하는 것**입니다. 아무리 훌륭한 백엔드 API와 DB가 구축되어 있어도, 사용자가 첫 화면에서 어떻게 회원가입을 해야 할지 헤매거나 결제 버튼을 찾지 못한다면 그 서비스는 실패하게 됩니다.

Day 5 실습은 Codex AI를 활용하여 작성된 화면 명세와 흐름을 사용자 중심적(User-Centered)으로 객관적으로 검토하는 데 초점을 맞춥니다. 처음 방문한 사용자 입장에서 사용성이 불편한 영역을 발굴하고(Task 01), 다수의 화면 사이에서 규칙이 깨진 일관성 저해 요소를 적발하며(Task 02), 비즈니스 목표에 도달하기 위한 사용자의 이동 동선(User Journey)을 최적화(Task 03)합니다. 또한 Codex를 가상의 '첫 번째 유저'로 설정하여 페르소나 기반 사용성 리뷰를 진행하고(Mission 01), 종합적인 편의성 평가 매트릭스를 기반으로 UI/UX 품질을 평가(Mission 02)하여 진정한 기획 및 아키텍처 관점의 UI/UX 안목을 갖추는 것을 학습 목표로 합니다.

---

# Task 01. 사용자 관점에서 화면 검토하기 (User Experience Review)

## 1. 스토리 및 실습 배경

스타트업이 오랜 시간 공들여 개발한 모바일 앱을 배포했습니다. 그런데 론칭 당일, 가입자는 늘어나는데 실제 서비스 이용으로 이어지는 수치가 비정상적으로 낮았습니다. 원인을 확인해 보니, 메인 대시보드 화면에 '상담사 찾기' 버튼이 직관적으로 보이지 않고 복잡한 서브 햄버거 메뉴 안에 숨겨져 있어, 사용자들이 첫 화면만 덩그러니 보다가 앱을 종료(이탈)해버린 것이었습니다. 개발자와 디자이너는 자신들이 만든 화면 구조에 너무 익숙해져 있어서 정작 초보 사용자가 느끼는 이러한 불편을 전혀 알아채지 못했던 것입니다.

이번 실습에서는 Codex에게 기획된 예약 프로세스 화면 명세서를 전송하고 가상의 초보 사용자 페르소나 관점에서 화면을 객관적으로 리뷰받아, 기획 단계에서 인지하기 어려운 UX 취약점을 선제적으로 도출하는 방법을 실습합니다.

---

## 2. 학습 목표

* 사용자의 입장에서 화면을 바라보고 정보 배치(Information Hierarchy)의 우선순위를 파악할 수 있다.
* 화면 명세 내에서 사용자를 혼란스럽게 하거나 인지 부하(Cognitive Load)를 주는 요소를 색출할 수 있다.
* AI를 활용하여 객관적인 시선으로 UX 개선 권고사항과 와이어프레임 수정 아이디어를 도출할 수 있다.

---

## 3. 실습 미션

학습자는 로컬 프로젝트 폴더 내에 `day5_signup_flow.md`를 준비하고 Codex Client에 아래 프롬프트를 전송하여 사용자 관점의 화면 검토 보고서를 작성합니다.

> "제공된 예약 신청 상세 폼의 화면 명세를 기반으로, 서비스를 처음 접하는 초보 사용자의 입장에서 정보 구조가 명확한지 검토하고 사용성 저해 요소를 지목하여 개선 제안 보고서(UX Review Report)를 작성해 주세요."

---

## 4. 결과물 예시

Codex는 화면 명세를 다각도로 심사하여 아래와 같이 체계적인 검토 보고서를 작성합니다.

### UX Review Report (사용자 관점 검토서)

| 검토 영역 | 사용성 저해 요소 (불편 지점) | 사용자에게 미치는 영향 | 권장 개선 방안 |
|---|---|---|---|
| **상담사 프로필 영역** | 전문가 평점(별점) 및 한줄 소개가 최하단 스크롤 영역에 위치함. | 상담사를 신뢰하기 위한 정보 인지가 늦어져 선택을 망설임. | 카드 최상단 닉네임 우측에 별점과 한줄 소개를 배치하여 첫 시선에 노출. |
| **시간 슬롯 선택** | 이미 예약 완료된 비활성화 시간대와 선택 가능한 활성화 시간대의 시각적 대비(명도 대비)가 모호함. | 마감된 슬롯을 중복 클릭하며 에러 팝업을 겪어 불쾌감을 유발함. | 비활성화 슬롯은 회색(Muted Gray)으로 아웃라인 처리하고 텍스트에 취소선 적용. |
| **결제 유도** | 하단 '예약 요청하기' 버튼 클릭 시 상세 예약 요금 정보가 팝업으로 가려진 후 결제 화면으로 넘어감. | 최종 청구 금액을 사전에 직관적으로 인지하지 못해 결제 단계에서 이탈함. | 버튼 상단에 '최종 결제 예상 금액'을 상시 폰트로 명시하는 레이아웃 고정. |

---

## 5. AI 활용 포인트

* **인지 부하 추정**: 화면의 복잡도와 필수 정보들의 시각적 인지 계층 구조를 계산하여 중요 정보의 누락 및 역배치 적발.
* **UX 휴리스틱 평가**: 제이콥 닐슨의 10대 사용성 휴리스틱을 기반으로 시스템 상태 표기 및 사용자 자유도 부합 여부 교차 매핑.

---

## 6. 학습 포인트

코드가 문제없이 돌아간다고 해서 설계가 끝난 것은 아닙니다. AI 비서를 활용하여 개발 주체(기획/개발팀)의 주관적 아집에서 벗어나 철저히 타자(사용자)의 시선에서 제품의 사용 편의성을 객관화하는 피드백 루프를 만드는 것이 진정한 설계 검증의 핵심입니다.

# Task 02. 화면의 일관성 검토하기 (Screen Consistency Review)

## 1. 스토리 및 실습 배경

제품 론칭을 앞두고 다수의 화면을 기획자와 퍼블리셔들이 나누어 코딩하다 보니 일관성이 깨지기 시작했습니다. 어떤 화면에서는 '저장하기' 버튼이 우측 하단에 파란색으로 배치되어 있는데, 다른 화면에서는 '등록하기'라는 명칭으로 좌측 상단에 초록색 버튼으로 디자인되어 있었습니다. 또한 동일한 회원 상태를 뜻하는 용어가 어떤 페이지에서는 '회원 활성상태', 다른 페이지에서는 '사용 여부'로 제각각 사용되어 사용자가 길을 잃게 만들었습니다.

화면의 레이아웃과 톤앤매너, 용어의 일관성이 깨지면 사용자들은 제품을 사용할 때마다 새로운 사용법을 학습해야 하는 심한 스트레스를 겪게 됩니다. 이번 실습에서는 Codex를 활용하여 개별 기획된 여러 화면 기획 문서를 한눈에 비교 분석하고 일관성(Consistency)이 무너진 구조, 단어, 디자인 규칙을 찾아 공통 UI 규칙 제안서를 빌드하는 방법을 학습합니다.

---

## 2. 학습 목표

* 여러 화면 기획 문서 간의 레이아웃 구도 및 공통 기능의 단어 불일치를 잡아낼 수 있다.
* 일관성 없는 버튼, 메뉴, 피드백 상태 명세를 발견하여 개선 리스트로 축적할 수 있다.
* AI와 함께 프로젝트 전체에 적용할 표준 UI/UX 가이드라인 초안을 제안할 수 있다.

---

## 3. 실습 미션

학습자는 여러 화면 명세가 포함된 자료를 로컬에 배치하고 Codex Client에 일관성 검사를 요구합니다.

> "제공된 day5_signup_flow.md의 각 화면 설계 내역들을 서로 대조하여, 버튼의 배치 규칙, 사용 용어, 피드백 메시지의 일관성이 결여된 요소를 분석해 화면 비교 보고서를 작성해 주세요."

---

## 4. 결과물 예시

### UI 일관성 개선 리포트

#### 1. 명칭 및 용어 불일치
- **가입 화면**: 사용자 식별자를 `'아이디'`로 표기함.
- **예약 신청 폼**: 사용자 식별자를 `'고객 ID'`로 표기함.
- **조치 사항**: 모든 대고객 UI 및 명세는 `'아이디(ID)'`로 용어를 단일 표준화할 것.

#### 2. 액션 버튼 디자인 규칙 위배
- **로그인 페이지**: 하단 전체 너비로 `'로그인'` 파란색 메인 버튼 배치.
- **회원 정보 개정 페이지**: 우측 상단 소형 버튼으로 `'수정 완료'` 초록색 배치.
- **조치 사항**: 메인 액션 버튼은 하단 100% 너비의 프라이머리 컬러(`--primary`)를 일괄 적용하도록 CSS 클래스 고정.

## 5. AI 활용 포인트

* **다중 화면 교차 대조**: 여러 화면 설계 템플릿의 문장을 텍스트 마이닝하여 유사 동작을 가진 버튼 및 라벨의 불일치 단어 클러스터링.
* **표준 디자인 시스템 추천**: 글로벌 디자인 가이드(Material Design, Human Interface Guidelines)를 참조한 일관성 정렬 템플릿 설계.

# Task 03. 사용자 동선 개선하기 (User Journey Review)

## 1. 스토리 및 실습 배경

제품이 완성되고 결제 전환율을 분석해 본 결과 참담했습니다. 가입자들이 예약 버튼을 누른 후 결제에 골인하는 비율이 고작 5%에 머문 것입니다. 왜 사용자들이 예약을 포기하는지 확인해 보니 동선(User Journey)이 너무나 길고 지루했습니다. [전문가 선택 ➔ 상세 소개 확인 ➔ 예약일 선택 ➔ 예약 시간 슬롯 선택 ➔ 개인 정보 수집 동의 ➔ 환불 규정 확인 ➔ 결제 정보 입력 ➔ 카드 번호 기입 ➔ 예약 확인 완료]까지 클릭을 무려 9번이나 해야 했습니다. 

사용자는 원하는 목적(상담 예약)을 완료하기 위해 거쳐야 하는 화면 이동과 클릭 횟수가 늘어날 때마다 지쳐서 앱을 꺼버립니다. 

이번 실습에서는 Codex의 강력한 플로우 추론 능력을 가동하여 사용자가 앱에 진입해 최종 결제를 마치기까지의 동선 흐름(User Journey)을 단계별로 파악하고, 불필요하게 파편화된 화면과 중복 입력 요구사항을 합치거나 간소화하여 사용자 클릭을 반으로 줄이는 최적의 동선 설계법을 학습합니다.

---

## 2. 학습 목표

* 사용자의 시나리오 이동 흐름을 다이어그램 및 시퀀스로 정의할 수 있다.
* 사용자가 목적지에 도달하기까지 병목(Friction)을 일으키는 중복 동의 및 입력 단계를 발굴할 수 있다.
* AI의 도식 제안을 통해 사용성을 향상할 수 있는 컴팩트한 동선 개선안을 기획할 수 있다.

---

## 3. 실습 미션

학습자는 사용자 시나리오 명세를 Codex Client에 전송하여 경로 최적화 제안을 생성합니다.

> "제공된 day5_signup_flow.md의 예약 상세 시나리오 동선을 분석하여, 사용자가 상담 예약을 완료하기까지의 클릭 단계와 화면 이동을 최소화할 수 있는 사용자 동선 개선 보고서(User Journey Report)를 작성해 주세요."

---

## 4. 결과물 예시

### User Journey 개선 보고서

#### [AS-IS 동선 흐름 (9단계)]
```text
상담사 목록 ➔ 상세 정보 보기 ➔ 예약일 선택 ➔ 시간 선택 ➔ 정보 입력 ➔ 환불 동의 ➔ 결제 수단 선택 ➔ 결제 승인 ➔ 완료
```

#### [TO-BE 개선 동선 흐름 (4단계 - 50% 단축)]
```text
상담사 목록 ➔ 상세/예약 캘린더 통합 페이지 ➔ 간편 동의 및 간편결제 ➔ 완료
```

#### [주요 개선 내용]
1. **화면 통합**: '상세 정보 보기' 하단에 '예약 캘린더와 시간 슬롯'을 탭/팝업이 아닌 한 화면의 아코디언 컴포넌트로 통합 배치하여 2단계 축소.
2. **동의 절차 간소화**: 예약하기 버튼 클릭 시 모달 팝업 안에서 개인 정보 및 환불 약관 동의를 한꺼번에 체크박스로 처리하여 단독 화면 이동 스텝 제거.

---

## 5. AI 활용 포인트

* **태스크 마찰(Friction) 측정**: 사용자 행동 기반의 클릭 뎁스(Depth)와 주의력 분산 요소를 정량화하여 간소화 타겟 영역 자동 도출.
* **사용성 대안 흐름 생성**: 다양한 커머스/예약 플랫폼의 모범 간편결제 설계 패턴을 분석해 대체 흐름(Alternative Flow) 제안.

# Mission 01. 처음 사용하는 사용자 되어보기

## 1. 스토리 및 실습 배경

제품 개발자들은 자기가 짠 프로그램에 지독한 확증 편향을 갖게 됩니다. "이 정도는 당연히 우측 상단을 누르면 되는 거 아닌가?", "비밀번호 규칙은 최소 12자에 대소문자와 특수기호를 섞는 게 요즘 트렌드 아닌가?" 같은 생각을 주저 없이 적용합니다. 하지만 디지털 기기에 익숙하지 않은 중장년층 사용자나, 단 5초의 여유도 없이 바쁘게 상담을 요청하려는 사용자가 이 앱을 켜면, 비밀번호 가입 에러가 3번 반복되는 순간 화를 내며 앱을 지워버립니다.

이번 미션에서는 Codex Client에게 **"이 상담 앱을 처음 다운로드받고 실행해 본 50대 개인 상담 고객"**이라는 페르소나(Persona)를 부여합니다. 그리고 이 가상의 초보 사용자가 회원가입부터 전문가 선택, 예약 시도 과정에서 겪는 생생한 첫인상 피드백과 당혹스러운 불편 사항 목록을 자율 발굴해내는 AI 페르소나 리서치 기법을 연마합니다.

---

## 2. 실습 미션

학습자는 Codex Client의 시스템 프롬프트 또는 메인 대화창에 사용자 페르소나 조건을 아래와 같이 주입하고 사용성 리뷰를 요청합니다.

> "당신은 디지털 스마트폰 앱 사용이 다소 서툰 50대 자영업자입니다. 제공된 day5_signup_flow.md 명세서에 작성된 회원가입 및 첫 화면 UI 명세를 보면서, 당신의 입장에서 가입 시 무엇이 가장 헷갈리고 어려운지 감정적인 반응과 개선 요구사항을 적어주세요."

---

## 3. 결과물 예시

### AI 가상 유저 페르소나 리뷰 보고서

* **리뷰어 페르소나**: 53세 개인 사업자 (스마트폰 메신저와 유튜브만 주로 사용함)
* **생생한 사용자 첫인상 & 곤경 리스트**:
  1. *아이디 중복확인 혼선*: "아이디를 입력하고 그냥 다음으로 넘어갔는데, 중복체크 버튼을 꼭 따로 눌러야 진행이 된다고 에러 창이 뜬다. 왜 입력창 아래에 실시간으로 '사용 가능'이라고 미리 써주지 않는지 번거롭다."
  2. *글자 크기 인지 문제*: "캘린더 요일 아래에 오전/오후 시간대 글자가 너무 작고 촘촘하게 박혀 있어서 돋보기를 쓰지 않고는 내가 2시를 눌렀는지 3시를 눌렀는지 확인하기 어렵다."
  3. *뒤로 가기 시 데이터 리셋*: "시간을 잘못 골라 뒤로 가기를 눌렀더니, 앞에서 열심히 입력한 이름과 연락처 정보가 싹 다 날아가서 처음부터 다시 써야 하니 혈압이 오른다."

---

## 4. AI 활용 포인트

* **페르소나 감정이입 검증**: 특정 연령대, 숙련도, 기기 환경을 모사하여 제품 개발자가 스스로 인지할 수 없는 행동 장벽(Behavioral Barrier) 재현.
* **마이크로 카피(Microcopy) 피드백**: 딱딱한 에러 메시지(예: `ERR_DUPLICATE_ID`)를 친절한 안내 문구로 교체할 포인트 자율 도출.

# Mission 02. AI와 함께 서비스 품질 평가하기

## 1. 스토리 및 실습 배경

제품 배포 전, 대기업 기획 부서에서는 오랜 시간과 막대한 비용을 들여 UX 전문 평가단(FGI - Focus Group Interview)을 구성해 사용성 테스트를 진행하고 평가서를 작성합니다. 하지만 소규모 스타트업이나 1인 개발자는 이러한 전문적인 UX 평가 인프라를 운영할 여력이 없어, 감에 의존해 제품을 출시했다가 처참한 품질 실패를 겪곤 합니다.

이번 미션에서는 국제 사용성 표준 품질 기준을 탑재한 전문 UX 컨설턴트로 Codex를 세팅합니다. 그리고 기획서 내 모든 화면 기획의 완성도를 이해성, 접근성, 조작 편의성, 불필요 스텝 존재 여부 등의 전문적인 항목으로 수치 평가(Usability Scoring)를 매기고, 평점 9.0 이상의 명품 UI/UX로 올라서기 위한 고품격 로드맵 평가서를 빌드하는 종합 실습을 진행합니다.

---

## 2. 실습 미션

학습자는 전체 기획 스펙 데이터 목록을 첨부하고 아래 표준 사용성 평가 프롬프트를 빌드합니다.

> "제공된 day5_signup_flow.md 스펙을 기반으로, 1) 정보 가독성, 2) 조작 접근성, 3) 에러 회복성, 4) 동선 효율성 등의 항목에 대해 각각 5점 만점의 점수를 매기고, 종합 평가 점수와 함께 장점 및 뼈아픈 개선점을 지목하는 서비스 품질 평가서(Usability Evaluation)를 빌드해 주세요."

---

## 3. 결과물 예시

### Usability Evaluation (서비스 품질 평가서)

#### 1. 영역별 평가 점수
* **정보 가독성**: 3.5 / 5.0 (전문가 태그 정보는 유용하나 정보 밀도가 너무 높음)
* **조작 접근성**: 3.0 / 5.0 (결제 금액 표시가 결제 팝업 안에 숨겨져 조작 직관성 부족)
* **에러 회복성**: 2.5 / 5.0 (뒤로 가기나 유효성 검사 실패 시 모든 기존 텍스트 입력값이 초기화됨)
* **동선 효율성**: 2.0 / 5.0 (가입부터 완료까지 총 9단계로, 전형적인 이탈 유발형 아웃풋 구조)

* **종합 사용성 평점: 2.75 / 5.0 (개선 필수 단계)**

#### 2. 핵심 개선 액션 플랜
* 입력 에러 시 입력 내용을 메모리 상태(Local Storage)에 임시 보존하도록 로직 수정.
* 가입 폼과 예약 시간 슬롯을 슬라이드식 멀티스텝 형태로 일관되게 구조화하여 인지 단계 간소화.

---

## 4. AI 활용 포인트

* **UX 매트릭스 수치화**: 주관적일 수 있는 UI/UX 의견을 정합성 점수(Metrics Score)로 환산하여 개선 우선순위를 수치로 가시화.
* **글로벌 UX 패턴 처방**: 피드백 루프, 사용성 한계치 극복을 위해 바로 사용할 수 있는 UI 컴포넌트 패턴(예: Autofill, Session Save) 권고.

# Day 05 실습용 원본 파일 데이터 내역

## 📄 day5_signup_flow.md
```markdown
# 상담 매칭 서비스 전체 화면 설계 명세서 (v1.0)

## 화면 1: 로그인 및 회원가입 페이지 (LOGIN-001)
* **UI 레이아웃**:
  - 최상단: 로고 이미지
  - 입력창 1: '아이디' 입력란
  - 입력창 2: '비밀번호' 입력란 (규칙 안내 문구 없음)
  - 버튼: '로그인' 버튼 (하단 100% 너비, 파란색)
  - 링크: '처음이신가요? 가입하기'
* **회원가입 모달**:
  - '가입하기' 링크 클릭 시 화면 전체를 가리는 모달 팝업 노출.
  - 입력 요소: 이름, 전화번호, 이메일, 아이디(중복확인 버튼 필수 클릭), 비밀번호.
  - 모달 내 '완료' 버튼: 우측 상단 소형 버튼으로 배치 (초록색).
  - 유효성 오류: 비밀번호가 12자 미만이거나 특수기호가 빠질 경우 에러 창("비밀번호 규칙 위반!")을 띄우고 모달을 강제 닫음 (작성하던 모든 글자는 전부 날아가고 다시 가입하기 모달을 열어야 함).

## 화면 2: 전문가 목록 및 매칭 카드 (EXPERT-LIST)
* **UI 레이아웃**:
  - 캘린더 요일 아래에 오전/오후 시간대 글자가 매우 조밀하게 10px 크기로 박혀 있음.
  - 카드 표기 요소: 전문가 이름, 카테고리 태그.
  - 카드 최하단 스크롤을 끝까지 내려야만 별점(평점)과 한줄 소개가 작게 노출됨.
  - 비활성화된 예약 불가 시간대 슬롯과 예약 가능한 슬롯의 아웃라인 두께가 거의 유사하여 언뜻 보기에 구분이 안 됨.

## 화면 3: 상세 예약 신청 및 결제 유도 (BOOKING-PAY)
* **사용자 이동 동선 (User Journey) 명세**:
  1단계: 상담사 목록에서 마음에 드는 상담사 클릭
  2단계: 상세 프로필 상세 보기 페이지로 이동
  3단계: 하단 '상담 예약' 버튼 클릭하여 예약 캘린더 이동
  4단계: 날짜 선택
  5단계: 마음에 드는 시간대 선택
  6단계: '예약 요청' 버튼 클릭시 개인 정보 수집 동의 체크 화면으로 단독 이동
  7단계: 동의 후 환불 규정 상세 안내 동의 화면으로 또 이동
  8단계: 동의 버튼 클릭 시 결제 수단 선택용 레이어 팝업 노출
  9단계: 최종 신용카드 번호 수동 입력 완료 후 최종 완료 페이지 토스트 노출
* **결제 예외 상황**:
  - 사용자는 8단계 결제 수단 선택 팝업이 노출되기 직전까지 최종 결제 금액이 얼마인지 화면 상에서 상시 확인이 불가함 (8단계 팝업을 띄워야만 비로소 쿠폰 미적용 금액이 노출됨).
```
