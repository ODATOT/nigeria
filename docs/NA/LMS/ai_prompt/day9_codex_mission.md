# Day 09. 결제 서비스 설계하기 (Payment Service)

결제 기능은 웹/앱 서비스에서 비즈니스의 수익이 발생하고 거래가 완결되는 최종적이고 가장 임계적인 단계(Critical Path)입니다. 하지만 많은 개발 입문 교육에서는 토스페이먼츠나 포트원(PortOne) 등 외부 전자결제대행사(PG)의 연동 소스코드를 가져와 단순히 '결제창 띄우기'와 '승인 API 호출'을 기계적으로 성공시키는 데에만 초점을 맞춥니다. 정작 실제 서비스 운영에서 매출에 직격타를 주는 **"결제 도중 불안감을 느낀 사용자의 이탈"**이나 **"승인 실패 시 뚱딴지같은 영어 오류코드를 보고 좌절하는 사용자 불만"** 등의 현실적인 결제 여정(Checkout Journey)의 문제를 놓치게 됩니다.

Day 9 과정은 결제 API를 복사-붙여넣기 하는 코딩 날이 아니라, **"사용자가 마지막 단계에서 한 치의 망설임과 불안감 없이 안심하고 지갑을 열어 돈을 지불할 수 있도록 결제 경험과 신뢰도를 AI와 함께 오디팅하는 날"**입니다. 상품 선택 후 최종 결제완료까지 이어지는 불필요한 단계를 제거하여 동선을 최적화하고(Task 01), 카드 한도 초과나 통신 두절 등 실무에서 빈번히 생기는 실패 상황을 꼼꼼하게 채집하여 회복 방안을 마련하며(Task 02), 보안 배지와 가격 상세 표기를 보완해 결제 신뢰를 향상(Task 03)시키는 실습을 진행합니다.

학습자는 Codex AI를 철저한 블랙박스 테스트 파트너 및 안심 결제 컨설턴트로 활용하여 예기치 못한 실패 안내 문구를 수립하고(Mission 01), 결제 단계별 이탈 유발 구간을 분석하여 우선 개선안을 도출하는(Mission 02) 협업 루틴을 익히게 됩니다. 이 과정은 기술 지식이 부족한 비기획자, 디자이너, 비개발자들도 결제 서비스 설계의 핵심 장벽과 신뢰 보완 방안을 온전히 공감하고 기획할 수 있도록 돕는 실전형 가이드라인을 제공합니다.

# Task 01. 결제 흐름 설계하기 (Payment Flow Planning)

## 1. 스토리 및 실습 배경

한 크라우드 펀딩 플랫폼 스타트업이 야심 차게 런칭했으나, '장바구니'에 상품을 담은 고객 중 15%만 최종 결제에 도달하고 나머지 85%는 결제 도중 이탈하는 엄청난 위기를 겪고 있습니다. 가입부터 결제까지의 동선을 점검해보니 상품 상세 정보 ➔ 옵션 선택 ➔ 주문서 작성 ➔ 약관 동의 ➔ 배송지 입력 ➔ 결제 수단 선택 ➔ 휴대폰 본인 인증 ➔ PG사 앱 실행 ➔ 결제 완료 등 무려 9단계가 넘는 과정이 꼬리를 물고 있었고, 그 사이 모바일 화면에서는 로딩이 지연되거나 불필요한 팝업이 뜨며 사용자의 구매 욕구를 완전히 꺾어버렸습니다.

사용자가 지출을 결심하는 순간의 동선은 1초라도 단절감이 없어야 합니다. 이번 실습에서는 Codex AI에게 현재 가상 서비스의 결제 동선 명세를 건네주고, 불필요한 중간 페이지와 승인 확인 팝업을 과감히 도려내어 '단 3단계'만으로 지불을 완료시키는 궁극의 간소화된 결제 여정 모델(Optimized Payment Flow)을 설계합니다.

---

## 2. 학습 목표

* 상품 선택부터 주문서 작성, 최종 승인에 이르는 결제 프로세스를 단계별로 도식화할 수 있다.
* 결제 여정 내 불필요한 확인 절차나 페이지 이동을 식별하고 사용자 마찰을 최소화할 수 있다.
* AI의 여정 간소화 소견을 반영하여 매끄럽고 빠른 UX 결제 동선 설계서를 획득할 수 있다.

---

## 3. 실습 미션

학습자는 현재 결제 동선이 구질구질하게 기술된 `day9_current_checkout_flow.md` 파일을 작성해 두고, Codex Client에게 단선화 설계를 의뢰합니다.

> "현재의 다단계 결제 동선(`day9_current_checkout_flow.md`)을 읽고, 유저가 결제를 누르기 전에 피로감을 느껴 도망칠 법한 장벽 2가지를 찾아주세요. 그리고 이메일 가입 유저가 가장 빠르게 구매에 골인하도록 불필요한 단계를 병합해 3단계 이하로 축약한 개선 결제 유저 플로우(TO-BE Flow)를 도출해 주세요."

---

## 4. 결과물 예시

Codex는 여정을 오디팅하여 축약된 시나리오와 단계 정의서를 전달합니다.

### 1) 개선된 결제 단계 정의 (Optimized TO-BE Flow)
* **1단계: 결제 예정 정보 및 배송지 자동 로드 (Single Page)**
  - 가입 시 저장된 배송지를 기본 노출하여 새로 적는 수고 제거.
* **2단계: 원클릭 결제 방식 선택 및 약관 통합 동의 (Checkout Overlay)**
  - 별도 페이지로 가던 수단 선택과 전체 동의를 한 오버레이 창에 통합.
* **3단계: PG 간편 결제 호출 및 완료 리디렉션 (Confirmation)**
  - 승인 후 중간 대기 없이 즉시 완료 대시보드로 이동.

### 2) 이탈 장벽 진단
- **휴대폰 본인 인증의 중복 요구**: 이미 로그인한 회원인데 결제 시 본인인증 팝업을 추가 호출하여 가입 탈출 요인 제공.
- **주소 찾기 입력 불편**: 우편번호 창이 모바일에서 이탈하는 인팝 브라우저를 띄워 뒤로가기 시 폼이 유실되는 중대 결함 식별.

---

## 5. AI 활용 포인트

* **동선 병합 자동화**: 여러 페이지로 흩어져 있는 '배송지 입력', '포인트 사용', '쿠폰 적용'을 한 장의 '주문/결제 요약 시트'로 병합하는 컴팩트한 화면 병합 설계 아이디어를 도출합니다.
* **이탈 리스크 정량 진사**: 모바일 기기 기준 각 추가 입력란마다 결제 포기율이 어떻게 상승하는지 유저 심리 관점에서 근거를 제시합니다.

---

## 6. 학습 포인트

결제 설계의 핵심은 **"지갑을 열게 만들었으면 딴생각을 할 틈을 주지 않고 최단거리로 처리하는 것"**입니다. 기술적 세부사항을 생각하기에 앞서 고객의 마찰 요인을 발굴하고 제거하는 직관적인 기획 설계법을 체득합니다.

# Task 02. 결제 실패 시나리오 검토하기 (Payment Exception Review)

## 1. 스토리 및 실습 배경

신나게 쇼핑몰에서 물건을 사고 신용카드 결제 버튼을 눌렀는데, 한참 로딩이 돌더니 화면에 뜬금없이 `Error 1042: System Transaction Declined by External Carrier`라는 영어 경고창만 덜렁 뜨고 멈췄습니다. 고객센터에는 "돈이 빠져나간 건가요?", "결제가 안 된 건가요?", "다시 결제하면 이중 청구되나요?"라는 사용자들의 다급한 항의 전화가 빗발쳤습니다. 확인해보니 단지 사용자의 한도초과였는데, 백엔드가 PG사 반환 오류코드를 필터 없이 날것 그대로 화면에 출력한 탓이었습니다.

결제 승인 오류는 아주 흔하게 발생합니다. 중요한 것은 **사용자가 오류를 만났을 때, 무엇이 잘못되었고 어떻게 행동해야 돈이 두 번 빠져나가지 않는지 안심하고 이해할 수 있도록 명확한 예외 피드백을 전달하는 것**입니다. 이번 실습에서는 Codex AI를 실패 코치로 기용하여 카드 한도초과, 네트워크 시간초과, 잔액부족, 중복 결제 요청 등의 4대 예외 상황을 도출하고, 이에 걸맞은 안심 오류 대응 안내서(Error Mitigation Guide)를 조립합니다.

---

## 2. 학습 목표

* 결제 연동 과정에서 벌어지는 4가지 이상의 대표적 예외 및 실패 유형을 설명할 수 있다.
* 기술적인 원시 오류 코드를 사용자 친화적이고 행동 지침이 포함된 언어로 변환할 수 있다.
* 중복 결제와 같이 자산 위협이 큰 예외를 인지 마찰 없이 수습하는 안내 시나리오를 구성할 수 있다.

---

## 3. 실습 미션

학습자는 PG사의 원시 실패 로그 포맷인 `day9_raw_payment_errors.json`을 모의 작성하고, Codex Client에게 변환 안내서 구축을 지시합니다.

> "제공된 PG사 원시 오류 로그 명세 `day9_raw_payment_errors.json`를 기반으로, 사용자에게 절대로 불안감을 주지 않는 친절한 '오류 상황별 한글 안내 문구집'과 중복 결제 시도를 차단하는 '이중 승인 예방 대응 가이드라인(Mitigation Playbook)'을 작성해 주세요."

---

## 4. 결과물 예시

Codex는 오류 코드를 분석해 매끄러운 수습 메시지와 대응 룰을 반환합니다.

### 1) 사용자 안심 오류 메시지 변안 (Actionable Error Copy)
| 원시 오류 코드 | 발생 원인 | 유저 화면 노출 문구 (TO-BE) |
|---|---|---|
| `ERR_CARD_LIMIT_EXCEEDED` | 한도 초과 | "선택하신 카드의 결제 한도가 초과되었습니다. 다른 카드를 사용하시거나 한도를 증액하신 후 다시 시도해 주세요. (결제는 취소되었습니다.)" |
| `ERR_NETWORK_TIMEOUT` | 통신 지연 | "결제 대행사와의 통신이 지연되고 있습니다. 현재 통장이나 카드에서 돈이 출금되지 않았으니 안심하시고 다시 시도해 주세요." |
| `ERR_DUPLICATE_REQUEST` | 연타/중복 | "현재 동일한 주문이 처리 중입니다. 중복 결제 방지를 위해 잠시만 대기해 주세요. 승인 여부는 주문 내역에서 즉시 확인 가능합니다." |

### 2) 이중 승인 예방 가이드
- **중복 전송 차단 (Debounce Lock)**: 결제 요청 클릭 즉시 버튼을 `disabled` 처리하고 대기 스피너 구동.
- **클라이언트 주문 토큰 발급**: 주문서 생성 시 UUID `orderToken`을 부여하여 동일 토큰의 이중 처리를 원천 차단.

---

## 5. AI 활용 포인트

* **불안감 완화 카피라이팅**: "이중 과금되지 않았으니 안심하세요"처럼 금융 불안을 잠재우는 최적의 문장 구조를 교정해 줍니다.
* **과도한 안내 교정**: 오류 원인이 서버 결함일 때 무작위로 상세 원인을 보여주는 것은 해킹 타깃이 되므로, 적절한 공통 에러 안내로 캡슐화해 줍니다.

---

## 6. 학습 포인트

돈이 걸린 상황에서 가장 위험한 것은 **"사용자에게 침묵하거나, 전문 용어로 겁을 주는 것"**입니다. AI 비서와 협업하여 신뢰도 높은 친절한 에러 문구와 안전한 클라이언트 락 장치를 조립하여 제품 완성도를 높입니다.

# Task 03. 결제 경험 개선하기 (Payment Experience Review)

## 1. 스토리 및 실습 배경

결제 성공도 아주 잘 되고, 오류 대책도 다 갖춘 플랫폼인데 이상하게 마지막 결제 수단 선택 화면에서 사용자들이 한참 망설이다가 이탈해 버렸습니다. 화면을 분석해 보니 흰 바탕에 검은색으로 '가입금액 50,000원'과 투박한 '결제하기' 버튼만 놓여 있었을 뿐, 회사가 안전한 결제 보안 라이선스를 가졌는지, 부가세가 포함된 총 지불액이 맞는지, 환불 및 취소 규정은 어떻게 되는지에 대한 안내가 완전히 누락되어 있었습니다. 사용자 입장에서는 마치 피싱 사이트에 접속해 카드 번호를 강탈당하는 느낌을 받았던 것입니다.

결제 화면의 미세한 심리적 요인은 실제 구매 전환율에 결정적인 영향을 줍니다. 이번 실습에서는 Codex AI를 금융 사용성 평가 위원으로 삼아, 최종 결제 승인 화면 기획안 `day9_payment_ui.html`을 평가하고, 신뢰성 배지 배치, 최종 혜택가 상세 상세 분리, 환불 규정 앵커 링크 연결 등 구매율을 2배 이상 끌어올리는 결제 신뢰 보완 보고서(Payment Experience Report)를 조립합니다.

---

## 2. 학습 목표

* 사용자가 안 안심하고 결제할 수 있도록 신뢰를 부여하는 3가지 요소(보안배지, 환불 안내 등)를 말할 수 있다.
* 결제 요약 화면에 들어가는 정보(총 결제액, 세부 할인, 수수료)를 누락 없이 배치할 수 있다.
* AI의 UI 개선안 피드백을 적용하여 결제율을 높이는 사용자 중심 결제 UX 기안을 획득할 수 있다.

---

## 3. 실습 미션

학습자는 기획 중인 결제 최종 확인 페이지 UI 레이아웃 사양인 `day9_payment_ui.html`을 제출하고 Codex Client에 UX 평가를 의뢰합니다.

> "제공된 `day9_payment_ui.html` 결제 UI 레이아웃의 사용성 및 신뢰도를 검토해 주세요. 사용자가 정보 불투명성으로 인해 불안을 느낄 만한 곳을 찾고, 1) 가격 세부 할인 영수증식 분리 표시, 2) 24시간 안심 결제 보안 문구 배치, 3) 간편 취소/환불 링크 처방이 보완된 최종 CSS/HTML 구조를 도출해 주세요."

---

# Mission 01. 결제 실패 상황 대응하기 (Handling Payment Failures)

## 1. 미션 개요

실제 모바일 네트워크 환경이나 간편 페이 앱 미설치, 한도 초과 등 실무에서 발생하는 예외 상황을 Codex의 시뮬레이션을 통해 점검하고, 사용자 관점에서 돈이 증발했다는 오해를 방지하는 행동형 결제 취소 및 재도전 에러 가이드라인 명세(`day9_failure_scenarios.md`)를 작성합니다.

---

## 2. 세부 수행 과제

1. **에러 매핑 시나리오 요청**: 결제 도중 PG창 폐쇄, 은행 점검 시간, 한도 초과 발생 시나리오 3개를 Codex Client에 던져 불안 점수를 평가받습니다.
2. **불안 완화 메시지 수립**: 사용자가 결제를 포기하고 항의 전화로 이어지지 않게 "어떤 금액도 승인되지 않았습니다. 현재 은행 점검 시간(23:55~00:05)이오니 다른 결제 수단을 고르시거나 잠시 후 시도해 주세요" 같은 행동 솔루션이 포함된 텍스트 카피를 마련합니다.
3. **대응 절차 테이블 구축**: 실패 원인 ➔ 유저 반응 ➔ 안내 메시지 ➔ 사후 취소 및 재결제 유도 단계를 연결해 일원화된 문구집을 마련합니다.
4. **산출물 보관**: 완성된 오류 예방 명세서를 `day9_failure_scenarios.md` 파일로 저장합니다.

# Mission 02. 구매 완료까지 직접 점검하기 (Checkout Journey Audit)

## 1. 미션 개요

최종적으로 다듬어진 가상 결제 요약 화면 및 API 연동 동선을 켜두고, 상품 선택 ➔ 장바구니 ➔ 주문서 작성 ➔ PG 결제창 호출 ➔ 승인 처리 ➔ 완료 페이지로 이어지는 고객 여정 지도(Customer Journey Map) 전체를 모의 실행하며 이탈이 극심할 지점을 분석해 우선 개선 순위 보고서(`day9_checkout_journey.md`)를 작성합니다.

---

## 2. 세부 수행 과제

1. **여정 단계 지도 획득**: Codex에게 전체 결제 단계를 기재한 코드를 제출하고, 사용자가 구매의 심리적 결정을 철회할 리스크가 극에 달하는 마찰 피크(Friction Peak) 지점 2곳을 특정하도록 의뢰합니다.
2. **이탈 유발 사유 규명**: 예컨대 "결제 수단 선택 시, 신용카드 아이콘의 미려한 로고가 없어 회사의 영세함에 불안을 느끼는 지점" 등 사소하지만 심리적으로 치명적인 곤경 구간을 도출합니다.
3. **개선 우선순위 배정**: 즉각 수리가 가능한 '보안 배지 배치' 및 '영수증 텍스트 폰트 크기 증대' 등을 우선순위 A로 할당하고 중장기 PG 계약 변경을 B로 배정하는 조치를 내립니다.
4. **산출물 보관**: 정리된 오디팅 보고서를 `day9_checkout_journey.md` 파일로 저장합니다.

```markdown
# [Day 9] 고객 결제 여정 사용성 진단서

## 1. 결제 여정 마찰 피크 (Friction Peaks)
* **피크 1: 주문 정보 작성 페이지 (마찰도: High)**
  - 이유: 쿠폰을 찾기 위해 현재 페이지를 나가면 기존에 작성했던 배송지 데이터가 다 날아가는 구조적 절망 존재.
* **피크 2: 최종 결제 승인 오버레이 (마찰도: Medium)**
  - 이유: 환불 절차와 기한에 관한 설명이 누락되어 결제를 누르기 직전 지불을 취소하는 사유 유발.

## 2. 개선 조치 우선순위 (TO-BE Remediation)
- **우선순위 1 (즉시 적용):** 결제 팝업창 하단에 "결제 완료 후 마이페이지에서 즉시 원클릭 취소/환불 가능" 굵은 텍스트 추가.
- **우선순위 2 (개발 패치):** 쿠폰 조회 모달 실행 시, 기존 배송지 필드 상태를 로컬 세션에 임시 동기화해 폼 초기화 차단.
```
