# Day 05 교육 내용 요약서 (Codex AI Workspace)

본 요약서는 Day 5 **"서비스 설계 (UI / UX 리뷰)"** 교육 세션을 진행하는 강사 및 참가자들을 위한 최종 종합 요약 가이드라인입니다. 기획 단계에서 발생할 수 있는 복잡한 사용자 정보 인지 장애를 발굴하고(Task 01), 다중 화면 기획 문서 간의 일관성 불일치 항목을 감지하며(Task 02), 최종 목적지 도달 클릭 스텝을 단축하는 사용자 동선 최적화(Task 03)를 통해 진정한 사용자 중심 설계(User-Centered Design)를 달성하기 위한 요약 정보를 제공합니다.

---

## 📌 Part 1. 도입 배경 및 필요성

### 1. 서비스 설계 단계의 사용성 장벽
* **기능 중심적 설계의 아집**: "기능이 제대로 돌면 개발은 끝났다"고 판단하는 개발 주체의 확증 편향으로 인해, 처음 앱을 접속한 사용자가 인터페이스 규칙을 이해하지 못해 이탈하는 현상이 자주 발생합니다.
* **통합 일관성 파편화**: 여러 명의 기획자와 퍼블리셔가 파트를 나누어 작업함에 따라, 로그인, 가입, 마이페이지 등 각기 다른 디자인 테마나 단어(아이디 vs 고객 ID), 다르게 생긴 버튼 위치로 인해 학습 부하가 증가합니다.
* **피로도 유발형 동선**: 비즈니스 정책 명목으로 클릭 및 단독 동의 화면을 연속으로 나열하여, 목적을 달성하는 데 과도한 화면 전환(Friction)을 겪게 만들어 결제 단계 진입률을 급격히 떨어뜨립니다.

### 2. ChatGPT vs Codex Client (Workspace 기반)
| 비교 항목 | ChatGPT (일반 대화형 AI) | Codex Client (Workspace 기반 AI) |
|---|---|---|
| **화면 구조 분석** | 사용자가 업로드한 텍스트 1개 속 가독성만 판단 | 가입 화면, 카드 상세 화면, 결제 화면 등 다중 파일 명세의 연결 고리와 유입 뎁스(Depth)를 종합 비교 분석 |
| **일관성 검증** | 단순 변수 영작 수준의 피상적인 단어 교정 | 서로 다른 화면에 배치된 동일 목적의 기능 버튼들의 색상, 폰트 너비, 상태 메시지 규격을 매핑해 일관성 위배 지점 도출 |
| **페르소나 리서치** | 단편적인 "사용하기 어렵네요" 수준의 정성적 피드백 | 50대 고연령 자영업자 등 구체적 숙련도 한계 시나리오를 투영해 에러 뤂 내 정보 리셋 곤경 및 글자 크기 가독성 실증 추적 |

## 📌 Part 2. 오늘 실습의 목표 및 결과물 요약

### 1. 오늘 만들 최종 결과물
* **Task 01. 사용자 관점에서 화면 검토하기**: 초보 사용자가 예약 신청 시 직면하는 사용성 한계를 발굴한 **UX 개선 보고서** (출력: `ux-review-report.md`)
* **Task 02. 화면의 일관성 검토하기**: 가입 및 정보 수정 화면 간의 버튼 배치, 규칙, 용어 모순을 잡아낸 **UI 일관성 보고서** (출력: `ui-consistency-report.md`)
* **Task 03. 사용자 동선 개선하기**: 9단계의 상담 예약 클릭 스텝을 4단계로 단축하는 아키텍처 제안이 담긴 **User Journey Report** (출력: `user-journey-report.md`)
* **Mission 01. 처음 사용하는 사용자 되어보기**: 50대 초보 페르소나를 부여한 Codex의 생생한 당혹 요소를 포착한 **가상 유저 사용기** (출력: `first-user-review.md`)
* **Mission 02. AI와 함께 서비스 품질 평가하기**: 이해성, 가독성, 회복성을 지표(Score)로 구조화한 종합 **서비스 품질 평가 보고서** (출력: `usability-evaluation.md`)

## 📌 Part 3. 따라하기 (Step-by-Step 실습 가이드)

### STEP 1. Task 01 - 사용자 관점에서 화면 검토하기
* **행동**: `day5_signup_flow.md` 파일을 준비한 후 아래 명령을 Codex에 전송합니다.
  > "제공된 예약 신청 상세 폼의 화면 명세를 기반으로, 서비스를 처음 접하는 초보 사용자의 입장에서 정보 구조가 명확한지 검토하고 사용성 저해 요소를 지목하여 개선 제안 보고서(UX Review Report)를 작성해 주세요."
* **확인**: 전문가 정보(평점 등)의 시선 분산 요인, 시간 슬롯 선택의 불분명성, 결제 요금 숨김 지점 및 구체적인 레이아웃 개선 가이드가 도출되었는지 확인합니다.

### STEP 2. Task 02 - 화면의 일관성 검토하기
* **행동**: 로그인/가입 화면 스펙 및 회원 정보 수정 명세를 대조하기 위해 아래 명령을 줍니다.
  > "제공된 day5_signup_flow.md의 각 화면 설계 내역들을 서로 대조하여, 버튼의 배치 규칙, 사용 용어, 피드백 메시지의 일관성이 결여된 요소를 분석해 화면 비교 보고서를 작성해 주세요."
* **확인**: 가입 화면에서의 '아이디' 용어와 예약 화면의 '고객 ID' 혼선 지점, 상향 소형 완료 버튼과 하단 전체 너비 로그인 버튼의 그리드 비대칭 조치 사항이 도출되었는지 점검합니다.

### STEP 3. Task 03 - 사용자 동선 개선하기
* **행동**: 캘린더 이동부터 상세 확인까지 분할되어 있는 9단계 경로를 제시하고 아래 최적화 명령을 빌드합니다.
  > "제공된 day5_signup_flow.md의 예약 상세 시나리오 동선을 분석하여, 사용자가 상담 예약을 완료하기까지의 클릭 단계와 화면 이동을 최소화할 수 있는 사용자 동선 개선 보고서(User Journey Report)를 작성해 주세요."
* **확인**: 상세와 예약 화면의 1페이지 통합 구조(TO-BE), 중복 약관 동의 절차의 모달 간소화 매트릭스가 4단계 동선 구조로 완성되었는지 검토합니다.

### Mission 1. 처음 사용하는 사용자 되어보기
* **행동**: 고연령 사용자의 리서치 맥락을 아래 페르소나 설정과 함께 AI에 의뢰합니다.
  > "당신은 디지털 스마트폰 앱 사용이 다소 서툰 50대 자영업자입니다. 제공된 day5_signup_flow.md 명세서에 작성된 회원가입 및 첫 화면 UI 명세를 보면서, 당신의 입장에서 가입 시 무엇이 가장 헷갈리고 어려운지 감정적인 반응과 개선 요구사항을 적어주세요."
* **확인**: 아이디 중복확인 버튼의 수동 클릭 장벽, 캘린더 내 요일 및 슬롯 10px 텍스트 가독성 고충, 가입 양식 오류 시 전체 글자가 날아가는 리셋 분노 지점이 보고서에 리스트업되었는지 파악합니다.

### Mission 2. AI와 함께 서비스 품질 평가하기
* **행동**: 완성된 기획서 전반의 품질 정량화(Usability Scoring) 평가를 아래 프롬프트로 의뢰합니다.
  > "제공된 day5_signup_flow.md 스펙을 기반으로, 1) 정보 가독성, 2) 조작 접근성, 3) 에러 회복성, 4) 동선 효율성 등의 항목에 대해 각각 5점 만점의 점수를 매기고, 종합 평가 점수와 함께 장점 및 뼈아픈 개선점을 지목하는 서비스 품질 평가서(Usability Evaluation)를 빌드해 주세요."
* **확인**: 4대 평가 축 점수와 함께 에러 회복성 2.5점, 동선 효율성 2.0점 등 아프게 지목된 수치를 확보하고, 로컬 스토리지 상태 보존 등의 종합 대책이 권장되었는지 점검합니다.

## 📌 Part 4. 작동 원리 및 의의

### 1. 휴리스틱 사용성 진단 (UX Heuristic Auditing)
* 기획자가 무심코 넘긴 단일 스펙의 정보 계층과 버튼 스타일을 표준 UI 원칙에 대조해 사용자가 직면할 장애(Friction) 수준을 측정하는 분석 방식입니다.

### 2. 가상 페르소나 시뮬레이션 (AI Persona Simulation)
* 특정 기술 숙련도와 연령 장벽을 지닌 페르소나의 행동 심리를 모사하여, 설계자가 자기 시야에 갇혀 놓칠 수 있는 에러 룹 및 인지 마찰 지점을 테스트단 이전에 조기 포착해 줍니다.

### 3. 다섯 가지 사용성 개선 마일스톤
```text
[초보 유저 사용성 리뷰] (Task 01. 불편 도출)
         │
         ▼
[UI 스타일 일관성 검사] (Task 02. 통일 규격)
         │
         ▼
[User Journey 단축 설계] (Task 03. 동선 최적화)
         │
         ▼
[가상 고객 곤경 로그 수집] (Mission 01. 첫 인상 피드백)
         │
         ▼
[Usability 수치 품질 진단] (Mission 02. 스코어 처방)
```
이 사용성 진단 파이프라인은 학생들로 하여금 **"코드가 돌면 개발 끝"**이라는 기술 만능주의 사고를 뛰어넘어, **"사용자가 이해할 수 있어야 성공한 소프트웨어"**라는 사용자 중심 사고(User-Centered Thinking)를 주입해 줍니다.

## 📌 Part 5. 교육 세션 가이드

### 💡 교육 설계 스펙
* **난이도**: ★★☆☆☆ (초급 - 비개발 기획 직군도 코딩 없이 100% 참여 가능)
* **예상 실습 시간**: 1시간 ~ 1시간 30분
* **실무 활용도**: ★★★★★ (기획서 최종 완성 전 무조건 가동할 검증 도구)
* **학습자 질문/토의 주제**:
  1. "회원가입 오류 시 입력한 데이터 전체가 날아가는 것은 보안을 위한 정보 삭제(Security) 관점과 사용자 경험(UX) 관점에서 어떻게 균형을 잡아야 할까요?"
  2. "제품이 성공하여 사용자가 10만 명 이상 늘어났을 때, AI가 예측한 가상 리뷰와 실제 수집되는 구글 애널리틱스(GA) 사용자 행동 로그 데이터를 어떻게 결합해 UI를 개선해야 할까요?"
