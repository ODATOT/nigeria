Day 5 Task 01 사용자 화면 검토

Task 01. 사용자 관점에서 화면 검토하기 (User Experience Review)

사용자의 시선에서 화면 기획의 배치 오류와 누락 정보를 입체적으로 식별하여 런타임 이탈 가능성을 조기에 방지합니다.

Task 01 사용자 관점 화면 검토 실습 가이드

📥 실습 입력 (Input)

  • • day5_meeting_notes.md (회의록)

💾 실습 출력 (Output)

  • • erd-schema.md (데이터 명세 및 ERD)

1. 스토리 및 실습 배경

서비스 화면을 완성하고 예약 프로세스도 설계해 배포했지만, 사용자들이 대시보드에서 예약까지 도달하는 도중 마구 이탈해 버렸습니다. 원인은 개발자나 설계자 시선에 가두어 배치한 정보 계층으로 인해, 처음 접하는 고객은 원하는 버튼을 식별하기가 대단히 난해했기 때문입니다.

이번 실습에서는 Codex에게 기획안을 제공하고 철저히 '초보 사용자 관점'에서 정보 가독성과 버튼 조작 흐름의 불편 지점을 지목받는 정합성 검사를 체험합니다.

2. 학습 목표

  • 처음 사용하는 사용자 입장에서 화면 기획의 정보 배치를 입체적으로 바라볼 수 있다.
  • 화면에서 사용성을 저해하는 캘린더 대비나 가격 숨김 등의 불편 요소를 지적할 수 있다.
  • AI를 활용하여 사용자 경험(UX) 개선을 유도할 레이아웃 대안 권고사항을 도출할 수 있다.
  • 기능 중심주의 사고에서 벗어나 사용자 중심 설계 의식을 체득할 수 있다.

🛠️ 실제 따라 하기 실습 가이드

  1. 실습용 파일 생성: 아래 다운로드 버튼을 눌러 day5_meeting_notes.md 파일을 automation/ 폴더 내에 저장합니다.
  2. Codex 검토 위임: 파일을 첨부하고 Codex Client 입력창에 아래 **Codex 요청 프롬프트**를 전송하여 빌드합니다.
  3. 개선 권고사항 확인: 출력된 보고서에서 스케줄 시간 슬롯 대비 오류 및 요금 표시 개선안이 타당한지 점검합니다.

제공된 예약 신청 상세 폼의 화면 명세를 기반으로, 서비스를 처음 접하는 초보 사용자의 입장에서 정보 구조가 명확한지 검토하고 사용성 저해 요소를 지목하여 개선 제안 보고서(UX Review Report)를 작성해 주세요.

4. 결과물 예시

Codex는 화면 명세를 다각도로 진단하여 아래와 같이 논리적인 개선 포인트 보고서를 빌드합니다.

엔티티명 설명 주요 속성 관계 정보

결제 유도 영역 사용자-전문가 간 예약 매핑 정보 결제 팝업 진입 전까지 최종 결제 요금 상시 인지 불가 User/Expert와 N:1, Payment와 1:1 관계

5. AI 활용 포인트

  • 사용성 감지: 설명 텍스트에서 사용자가 실제로 맞부딪칠 불편 및 당혹감 유발 구간 감지.
  • 레이아웃 개선안: 모호한 명도 대비 해결, 필드 통합 등 바로 적용할 와이어프레임 구조 권장.
