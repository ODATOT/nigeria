CHAPTER 01

백엔드 로직과 데이터 통합 핵심 이론

전문 용어는 복잡해 보이지만, 각 용어는 설계에서 반복되는 한 가지 문제를 해결하기 위해 존재합니다. 아래 표에서 “무엇을 뜻하는가”보다 “언제 필요한가”를 중심으로 학습하세요.

핵심 개념설명
Transaction여러 데이터 변경을 하나의 성공 또는 실패 단위로 묶습니다.
Optimistic Lock충돌이 적다고 보고 버전 비교로 갱신 충돌을 검출합니다.
Pessimistic Lock충돌 가능성이 높을 때 자원을 먼저 잠급니다.
Timeout / Retry응답 대기 한계와 일시 실패 재시도 정책입니다.
Circuit Breaker계속 실패하는 외부 호출을 잠시 차단합니다.
Outbox PatternDB 변경과 이벤트 발행의 불일치를 줄이는 패턴입니다.

좋은 설계와 나쁜 설계의 차이

피해야 할 접근

DB 저장, 결제 API, 이메일 발송을 하나의 긴 요청에서 무제한 재시도한다.

권장 접근

핵심 DB 트랜잭션을 짧게 유지하고 외부 작업은 타임아웃·멱등성·이벤트와 보상 정책으로 분리한다.

설계 공식

[입력 검증] → [권한 확인] → [트랜잭션] → [상태 저장] → [이벤트/외부 연동] → [관측과 복구]

단계별 설계 절차

1

문제 정의

유스케이스의 불변 조건과 최종 상태를 정의한다.

2

구조 추출

원자적으로 처리할 DB 변경만 트랜잭션으로 묶는다.

3

핵심 설계

4

실패 조건

외부 호출에 연결·응답 타임아웃과 제한된 재시도를 둔다.

5

정책 연결

중복 메시지와 부분 실패에 멱등성·보상 처리를 적용한다.

6

검증과 추적

correlation ID로 로그, 메트릭, 분산 추적을 연결한다.

작동하는 예시

낙관적 락 의사코드

CHAPTER 04

종합 실습과 모범답안

제출 과제

재고가 1개 남은 상품에 동시에 100개의 주문이 들어오는 흐름을 설계하세요. 결제 성공 후 재고 저장 실패도 처리하세요.

  1. 핵심 가정과 미결정 사항을 먼저 적습니다.
  2. 주요 설계 결과물을 표, 코드 또는 다이어그램으로 작성합니다.
  3. 정상 흐름과 최소 3개의 실패·경계 조건을 포함합니다.
  4. 자가진단표로 채점하고 개선 전후를 비교합니다.
모범답안의 핵심 방향 보기

재고 감소는 조건부 UPDATE 또는 행 잠금으로 한 요청만 성공시킵니다. 주문 요청에는 멱등성 키를 사용합니다. 결제 후 재고 확정이 실패하면 결제 취소 이벤트를 발행하고 처리 결과를 추적 가능한 상태로 저장합니다.

답안 사용법

모범답안은 유일한 정답이 아닙니다. 자신의 설계가 다른 경우에는 요구사항, 비용, 복잡도, 위험 중 어떤 근거로 다른 선택을 했는지 설명할 수 있어야 합니다.
