Day 2 Task 02 변경사항 관리

Task 02. 변경사항 관리 (Change Management)

비즈니스 정책 변화에 맞춰 요구사항(v1.0 ➔ v2.0)이 달라졌을 때, 하위 산출물(화면 정의서, API 명세서)의 영향 범위를 매핑하는 통제 기술을 학습합니다.

Task 02 변경 영향도 분석(Impact Analysis) 실습 가이드

📥 실습 입력 (Input)

  • • requirements-before.md (v1.0 요구사항)
  • • requirements-after.md (v2.0 요구사항)
  • • screen-specification-v2.md (v1.0 화면설계서)
  • • api-specification.md (v1.0 API 규격서)

📤 실습 출력 (Output)

  • • 변경 분석 및 조치 리포트 표

🛠️ 실제 따라 하기 실습 가이드

  1. 실습용 파일 생성: 아래 다운로드 버튼들을 눌러 4개 파일을 automation/ 폴더 내에 저장합니다.
  2. 영향 범위 매핑 의뢰: Codex Client 입력창에 아래 Codex 요청 프롬프트를 전송하여 빌드합니다.
  3. 수정 액션 아이템 확인: AI가 분석해 준 조치 사항을 읽고 프론트엔드 로그인 버튼 추가, 백엔드 회원가입 API 추가 필드 누락이 해결되는 시나리오를 검토합니다.

실습 자료 다운로드

Codex 요청 프롬프트

Task 02 Prompt프로젝트 폴더 내에 있는 'requirements-before.md'와 'requirements-after.md' 파일을 대조하여 어떤 정책이 변경되었는지 먼저 분석해줘.

그 후, 변경된 정책 내용이 v1.0 수준에 머물러 있는 'screen-specification-v2.md' 및 'api-specification.md' 문서의 어느 부분에 반영되어야 하는지 분석해줘.

결과는 아래 형식에 맞춰 Markdown 표 형태로 출력해줘:
1. '변경 항목', '변경 전', '변경 후', '영향 범위 (화면/API)', '조치 사항 (필요한 구체적인 수정 가이드)'
2. 추가로, v2.0 요구사항을 기준으로 수정이 필요한 부분의 중요도를 '높음/중간/낮음' 순으로 구분하여 칼럼에 표시해줘.

예상 결과 리포트

변경 항목 변경 전 변경 후 영향 범위 (화면/API) 중요도 조치 사항 (구체적인 수정 가이드)
소셜 로그인 이메일 로그인만 제공 Google 소셜 로그인 기능 추가 • 로그인 화면(`SCR-01`)
• 로그인 API		 높음 • 로그인 화면 UI에 'Google 로그인' 버튼 컴포넌트 배치
• API Payload에 Google OAuth 토큰 수신 파라미터(`"oauth_token": "string"`) 추가 설계 필요
회원가입 인증 이메일 링크 인증 휴대폰 번호 입력을 통한 SMS 인증번호 확인 • 회원가입 화면(`SCR-02`)
• 회원가입 API		 높음 • 이메일 발송 컴포넌트를 휴대폰 번호 입력 필드 및 '인증번호 발송/확인' 필드로 UI 교체
• 가입 API Payload에 휴대폰 번호(`"phone": "string"`) 및 인증코드(`"verification_code": "string"`) 필드 필수 반영
관리자 권한 단일 User 권한 자동 부여 일반 User / 시스템 Admin 권한 다원화 • 마이페이지 화면(`SCR-03`)
• 전체 보안 인가 API		 중간 • 관리자 계정으로 로그인 시 노출될 관리자 전용 대시보드 화면 설계서 추가
• API 인증 헤더 또는 회원 정보 응답에 권한 역할(`"role": "string"`) 정보 수신부 설계

💡 AI 활용 및 학습 포인트

요구사항 문서가 고쳐졌을 때, 하위 개발 규격서(API)와 디자인 설계서(Screen spec)의 싱크 상태를 동적으로 추적(Impact Mapping)하여 소스 코드 및 기획 누락 사고를 차단합니다.
