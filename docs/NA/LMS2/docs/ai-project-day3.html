What is gstack?

gstack = a folder of role guides for AI coding tools

In one sentence

An open-source (MIT, free) set of skills made by Garry Tan, President & CEO of Y Combinator. Each skill is a Markdown file that tells the AI which role to play and how to do that job: CEO, designer, engineer, reviewer, QA.

It is NOT

✕ a new AI model   ✕ an app you open   ✕ magic that writes better code
gstack's own README says it gives no higher bug-fix rate. Use it for the workflow, reviews and checks.

Where it is

github.com/garrytan/gstack · 50+ skills · works in Claude Code (full support) and Codex (experimental) and other agents

Before gstack · git

Git = save points for your project

Git is a free tool that remembers every saved version of your files: what changed, when, who changed it and why. Like save points in a game, or "track changes" in Word, but for a whole folder.

WordMeaningCommand
repository (repo)A folder that git watchesgit init
commitA save point, with a short message saying whygit add . then git commit -m "message"
status / diffWhich files changed, and exactly which linesgit status · git diff
restoreThrow away changes since the last save pointgit restore .
logThe list of all save pointsgit log --oneline

Git vs GitHub

Git = the tool on your laptop (works offline). GitHub = a website that stores git projects online for sharing. gstack itself lives on GitHub.

Who uses it?

Almost every software team in the world. Created in 2005 by Linus Torvalds for the Linux project.

Why git?

AI changes files fast. Git lets you see, check and undo.

✕ Without git

  • AI edits 6 files; you don't know which
  • It worked an hour ago, now it's broken: no way back
  • Folders named final, final2, final_REAL
  • Teammates overwrite each other's work
  • "AI said it's done", but you can't prove what it did

✓ With git

  • git status shows exactly which files AI touched
  • git restore . returns to the last good version in 1 second
  • One folder, a clear history with reasons
  • Everyone sees who changed what, and why
  • git diff is the evidence of what AI really did

1 · Safety

Try anything with AI. If it goes wrong, undo.

2 · Evidence

The diff shows what changed, not what AI says changed.

3 · Teamwork

Three people, one project, no overwriting.

4 · gstack needs it

/review reads your git diff. No git, no review.

"Commit before you ask AI. Look at the diff after. That one habit prevents most AI disasters."

What it does

Asks six forcing questions: is there real demand? what do people use today? who exactly? what is the narrowest first version? what did you observe? will it still matter later?

It asks you questions back. Answer with your OBS evidence, not imagination.

Before Lab 5 · git = your undo button

Don't like what AI made? Undo, then ask better

Which undo?

SituationType this
See what AI changedgit status · git diff
Throw away all changes since my last commitgit restore .
Remove new files AI createdgit clean -n (preview) → git clean -fd
Undo one file onlygit restore build/index.html
Already committed, want it backgit log --oneline → git revert HEAD

Check: git status says "working tree clean" → you're back at your save point.

Ask again: say what was wrong, what to keep, the limit

I undid your last change with git.
Problem: you changed 5 files and the Cancel button stopped working.
Keep: the "no next video" screen design.
Try again: change ONLY build/index.html, only DEC-002.
List the files you'll change before editing. Don't run git commands.

Same prompt again → usually the same mistake. A better prompt is the real fix. Log it in GSTACK_LOG: what went wrong, what you changed in the prompt.

Don't

✗ git reset --hard or deleting the .git folder: you can lose work for good.
✗ Let AI run git for you today: you press undo, so you know what happened.
✗ Forget to commit before asking AI: undo only reaches your last commit.

Claude Code also has its own rewind (Esc Esc or /rewind). Git works the same in both tools, and also for changes you made by hand.

Before the retro

Same file, same skill, different answers. Why?

1 · Your answers

gstack asks you questions. Different answers → different plan.

2 · Your words

One extra sentence in the prompt changes what AI focuses on.

3 · Tool and model

Claude Code and Codex use different models and features.

4 · Chance

AI is not a calculator: run it twice, get two versions.

So the useful question is

Not "which AI is right?" but "which answer has evidence?" An answer that points to an OBS, a Done-when line or a diff beats one that just sounds clever.

Team habit worth keeping

For important steps, two people run the same skill. Where they agree, move fast. Where they differ, look at the evidence.
