What a backend does

⑥ 외부 연동결제, 문자·이메일 알림, 지도 등실패·지연에 대비
Why frameworks?

프레임워크 = 반복되는 일 + 코드 위치의 약속

프레임워크 없이

  • URL 파싱, DB 연결, 세션, 보안을 매번 직접 구현
  • 사람마다 코드 위치와 스타일이 제각각
  • SQL 인젝션·CSRF 같은 보안 실수 위험

프레임워크와 함께

  • 라우팅 · ORM · 인증 · 관리자 · 보안 기능 기본 제공
  • “모델은 여기, 뷰는 여기” 공통 구조 → 협업 용이
  • AI도 정해진 위치에 코드를 작성하기 쉬움
라이브러리는 내가 부르는 도구, 프레임워크는 나를 불러 주는 뼈대입니다. (제어의 역전)

MVC pattern

MVC: 세 가지 책임을 나눈다

🗄️
Model데이터의 구조와 저장, 데이터에 대한 규칙
예: Menu, Order, OrderItem
🧭
Controller요청을 받아 Model을 호출하고 어떤 View로 응답할지 결정
예: OrderController.create()
🖼️
View사용자에게 보여 줄 표현 (HTML 화면 또는 JSON)

🍽️ 식당 비유 — 웨이터(Controller)가 주문을 받아 주방(Model)에 전달하고, 완성된 요리(View)를 손님에게 내놓는다.

Rule · Policy · Calculator

Day 3의 REQ가 순수 Python 규칙이 된다

Rule · REQ-006

class OrderQuantityRule:
    MAX = 20

    def evaluate(self, quantity):
        if quantity < 1 or quantity > self.MAX:
            return RuleResult.reject(
                "QUANTITY_OUT_OF_RANGE")
        return RuleResult.accept()

Policy

class OrderAcceptancePolicy:
    def __init__(self, rules):
        self.rules = rules

    def evaluate(self, context):
        for rule in self.rules:
            result = rule.evaluate(context)
            if not result.passed:
                return result
        return RuleResult.accept()

Calculator

class OrderPriceCalculator:
    def calculate(self, items):
        return sum(
            item.unit_price * item.quantity
            for item in items
        )
# 금액은 정수(최소 화폐 단위)
# 또는 Decimal 사용, float 금지

Registry (조립)

class PaymentGatewayRegistry:
    def __init__(self, gateways):
        self._gateways = {
            g.provider_code: g for g in gateways}
    def get(self, provider_code):
        return self._gateways[provider_code]

Payment safety

돈이 오가는 곳의 5가지 안전장치

상태 전이READY → PENDING → PAID / FAILED
PAID → REFUNDED금지: FAILED → REFUNDED
TX 분리TX1: PENDING 저장 → TX 밖: 결제사 호출 → TX2: 결과 + OutboxTimeout ≠ 즉시 실패
멱등성Idempotency-Key 필수. 같은 키 + 같은 요청 → 기존 결과다른 금액 → 409
웹훅Raw Body 서명 검증, event_id Unique과거 이벤트가 최신 상태 덮어쓰기 금지
Outbox결제 저장과 이벤트를 같은 TX에, 후속 작업은 Commit 후 비동기알림 장애 ≠ 결제 롤백

  • Workflow는 업무 처리 순서를 관리한다
  • Rule · Policy · Calculator는 순수 업무 로직
  • DB와 외부 시스템은 Port와 Adapter로 연결, business는 Django에 의존하지 않는다
