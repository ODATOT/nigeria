Codex 기반 요구사항 정의 교육 미션

비정형화된 회의록 대화에서 요약(전처리)을 수행하고, 기능 명세와 예외 흐름 정의, 의사결정 질문지 구축 및 최종 문서 통합 & 이메일 공유까지의 전체 기획 워크플로우를 학습합니다.

진행 단계 선택

Step 0

대화록 요약 전처리

회의 대화록 원본에서 핵심 요약 메모 추출

Step 1

회의 메모 분석

회의록 요약본에서 사용자, 기능, 비즈니스 정책 분류하기

Step 2

기능 요구사항 정의

추출된 기능 후보를 테스트 가능한 정형 명세 문장으로 변환

Step 3

정상 및 예외 흐름

사용자 시나리오와 예외 케이스(실패, 중복 등) 디테일 보완

Step 4

미결정 기획 질문

미결정 사항을 이해관계자 확인 질문 목록으로 변경

Step 5

문서 통합 및 메일 공유

AI 린트 검증을 통한 문서 완성 및 Gmail 플러그인 연동 발송

📥 단계 입력 (Input)

비정형 핑퐁 대화 형태의 1차 회의록 원본 (meeting-notes-raw.md)

📤 단계 출력 (Output)

핵심 요약 메모 파일 (meeting-notes.md)

🛠️ 실제 따라 하기 상세 가이드

  1. 원본 회의록 확보: 아래 다운로드 버튼을 눌러 1차 회의록 대화록 원본인 meeting-notes-raw.md 파일을 다운로드하여 작업 폴더에 놓거나 파일 내용을 생성합니다.
  2. 전처리 지시: 사용할 Codex/ChatGPT 대화창을 열고 아래 Codex 요청 예시 프롬프트를 전송합니다.
  3. 결과물 저장: AI가 가공되지 않은 핑퐁 대화에서 뽑아낸 정제된 요약 메모 텍스트를 복사하여 meeting-notes.md 파일로 저장합니다. (이 파일은 다음 1단계 실습의 Input 데이터가 됩니다.)

미션 상황

기획 회의에서 작성된 회의록 원본은 각 팀원들(대표, 기획자, 개발자, 디자이너) 간의 핑퐁 대화와 사담이 섞여 있어서 요구사항을 바로 추출해 분석하기에는 너무 산만합니다. 학습자는 Codex를 전처리 도구로 활용하여 회의록에서 핵심 비즈니스 요건만 요약한 기획 메모를 도출해야 합니다.

학습자 미션

다음 1차 회의 대화록 원본을 meeting-notes-raw.md 파일로 작성하거나 다운로드합니다.

meeting-notes-raw.md 원문 (스크롤)# 전문가 상담 서비스 구축을 위한 1차 Kick-off 회의록

**일시**: 2026-07-10 14:00 - 15:30
**참석자**: 대표(CEO), 기획자(PM), 개발자(Dev), 디자이너(Designer)

---

**대표**: 여러분, 안녕하세요. 오늘 회의는 우리가 새로 론칭할 "온라인 전문가 상담 서비스"의 기본 요구사항을 논의하고 방향을 잡기 위한 자리입니다. 핵심은 사용자가 우리 플랫폼에 와서 다양한 분야의 전문가를 찾고, 상담 예약을 한 뒤 결제까지 원활하게 마치는 프로세스입니다.

**기획자**: 네, 대표님. 서비스의 기본적인 가입 절차부터 논의를 시작해보죠. 사용자는 회원가입을 해야 서비스를 이용할 수 있는 구조인가요?

**대표**: 네, 맞습니다. 사용자는 우선 회원가입을 마쳐야만 전문가 검색이나 예약 등의 기능을 원활하게 이용할 수 있도록 합시다. 비회원 상태에서는 간단한 둘러보기만 가능하도록 하고요.

**디자이너**: 가입하고 나면 전문가를 검색할 텐데, 전문가 프로필 페이지나 분류 기준은 어떻게 생각하고 계신가요?

**대표**: 전문가는 일단 분야별로 구분되어야 합니다. 예를 들어 IT 컨설팅, 법률 상담, 디자인 코칭 같은 카테고리가 있겠죠. 사용자는 카테고리를 선택하거나 직접 검색어를 입력해 본인이 원하는 전문가를 빠르게 찾아낼 수 있어야 합니다.

**디자이너**: 그러면 검색 결과에서 전문가 목록이 나오고, 상세 페이지로 들어가서 일정을 고르는 구조겠군요. 날짜와 시간은 어떻게 선택하나요?

**대표**: 예, 사용자가 특정 전문가를 선택하면, 해당 전문가가 상담 가능한 스케줄 일정이 캘린더나 타임라인 형태로 표시되어야 해요. 사용자는 그중에서 자신이 상담받고 싶은 날짜와 시간을 자유롭게 골라 예약 신청을 할 수 있게 해야 합니다.

**개발자**: 예약 신청 직후의 결제 프로세스는 어떻게 진행되나요? 예약 신청과 동시에 결제가 바로 이루어져야 예약이 확정되는 형태인가요?

**대표**: 결제가 완료되어야만 최종 예약이 "확정" 상태로 넘어가야 합니다. 만약 PG사 한도 초과나 기타 원인으로 결제가 실패하면, 당연히 그 예약은 완료 처리되면 안 되고 대기 혹은 취소 상태로 묶여야겠죠.

**개발자**: 결제 실패 시 예약이 생성되지 않거나 잠금 해제가 되어야 한다는 비즈니스 규칙이군요. 전문가는 자신이 예약된 스케줄을 어디서 확인하나요?

**대표**: 전문가는 우리 시스템 내에 전문가 전용 대시보드가 있어서, 거기서 자신에게 들어온 예약 신청 내역이나 확정된 스케줄을 실시간으로 모니터링하고 관리할 수 있어야 합니다.

**기획자**: 전문가 가입은 일반 회원가입과 다를 텐데, 인증이나 승인 절차가 별도로 필요한가요? 아무나 전문가로 활동하게 할 순 없으니까요.

**대표**: 좋은 지적입니다. 전문가는 가입 신청을 한 후에 바로 활동할 수 있는 게 아니라, 사이트 관리자가 제출 서류나 자격을 심사한 뒤 "승인"을 해줘야 비로소 전문가 목록에 노출되고 예약 시스템에 참여할 수 있도록 관리자 승인 정책을 필수로 두겠습니다.

**기획자**: 예약을 완료하면 사용자나 전문가에게 알림을 발송해야 개발 편의와 사용성이 높을 텐데, 알림 채널은 어떤 걸 선호하시나요?

**대표**: 알림은 무조건 보내야죠. 예약이 확정되었거나 취소되었을 때 알려줘야 하니까요. 그런데 알림을 이메일로 쏠지, 아니면 휴대폰 문자로 보낼지는 개발 리소스와 비용 문제를 좀 더 따져봐야 할 것 같아요. 이 부분은 아직 확정하지 맙시다.

**개발자**: 취소 수수료나 환불에 대한 규칙도 지금 정해야 하나요?

**대표**: 취소 수수료 정책도 법률 검토와 마케팅 부서 협의가 필요한 사항이라서요. 오늘 당장 결정하긴 어려우니, 이것도 아직 결정되지 않은 보류 사항으로 남겨둡시다. 추후 2차 회의 때 확정 짓는 걸로 하죠.

**기획자**: 알겠습니다. 오늘 결정된 정책과 보류 사항들을 대략 취합해서 명세 초안을 위한 전처리 회의 요약 메모로 정리해 보겠습니다.

Codex 요청 예시 (전처리 프롬프트)

Promptmeeting-notes-raw.md의 회의록 원문을 읽고, 화자 간의 불필요한 대화 맥락과 문맥을 걷어내고
서비스 사용자, 기능 요건, 시스템 정책, 미결정 유보 사항을 15줄 내외의 컴팩트한 비정형 요약 메모 형태로 작성해줘.
원문에 없는 가상의 내용은 임의로 상상해서 추가하지 말아줘.

  • • 미결정 사항 목록

🛠️ 실제 따라 하기 상세 가이드

  1. 회의 메모 준비: 0단계 요약본인 meeting-notes.md 파일을 배치합니다. 아래 다운로드 버튼을 눌러 정제본 예시 파일을 직접 다운로드해도 됩니다.
  2. AI 분석 의뢰: 0단계 대화에 이어서 아래 Codex 요청 예시 프롬프트를 전송합니다.
  3. 분류 검토: 도출된 사용자 목록(Customer, Expert, Admin)과 확정/미결정 정책 분류가 학습자 확인 사항 기준에 부합하는지 봅니다.

미션 상황

대표와 기획자, 개발자 등의 회의 대화에서 정제된 0단계의 기획 요약 메모(`meeting-notes.md`)를 분석할 때입니다. 학습자는 이 요약문을 바탕으로 서비스의 주요 객체(사용자 역할, 기능, 비즈니스 룰, 정책)를 정확히 카테고리화해야 합니다.

학습자 미션

정제된 meeting-notes.md 요약 파일을 준비하거나 아래 예시 다운로드를 이용합니다.

meeting-notes.md 요약문 (스크롤)온라인 전문가 상담 서비스를 만들려고 한다.

사용자는 회원가입 후 전문가를 검색할 수 있다.
전문가는 분야별로 구분한다.
사용자는 상담 날짜와 시간을 선택할 수 있다.
결제가 완료되면 예약이 확정된다.
결제가 실패하면 예약은 완료되면 안 된다.

전문가는 자신의 예약을 확인할 수 있다.
관리자는 전문가 가입을 승인할 수 있다.

예약이 완료되면 알림을 보내야 한다.
알림을 이메일로 보낼지 문자로 보낼지는 아직 정하지 않았다.
취소 수수료 정책도 아직 정하지 않았다.

🛠️ 실제 따라 하기 상세 가이드

  2. 프롬프트 전송: 1단계 대화에 이어 아래 Codex 요청 예시 프롬프트를 복사해 채팅창에 전송합니다.

  4. 모호성 필터링: 완성된 문장에 "편리하게", "빠르게"와 같은 모호한 수식어가 포함되어 있다면 AI에게 정량화 수정을 다시 요구해 봅니다.

미션 상황
